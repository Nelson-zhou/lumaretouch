# Background-spill review acceptance: authored, not executed

No app, inference, product import, dependency install, compiler, typecheck, build or test runner was executed. These are acceptance instructions, not pass claims.

1. A legacy version-1 ID recipe reads without adding spill or changing its JSON. Ordinary ID controls and id_set keep their original payload and cannot edit spill. Missing spill_protocol:1 or spill_available:true disables only the new spill UI. A version-2 recipe shows its own enabled, strength and retained manual-coverage state.
2. Independent spill enabled/strength values remain unsaved until the full review flow completes. A preview is read-only: no edit-intent event, history, document revision, inspection mutation or original draft reset. Enabling requires an applied active ID replacement with opacity greater than zero and the selected independently reviewed support. Disabling an existing effect still generates a before/after review. If the processing library is missing while a stored spill effect is active, neither side can be honestly rendered: show the blocker, never fabricate a preview, and explain that the existing clear-background action can disable the parent background path without deleting its stored spill intent.
3. Null coverage IDs retain an existing snapshot. Empty IDs explicitly clear it and select automatic candidate coverage. Nonempty IDs require a separate source-coverage checkbox and select only enabled, drawn brush, linear or radial objects from the current source editor. Empty brushes, semantic/AI/full/color/luminance objects cannot be selected. Preserve vector object order/operations as enforced by the engine, never import another photo's mask.
4. Load original and creative-derived sources independently. Changing the active document, active source, masks, recipe revision, editor activity, coverage choice, selected IDs, enabled or strength invalidates the old review and explicit checkbox. Engine and native requests reject a mismatched document or revision. A source change while preview is in flight must not display the old pair as current.
5. Show the actual engine-rendered before/after PNG pair, at matching dimensions no larger than 640. Hash both decoded byte arrays with SHA-256, require browser load events and exact natural dimensions, then enable the explicit pixel-review checkbox. A CSS/screenshot/source-only placeholder, wrong digest, broken PNG, over-budget data, invalid canonical base64, dimension mismatch or stale fence never unlocks Apply. If hashing is unavailable, fail closed.
6. Apply includes the one-use token and both PNG hashes, not the candidate recipe digest. Native matches a cached successful review from the same engine epoch, document and exact recipe fence. Two rapid clicks, a second request ID with the same token, modified PNG hashes, replay after source change, or altered action/protocol must not submit a second mutation. Same request ID only queries its existing receipt; it never sends again.
7. Timeout, send error and engine restart do not blindly replay. Query the original request. An unresolved or unknown mutation remains locked and cannot be cleared by a speculative read. Malformed apply receipts produce unknown/reload flags; malformed read-only previews can be replaced only by an explicit fresh preview. A late valid preview can be queried without committing anything. A proven native refusal before any send uses a strict requested:false/not_sent:true admission result bound to this action, request, document and protocol; only that result clears pending/uncertain. Cap, schema, stale-token and pre-send lock refusals cannot strand the UI querying a nonexistent receipt forever. Errors after any send attempt remain unknown, even if they may have occurred before engine execution.
8. Native ordinary ID response cap remains 2 MiB. Spill has per-preview PNG limits of 1 MiB each and a 4 MiB total response cap. At most one completed PNG pair is retained; earlier previews become identity-preserving nonmutating expiry receipts. Unresolved requests and confirmed mutation receipts are never evicted. Reserve the worst-case response before sending within a 16 MiB spill-specific total budget, so a successful mutation is never thrown away to free memory.
9. Check skin, hair, bright and dark edges, genuine similarly colored clothes, strongly colored backdrop, weak or absent contamination, grain, and near-zero alpha. Inspect full-resolution export separately from thumbnails. This UI promises bounded color-contamination estimation, not blanket desaturation, perfect unmixing or recovery of lost color. No quality or performance requirement is marked passed by this source work.
10. After successful apply, check one history transaction, undo/redo, reset, project round-trip, preset boundaries and output export through engine acceptance. Other background parameters and manual source masks must remain unchanged. Native budget exhaustion must reject before mutation, preserving all existing outcomes.
