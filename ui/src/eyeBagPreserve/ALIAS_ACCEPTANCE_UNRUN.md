# Direct editor shared-source alias slice

AUTHORED / UNRUN. Static source inspection and file hashing only. No product
imports, tests, typecheck, build, Rust compile, inference, downloads or Git writes
were performed by this UI task. The synthetic 2×2 PNG fixtures are contract inputs,
not photo evidence, and have not been executed against product code.

## Authored behavior and contracts

- Reference/source-preview/native eye crops keep the existing shape and represent
  the current logical document only. The UI explicitly discloses that these do
  not inspect each sibling's repaired pixels. Source marks are geometric support,
  not transferred repair, image content, automatic anatomy, or donor masks.
- Preview input remains the existing recipe/eyes/replace_legacy candidate. V1
  review/image/ACK remains single-document. V2 adds exactly current-first members
  (2–16), each path and full mixed visual. All have the same effective source asset
  and extent while retaining independent original/creative provenance and pixels.
- One source-owned support digest, overlay and source/decode mapping is shown and
  acknowledged. Every member's own complete before/after PNG pair is fetched on
  demand by document ID and validated by side, token, frozen review hash, PNG
  digest, declared size and natural decoded size. Each member is individually
  accepted; the whole group is blocked if any pair, display, or acceptance is missing.
- Alias ACK contains only review_sha256, support_overlay_sha256 and the exact
  current-first member document/revision/before/after list. A support image request
  is allowed only for the current owner document. V1 omits document_id as before.
- Confirmation validates exact echo and existing receipt fields plus the complete
  ordered alias_members with canonical expected/result revisions, exact +1 per
  logical document, exact shared graph revision and a nonempty actual batch_id.
- Existing app-lifetime people mailbox retains the frozen confirmation across
  navigation/unmount. An unknown or malformed outcome is query-only, never replayed.
  Source changes, draft changes, close/discard, cancellation and recovery invalidate
  old image/visibility/acceptance authority. Read cancellation never cancels a write.
- The existing batch history controller owns undo/redo. The new safety classifier
  consumes eye_bag_alias_review from the same engine ledger, including reopened
  projects. Full original member count, unique restored indices, matching scope,
  exact batch ID and no conflicts are required. Unknown or partial restores remain
  query-only across all batch controllers. Malformed/conflicting markers tighten
  the fence; they do not degrade to generic history.
- Neutral reset and bounded same-binding session drafts remain in the existing
  people owner. Drafts never preserve image/ACK authority. No preset alias support,
  dormant-member skip, source-mismatch fallback or partial member apply is claimed.
