# Mixed eye-bag preset source-alias review: authored, not executed

This change is source-only. No test runner, build, typecheck, import execution, engine execution, inference, model download or photographic acceptance was performed.

- Version 1 remains the exact single-current-document review and ACK. Version 2 adds a source-alias group with current member first, unique document IDs (duplicate paths remain legal), each member's own source proof, state, output geometry and immutable full-chain before/after PNG metadata.
- The current document receives the selected mixed recipe; sibling recipe/state and output crop geometry must remain unchanged. Every member receives the same shared portrait-graph change. Current target support and explicit legacy replacement are frozen; donor support or recovery strokes are not transferred.
- The panel separately fetches, checks PNG bytes/dimensions/hash, waits for actual image decode and requires an explicit checkbox for every member. Aggregate readiness cannot be satisfied by metadata or just the current image. Review and support canonical digests are verified before image review and again before dispatch.
- Paged image identity retains the active load ID and revision, adding the exact logical member ID/revision only for v2. Member, side, token, preset, hash, and response request IDs must all match.
- Apply ACK order is immutable. Success needs the matching preset/token/full mixed scope, exact composite marker, a real batch ID, all member +1 revisions, and the current people binding. Known post-ledger member-publication diagnostics are accepted only with the exact ordered +1 revisions, batch ID and composite marker, but remain UNKNOWN. An exact unclaimed/expired-token ACK can be rejected without a stored scope only when its identity matches and no publication is present. Native diagnostic-only UNKNOWN envelopes may omit actual module scope only when the original binding is exact and no publication is claimed; a bounded known batch ID may be retained as a diagnostic, not as restore authority. The UI never invents result scope or synthesizes a marker from the expected review: receipt registration requires an actual matching marker. Any provided actual scope must still match the frozen scope. Unknown writes retain the original request, ACK and known group identity; they cannot be dismissed or resent. If a later matching terminal result is available it triggers fresh status instead of replaying stale document state; polling is not promised to change an immutable native unknown receipt. User-driven reopening of a verified saved project is the explicit recovery remedy. Only a verified change from a known workspace generation retires obsolete per-epoch write fences and notifies subscribers; initial workspace observation, ordinary photo navigation and panel closure cannot clear them. The existing preset and composite batch controllers retire only the matching old-workspace pending request, report that its outcome remains unknown, and invalidate callbacks so a late receipt cannot overwrite the reopened workspace. Other batch families keep their existing behavior.
- The distinct `eye_bag_preset_alias_review` ledger marker cannot be treated as a direct-alias, cohort or generic preset permission. Malformed markers tighten recovery. Undo/redo must prove exact marker, batch ID, graph-ledger scope, complete unique restored rows and zero conflicts.
- The existing people-owned batch controller remains the sole UI history owner. The eye-bag panel displays composite ledger history, including reopened projects without a local success receipt. No current-document undo snapshot or second controller is created.
