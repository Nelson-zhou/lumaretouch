# Ordinary eye-bag v2 batch UI: AUTHORED / UNRUN

This is source implementation and an unexecuted acceptance plan, not a runtime,
photographic quality, compatibility, or completion claim. No product code/import,
test runner, typecheck, build, inference, download, or Git write was performed for
this UI slice. It does not modify Rust numerical behavior, the legacy eye-bag
algorithm, App.tsx, or any cohort/shared-alias admission rule.

## Implemented source boundary

- Ordinary explicit face maps transfer selected v2 `/amount` and `/preserve`
  scalar leaves, retaining every other explicitly selected parameter.
- The reviewed route requires a non-default boolean legacy-replacement choice
  for every exact target document before preflight. Active targets retain their
  own already-painted and reviewed ridge protection. No donor support, recovery,
  masks, landmarks, identity links, or inferred anatomy are transferred.
- Explicitly selected nonzero legacy eye-bag plus an active v2 candidate is a
  conflict even when replacement is allowed. Neutral v2 does not clear legacy or
  existing protection. Independently selected legacy parameters remain selected.
- The separate user-visible neutral-stop route requires selected, resolved,
  conflict-free numeric `/amount === 0`. It sends no eye policy envelope or eye
  image ACK and does not require rendering the active-before effect just to stop
  it. The engine must still verify final target neutrality. Preserve-only or
  nonzero activity cannot use this route; persistent association remains guarded.
- Reviewed transfers use each frozen target's complete mixed before/after render,
  fetched one target/side per read. SHA-256, PNG header, dimensions, output
  geometry, source identity, coverage digest, decoded display and user checkbox
  all gate acknowledgment. The display is at most 1024 px on the longest edge,
  never advertised as full-resolution photo acceptance.
- Mixed collarbone selection retains both evidence and ACK families and must
  describe the same underlying complete candidate render. Neither family can
  silently replace the other.
- Policy and route toggles advance a local review epoch. Every actual context
  change advances a monotonic revision, so a pending read cannot revive after
  changing away and back. Submitted/unknown writes retain the original request
  identity and remain query-only through context changes, Close and retry. A
  workspace-scoped read-only ledger classifier preserves this fence for reopened
  marked eye-bag undo/redo and independent batch controllers; malformed markers
  can only tighten the fence. It stores no edit snapshots or command authority.
- Successful receipts distinguish applied, skipped and no-op targets. No-op
  targets retain the frozen document revision; all-no-op returns no undo batch.

the production TypeScript build root. It imports Node hashing only in test scope.

- `batchModel.unrun.test.ts`: exact policy target set/booleans, own-ref coverage,

- `batchWiring.unrun.test.ts`: explicit policy and neutral route controls, full

## Required runtime and photo acceptance, NOT DONE

1. Typecheck/build and execute the focused fixtures with the repository's supported
   test harness; execute existing batch, people, collarbone, face-style and
   eye-bag preset regressions. These files are not added to a test script here.
2. In an actual app, verify 1 and 16 target documents, multiple explicit faces,
   missing or stale target protection, occlusion, nonuniform target activity,
   per-target legacy policies and an independently selected legacy conflict.
3. Compare every target's actual full-chain before/after against ordinary local
   application with eye-bag plus independent portrait parameters and collarbone.
   Verify no donor support or recovery appears in a target.
4. Exercise visible image failure, hash failure, rejected read, retry, slow read,
   late read, Close, repeated clicks, source/target edit, policy false→true→false,
   face remapping and uncertain native commit/undo/redo. Never retry a write.
5. Stop v2 through the neutral route while active-before rendering is unavailable;
   verify final zero, unchanged support, no implicit legacy clearing, retained
   explicitly selected other effects and each other module's necessary review.
6. Verify no-op/mixed-no-op outcomes, atomic recheck and skip/report behavior,
   missing/mismatched ACK receipt, full-scope echo, old neutral compatibility,
   and continued rejection of active cohort/shared-alias routes.
7. Perform real-source full-resolution photo evaluation for retained ridge detail,
   target skin texture, eye/eyelid boundaries, neighboring subjects, background,
   crop/geometry and simultaneous effects. No such acceptance is established by
   synthetic one-pixel DTO fixtures or source inspection.
