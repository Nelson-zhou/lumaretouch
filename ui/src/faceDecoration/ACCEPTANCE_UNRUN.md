# Face-decoration UI source candidate

Status: AUTHORED / UNRUN. No application imports, tests, typecheck, build, native
load, inference, GUI run, screenshot, real-photo output or release acceptance was
performed for this source change. These fixtures are not a pass claim.

Scope: `LNX-REF-PC-32471-C-dd14134407`, local makeup / face decoration only.
Eight original analytic templates (five freckles, three mole layouts), independent
`lnx.face_decoration.v1` version-1 recipe, pattern and strength 0–1. The 0–100 UI
scale and original template names are local design, not official numeric-range
claims. Other makeup, makeup reduction, automatic segmentation and AI replacement
are not implemented by this route.

The actual RetouchPanel route uses the existing people owner. Pattern changes
write only `/pattern`; strength and neutral write only `/strength`. Scope and
selected-face effective values remain distinct. Native ABI readiness and each
person's owned support are separate. Missing core/support cannot enable strength;
zero recovery remains possible with the operation protocol and a valid owned
scope. Existing shared-source alias rejection and global edit/history fences stay
in force. No new graph, transaction, history store or native command is introduced.

Source review requests `face_decoration_reference`, retains the exact request
and people envelope, checks the echoed request and proof, hashes the sole report
PNG, and waits for exact browser-decoded dimensions. Only then can pointer or
keyboard paint and three decoration-specific confirmations enable a review.
Review submits `{region, reference_proof}` through `submitCaptured`, never blush
consent, cross-person pixels, cached masks or a mutable latest-context envelope.
Full source, document revision/epoch, graph and association revision, selected
face/analysis/enablement, write scope and landmark proof changes invalidate drafts.
Closing the panel discards its unsubmitted paint, never a sent uncertain request.
A bounded cached reference may expire: only the exact terminal read-only receipt
(success true, outcome known, no payload/document/frame/mutation, exact original
identity and echo, explicit payload_released) clears its read wait. Its original
outcome is preserved, its local image/consent is discarded, and the user must
request a new reference. This diagnostic cannot release a review write or supply
new review authority.

Catalogue thumbnails are explicitly schematic original marks without fake face
photos. The real source image is a full-frame 1280px-or-smaller review preview,
not a full-resolution result. Final output comparisons use the existing main
viewer. Preset/batch selectors expose parameter-only transfers only when the
engine advertises support; every target must retain its own analysis and review.
