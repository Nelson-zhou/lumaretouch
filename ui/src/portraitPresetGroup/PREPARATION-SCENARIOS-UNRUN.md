# Explicit group preparation — authored scenarios, UNRUN

These are source-review acceptance specifications, not executed test results.
No build, typecheck, engine, inference, UI, device, quality or performance run was performed.

- Select two fresh parked originals and saved supported preset. Explicit preparation
  starts once; canonical image_ready/load ID changes must not cancel receipt polling.
  UI blocks unrelated pointer/key/click work until exact known terminal receipt.
- Complete ordered preparation results, exact docs/preset hash, restored editor and
  all prepared statuses are required before the existing complete SHA/DOM-loaded
  group review. Preparation does not check the acceptance box or submit a preset.
- A failure on the second target displays first prepared / second failed / later
  not started, preserves known progress, and never claims the whole group ready.
- Timeout/disconnect/unknown retains the original request, including remount;
  only query-original is offered. Do not resend analysis on timeout.
- New engine, changed selection or changed preset cannot adopt an old review.
  A same-engine load ID change during serial preparation is expected, unlike
  an engine replacement. A full application restart never restores approval.
- Pre-handler no-write refusal may unlock only the exact request identity.
  A partial mutation requires editor_restored and outcome_unknown false to unlock.
- Original project save/export remain separate; normal history is unchanged.
- An older engine advertising only portrait_preset_group_protocol:1 keeps the
  existing prepared-target read-only review, but fresh preparation is disabled.
  Both UI and native batch entry require portrait_preset_preparation_protocol:1
  before dispatching that new mutation.

## Retained multi-person finish / texture group — AUTHORED / UNRUN

- Select `lnx.skin_finish.v1`, `lnx.skin_texture.v1`, or both: display the retained all-face mode; finish means 美白／红润 and texture means 质感／清晰度, never legacy smoothing; legacy `lnx.skin.v1` stays single-face with its original algorithm.
- Two selected fresh originals with 2 and 3 verified own faces: prepare sequentially, restore editor, display full before/after for both and exact respective face counts, then one explicit all-face group approval. No cross-image identities or source masks are selected.
- Missing/duplicate FaceRefs, count mismatch, another asset within a target, lossy analysis revision, absent retained mode, omitted target, stale source/revision, unread or unloaded image: refuse approval.
- Zero faces, manual/unresolved evidence, detector truncation, unsupported operator or legacy smoothing mixed with retained effects: surface refusal, never silently drop a face, module or photograph.
- Closing after successful preparation preserves neutral analysis, never applies the preset. Unknown prepare/commit results remain locked to their original request.
- Scope limits (8 photos, 8 faces each) are admission bounds, not measured speed/quality guarantees. Save and export remain separate explicit actions after a confirmed group receipt.

- Texture native ABI unavailable or target-owned face support missing: surface failure, never use global clarity or scalar smoothing as fallback. This is source wiring only, not texture quality acceptance.

## Mixed global / target-owned group — AUTHORED / UNRUN

- Genuine `portrait-group-wedding-start` store entry appears only with engine
  retained admission; no UI-only recipe or substitute builtin is generated.
- Option and frozen review identify global exposure/WB versus own-face finish/
  texture. Whole-image colour changes are not described as skin-only or adaptive
  per-photo correction; modest builtin values are not a quality recommendation.
- An omitted global module, forged retained mode on global-only preset, unsupported
  module or legacy smoothing mix is refused whole. Original image/DOM/face-ref
  gates still apply; one approval covers the complete declared module scope.
- Engine publication failure cannot be shown as partial success. Unknown original
  commit remains locked. Save/export are still explicit, separate operations.
