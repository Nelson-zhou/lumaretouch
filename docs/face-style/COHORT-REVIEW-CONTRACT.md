# Named face styles and durable all-member portrait review

Baseline `0c65ff49112a8bc56e25d6a013d250594e67f28f`. Source-only implementation;
all execution, numerical and photographic acceptance **UNRUN**. This extends the
same nine PC-32466 family/style/degree requirements, not the algorithm count.
The [original recipe research](REVIEW-CONTRACT.md) and [one-shot target review](BATCH-REVIEW-CONTRACT.md)
remain applicable. New code is repository-original GPL-3.0-or-later. No external
code, model, weights or images are copied, downloaded or executed.

## Named authoring, canonical persistence

The user explicitly chooses one-shot face mapping or persistent association.
Persistent named create/update carries binding-v1 `{version, style, amount}` and
exactly the thirty managed keys of ten operations. The engine regenerates those
local values. It never reads donor slider values, landmarks or masks to create a
named recipe. Source and each target retain their own verified analysis, source
pixels, original provenance, support and existing face-level edits.

Named updates replace the thirty shared person-level leaves and preserve other
shared intent. Existing explicit face overrides still take precedence. They are
not silently cleared to make the chosen style visibly stronger. A member may
therefore look unchanged, but it is still part of the association and must be
reviewed. Degree zero writes neutral shared leaves, not unset/inherit or restoration
of prior manual values.

The existing capsule v1 remains unchanged: canonical scalar intent, members,
generation and local ownership. A preset name is an explicit authoring operation,
not a persistent live badge. It is not reconstructed from saved coefficients.
Canonical unchanged intent remains a known preflight no-write rejection, including
choosing another name at zero. No artificial generation or history transaction is
created from a label change. Old scalar association semantics remain intact.

## Durable lifecycle review without a format migration

A full portrait-cohort review is mandatory whenever the selected association's
prior or resulting canonical intent contains all thirty managed `(op,path)` keys.
The rule tests key coverage, not numeric equality to a named recipe. Every named
create/update installs the full key set; existing scalar patches merge but cannot
remove keys, and direct person-level edits to a cross-owner association are fenced.
Consequently a later generic patch or complete unlink cannot evade visual review,
even after reopening the project or changing individual shared values.

Legacy scalar associations already containing all thirty keys gain this explicit
visual consent requirement. Other scalar associations retain their existing path.
Capsules, numerical inheritance, old saved appearance and generation rules are not
silently migrated. Complete unlink accepts no new named recipe or amount.

## Source plus every member, atomically

Existing association rules still require two to sixteen distinct independently
owned document members, with exactly one explicitly chosen verified face per member.
The current source is a real member, not merely a donor excluded from review.
All members must be available, current and in consensus; there is no skip-and-report
partial association publication and no inference of missing membership.

Before and after are complete actual full-source renders, including retained
nonportrait state, repairs and all effective portrait edits. Full export-snapshot,
support/context and graph identities are frozen for every member. Later rendering
cannot invalidate earlier evidence unnoticed; the entire set is checked again
before claim, after canonical preparation. Opaque-SDR derived sources use their
real effective identity and independently owned evidence; unsupported alpha/HDR
paths are not flattened or clipped to pretend compatibility.

A separate `portrait_cohort` visual contract binds an opaque digest of the exact
association review plus the explicit named authoring recipe, or null for generic
lifecycle operations. Generic later edits never fabricate a style or misuse a
named recipe hash. Native/UI consumers retain the frozen Python proof instead of
recomputing cross-language JSON floating-point hashes.

Paged image reads validate token, member document/revision, side, metadata and
PNG bytes. The user must load and acknowledge source first and every target's
actual pair. Commit carries the exact frozen operation scope, token and ordered
cohort ACK, not a replacement parameter request. Unlink uses an empty scope.

## Collarbone coexistence and bounded pixels

The existing collarbone coverage and complete-cohort review remain independently
mandatory when their original rule applies. Neither proof substitutes for the
other. Both ACK families are accepted together only for the actual frozen
persistent cohort that requires both.

When both reviews describe the same whole-source before/after pair, the second
proof reuses those actual rendered pixels. A shared immutable `_Images` cache
checks complete member, source, snapshot-identity, dimensions and PNG agreement.
Family-specific read wrappers still require their own frozen proof; sharing bytes
does not authorize reading a token through an unrelated family. The same pair is
not rendered twice or stored twice. Both corresponding user approvals remain
explicit and separate.

The existing 128 MiB / 256-image cache bound is shared by these review families,
not doubled. PNGs remain at most 4 MiB each, 1024-pixel-edge RGB8 display reductions,
not full-resolution quality acceptance. Tokens retain existing eight-plan and
30-minute limits. Ordinary sixteen-member memory/performance remains unmeasured.

## History, uncertainty and residual limits

The existing scoped graph ledger owns all-member publication, rollback, dormant
history, undo and redo. Every expected source/owner/FaceRef is rechecked. No new
transaction/history owner is introduced. Exact cohort ACK and scope survive
terminal overflow and replay. Unknown writes remain query-only; no blind retry or
metadata-only dismissal is introduced.

Named preflight requires the existing active owner and already reviewed member
scopes; it does not classify fresh imports. Synchronizing an already committed
live row and filling runtime caches is not claimed as byte-for-byte cache immutability.
Generic lifecycle preflight retains its existing guarded routing; detached generic
request metadata alone does not prove its prior all-thirty-key content.

Single-photo shared-source alias admission remains a separate limitation. No
automatic shape/person classification, proprietary numerical equivalence, learned
AI reconstruction or photographic quality is claimed. All fixtures and actual
save/reopen, native interaction, full-resolution export, undo/redo, numerical and
photographic acceptance are still UNRUN.
