## Replaceable boundary, not a hot plugin loader

The single public source entrypoint is `ui/src/expressionReplacement/index.ts`. The host mounts `ExpressionReplacementPanel` with one `ExpressionController`, a validated `Current` snapshot and optional panel-hide callback. `ExpressionPort` protocol 1 is injected, never constructed through guessed native command names. Its capability declares protocol, exact operation ID, availability and reason. Native-core capability checking is the host's responsibility; missing/incompatible capabilities disable editing instead of substituting a different algorithm. The module performs no registration, dynamic native loading or history ownership.

The parent owns the actual donor picker/import, immutable source bank, analysis, real rasterization, core invocation, full rendering, preview leases, command/status transport, persistence, new-copy transaction and main-workspace mounting. The interface is a contract for those adapters, not evidence that they already exist.

- `chooseDonor(packet)` receives an immutable versioned `choose_donor` command with request ID, binding, exact JSON and hash. It returns an identity-bound `donor_ready` receipt containing `photo`, or a terminal `cancelled` receipt with `no_write: true`. The host registers the request before opening the chooser or starting analysis, so the acquisition can be queried or tombstoned by its exact identity. It must open an actual native image chooser or an already retained image list. It never fetches donor pixels from a name, guessed URL or remote suggestion. The UI accepts only inline PNG bytes and opaque retained source IDs.
- `preview(packet)` is strictly read-only with respect to document pixels/history. It produces a retained candidate, never a side-effecting save.
- `apply(packet)` has `return_mode: new_image`. It must use the existing atomic save-copy owner, never overwrite the original document. A successful receipt supplies the distinct actual result document ID, exact result source identity and revision, and the copied original document ID. Revision zero is valid for a newly created result.
- `cancel({version: 1, operation_id, request_id, command_sha256})` requests cancellation of the original `choose_donor` or `preview` job, never apply. It returns the same identity-bound receipt. `cancelling` means requested but not unwound; only terminal `cancelled` with `no_write: true` confirms task exit. No native/model force-stop is claimed. Late donor/candidate replies cannot regain review authority; late candidate tokens are released.
- `status(requestId, commandSha256)` queries only that existing request, including cancellation completion. A lost/unknown response never authorizes another apply.
- `releasePreview(token)` releases only immutable candidate resources, not a document or historical recipe. It must be idempotent. A submitted save retains its original lease until its outcome is known.

Do not recreate the controller when a panel collapses, the tool changes, or a component remounts. The application lifetime owns it. `canDetach()` is false while any acquisition, candidate or save request is unterminal, or while a request is being prepared/sent; `dispose()` refuses module replacement then. Read-only cancellation retains its request owner until the host confirms exit; a local hide or timeout is not proof of task cancellation. The host must retain its receipt owner and status endpoint across a capability disable, and reconcile that exact request before replacement. Changing the `Current` snapshot revokes review, but does not discard an in-flight save. The host should remove or replace the module only after `canDetach()` and normal reference-resource cleanup.

Neutral is no submitted candidate: opening, clearing the mask, requesting cancellation of a read-only preview and an unavailable module make no document mutation. Cancellation completion is a separate host-receipt fact. This module must never delete, replace with zero, migrate or reinterpret any older saved recipe when disabled. Historical assets and supported old versions remain owned by the host; unsupported versions remain retained and visibly unavailable. Density zero is not used as a fake replacement operation. An explicit copy with numerically identical pixels still needs an actual distinct result identity; `no_change` describes pixels, not absence of a copy.

## Source ownership

Each source binds its effective asset SHA-256, original provenance SHA-256, original/derived kind, EXIF-normalized-once dimensions and opaque retained-asset ID. Each exact source owns its own enabled, verified, nonmanual 478-landmark FaceRef; crop, landmark digest, eligibility digest and hard-protection digest. Face and image ownership must match this source, never the other photograph. A donor matching either the target effective asset or its original-provenance hash is rejected, so re-encoding the same original does not masquerade as another expression photograph. Source hash, retained ID, people graph, document/load/epoch/revision and analysis revision changes invalidate review.

For a currently edited photograph, capture the true full current render as an immutable source, then independently analyze that render. Never reuse original-source FaceRefs or landmarks with a new SHA and never use the preview thumbnail as native input. Host source identity and command binding must stay valid throughout capture, analysis, preview and save. The UI's source proof alone does not perform this work.

Faces have no fabricated yaw/pitch/roll fields. Existing analysis does not supply them. Human pose review is a visible-compatibility assertion only. The core derives conservative two-dimensional compatibility from actual measured landmarks and rejects incompatible or unknown geometry; this is not metric 3D pose estimation. Eligibility can be authentic measured face-oval geometry and is not called skin segmentation. Colour matching is fixed to zero until an independently reviewed skin-only reference exists.

The native header is `core/expression_blend/expression_blend.h`, ABI 1. Crops are bounded to 1024 × 1024, taken at exact original pixel resolution, with finite opaque linear-sRGB D65 float32 RGBA. No rescale, uint8/PNG, invented ICC conversion, guessed pose or transferred analysis enters the core. Landmarks are remapped to the crop's normalized first/last pixel centres. The UI does not own numerical arrays.

## Fusion coordinates and effective mask

Fusion starts empty. It stores up to 128 ordered add/erase strokes with at most 2048 total points. Points are normalized full-source pixel centres, not screen or thumbnail coordinates. Convert to source pixels as `(u * (width - 1), v * (height - 1))`, then subtract crop left/top. Radius is measured in source pixels; crop coordinates and source dimensions are immutable. The editor uses `getScreenCTM().inverse()` and a full-source `-.5 -.5 width height` viewBox. Pointer cancellation, capture loss, source change or disabling aborts the incomplete stroke; over-budget strokes are rejected whole, never truncated.

The host owns and versions the stroke rasterizer. It must make deterministic sequential add/erase round strokes, starting at zero, in the target crop and retain its version in the immutable numerical evidence. Do not treat SVG overlay pixels as the mask. The overlay is deliberately labeled a hand-painted range guide, not actual effective coverage.

The native core returns the actual effective target-crop fusion mask atomically alongside already-fused target-crop RGBA and the numerical report. Effective coverage is constrained by fusion, positive-weight donor eligibility taps, target eligibility, density and exact protected zeroes, as defined by the frozen core ABI. Forbidden donor taps must refuse rather than interpolate around them. Bind the exact numerical mask digest to the retained candidate. The parent must define a stable byte serialization (shape, crop, pixel-centre convention, rasterizer version and float32 byte order); this UI treats the returned digest as opaque and does not invent an independent digest convention. The PNG SHA is not a numerical-mask SHA. Use the exact core-returned mask, not an independent reimplementation. It represents coverage, not pixel-difference magnitude; unchanged colours can have nonzero coverage. Paste returned target RGBA into its exact rectangle without applying the effective mask a second time.

Every preview receipt includes three genuine full-frame PNGs: before, after, and the actual effective fusion mask (white active, black unchanged, gray transitions). Each has independent byte SHA, verified PNG signature/IHDR and natural decode dimensions. Both source references and all three review images must actually load; the user then explicitly confirms the full comparison. A crop, simulated candidate, foreign source, altered PNG or mismatched dimensions cannot enable save. Thumbnails are display-only, not full-resolution or naturalness acceptance.

## Immutable commands and receipts

The UI deep-clones and freezes the full command before any asynchronous send. Each packet contains `command`, the exact bounded `command_json` string, and `command_sha256`. UI JSON uses lexicographically sorted object keys, original array order, finite numbers only, and negative zero as zero. SHA-256 covers the UTF-8 bytes of the exact supplied string. The host hashes those exact bytes, parses with duplicate/nonfinite rejection, and requires the parsed object to equal the separately supplied command. It must not reserialize with Python float formatting or claim cross-language JCS equivalence. The retained bytes/object/hash jointly own later status and apply. Neither the digest alone nor a second independently serialized object is authority.

Preview commands pin the binding, target and donor source-owned face facts, mask vectors, exact settings, and six explicit confirmations: same person, same session, true measured landmarks, visible pose compatibility, both faces unoccluded, and inspected fusion. Human confirmations do not supply missing measured facts. Native ABI review bits map as same_person=1, same_session=2, real_measured_landmarks=4|8, reviewed_pose=16 and both_unoccluded=32|64; fusion_reviewed is an additional host/UI requirement, not an invented native bit. The host must independently verify both measured landmark records before asserting either real-landmark bit.

Apply pins the original preview request and command digest, private candidate token, canonical full-output asset identity, numerical fusion-mask digest, before/after/mask PNG identities, explicit full-image review and save-copy mode. The host must atomically reject changes since preview and refuse token reuse. It returns the exact command identity and original binding even if the user has navigated elsewhere, plus the distinct created document. `result_source_sha256` must equal the candidate immutable asset identity, never a display PNG hash. No nonexistent history-entry ID is required.

Receipts are exact-key discriminated envelopes. Pending, unknown, cancelling, cancelled, donor-ready, no-write rejection, preview-ready and copied-result-committed cannot be conflated. Contradictory extra write claims or missing source/output identities remain unknown. Only an explicit terminal `no_write: true` rejection or read-only cancellation unlocks an unsuccessful operation. Apply cannot have a cancelled receipt. Read-only cancellation suppresses a late successful candidate until the host supplies terminal cancellation/no-write evidence. Saving is sent once; transport failure, timeout, cancellation, new navigation or hidden panel never means a failed write. Reconciliation uses only the original request and digest.
