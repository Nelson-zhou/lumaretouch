# Acceptance matrix — UNRUN

This is a future verification plan, not a test report or completion claim. The requirement is `LNX-REF-WF-165438-165adae6a7`; the current module is source-only and not connected to the shared host.

## Contract and interrupted lifecycle

- Run `model.unrun.test.ts` and `workflow.unrun.test.ts` only after execution is authorized. Compile/typecheck/build the final integrated code separately. Source-only parse success is not a TypeScript typecheck.
- Exercise malformed/extra/missing fields; wrong operation/protocol; v1 wire envelopes against protocol 2; unsupported kernels; malformed decimal revisions; source hash/orientation/dimension changes; reopened document epoch; stale model result; stale/manual/model provenance substitution; depth byte length, endian, padding and SHA mismatch. V1 recipe/depth/capability and the existing context shape must remain unchanged.
- Corrupt PNG CRC, SHA, natural dimensions, IDAT, duplicate IHDR, animation chunks and data after IEND. A structurally plausible test PNG does not prove photograph integrity. Verify browser load rejection and no image-URL fallback.
- Preview with actual measured model data and a separately supplied manual raster. Confirm the visualization is created from the received raster; inspect sparse/flat maps, non-square resolutions and depth borders. Missing-model and pending states must contain no substitute depth and must not initiate downloads.
- Invoke the optional explicit manual-plane action, then test mismatched owner/session/request acknowledgement, wrong constant, a nonconstant returned raster, cancelled preparation and a late result. No manual baseline may appear automatically. The whole path and visualization must say it is an artificial editing baseline, not measured scene depth or completed AI functionality.
- Test subject mode with no mask, stale mask and current measured mask. No face-centre heuristic, uniform foreground depth or label-only “AI ready” may enable subject focus.
- Confirm preview requests do not mutate the document or create history. Change source, document, epoch, revision, depth, model, aperture, interval, stroke or capability while a preview is pending; ignore late results and clean candidate resources through host session leases.
- Verify before and after must BOTH load with exact dimensions and their bound bytes. Check only one loaded, one failed, stale event callbacks, reloaded images, changed recipe, tab navigation/unmount and explicit user checkbox. No comparison slider appearance or checkbox alone authorizes Apply.
- Repeated Apply/Cancel, apply transport timeout, malformed receipt, pending receipt, wrong request/action/token/owner, missing new-document/candidate-output evidence and receipt-query failure must never resend the original command or dismiss unknown state as cancelled. Only a correlated terminal result resolves it.
- Require explicit `return_mode: 'new_image'`, distinct `result_document_id`, exact `copied_original_document_id` and a bounded decimal actual `result_revision`. Reject original-replacement mode, same-document results, an after-PNG hash substituted for `result_source_sha256`, an output hash different from the reviewed candidate, and fabricated `history_entry_id` or old `document_revision` fields. Do not compare new-source-row revision to original or assume the creative-layer revision 0 is the source-row revision.
- Confirm canonical output identity participates in the review key and echoed Apply command. An output-identity change invalidates presentation/ACK even when display PNGs match. Test neutral candidate identity separately: `no_change: true` still returns a distinct created copy, while source/copy pixels and source/original state remain unchanged.
- Switch documents during pending/unknown Apply. Hide stale source imagery; retain the original request owner; query that same request. Test external panel unmount and reopen without destroying the host ledger. Apply and confirmed Cancel auto-exit only after the corresponding terminal receipt and successful actual editor refresh.
- Verify `onTerminal` receives the actual immutable receipt plus original command and refreshes the new `result_document_id`. Delay, reject and time out that callback; keep the successful commit outcome, do not auto-exit early and do not call Apply/Cancel again. Retry only the read-only refresh. Test a context switch during refresh and an omitted callback (`not-configured`, no claim of refresh).
- Disable/re-enable the module during editing, preview, review and an unresolved write. Preserve the draft/stored recipe and original receipt. Do not treat missing module/model as permission to reset the saved effect. Neutral radius zero uses explicit independent-copy semantics, not a nonexistent original history entry.

## Geometry and input

- Test source-aspect fit, real source pixel centres, edges/corners, reduced-depth sample centres, wide/tall photos, CSS scaling, touch/pen/mouse, pointer leaving/reentering, pointercancel and lost capture. No hit in letterbox padding may become a focus point.
- Test click focus at near/far clipping boundaries, keyboard X/Y coordinate entry, crossing near/far sliders and interval invalidation of subject/point mode. Invalid numeric input must not change the recipe.
- Paint clear/blur independently and in order, minimum/maximum radius, zero/full amount, zero/full flow, hard/full feather, taps and long strokes. Verify actual signed rasterization upstream and source-owned persistence. The UI color annotation is not a numerical brush test.
- Test per-stroke/global point limits and total byte budgets without decimation. Interrupt a stroke by source change, module disable, loading, preview, cancel and mode change. An interrupted/oversized in-progress stroke must not remain as a hidden committed vector.
- Check keyboard tab order, labels, disabled controls, focus restoration on exit, dialog focus containment and screen-reader status. Accessibility behavior remains unverified until browser review.

## Numerical/photo and shared integration

- Verify all five original aperture kernels in the actual native renderer, including signed refinement behavior, alpha/premultiplication, linear-light processing, radius limits, occlusion boundaries, depth normalization and exact neutral passthrough. The UI does not establish numerical correctness.
- Review real current photographs with fine hair, glasses, foreground occluders, multiple depth layers, specular highlights, transparent subjects, large blur radii and near/far subjects. Check before/after integrity, halos, protected focus regions, dimensions and memory usage. Record failures; do not claim proprietary parity.
- Integrate the host port with the existing canonical `CreativeHost.commit_return(mode='new_image')` boundary and verify exactly one independent copy, actual post-commit row/source identity, unchanged original document/undo/redo and unchanged original file bytes. Repeated receipt lookup must not create another copy. Inspect new-copy history semantics, project save/reopen and actual export separately; no original-document history entry is expected or fabricated by this path. A neutral request still creates a copy. Candidate images and tokens must not migrate across photos.
- Verify optional model absence, exact pinned model present, incompatible runtime, cancelled inference, source replacement during inference and import of authentic manual depth. Inference/model quality and licensing are separate gates.
- The source-only interface rejects incompatible crop/geometry. If the shared host later expands coordinates, version that mapping and add exact transformation tests rather than silently treating edited previews as original source pixels.
- Check the visible “保存为新副本” action and disclosure distinguish an in-project independent copy from overwriting a source, exporting a file or saving the project. Batch processing, cross-photo transfer, automatic depth acquisition, desktop execution and native/global application wiring are not delivered by this isolated UI module.
