# 产品与手册差距复核（2026-10-21）

## 结论与口径

当前是有真实编辑主链的开发 Alpha，不是纯界面原型，但尚未达到手册 P0 的完整产品验收。P1 只有部分能力，P2 大多未实装。已安装旧包、修复分支源码、定向测试通过、原生产品验收必须分开记账。

依据原始《Linux开源人像修图产品指导手册》和《Linux开源人像修图_AI开发资料包》，而不是旧版 ADR 中的缩减范围。阶段用于排序，不能删除需求。会员、积分等手册原本排除的商业机制不计编辑功能欠账。

本报告是大模块与关键契约复核，不声称已重新验完全部追溯记录。1047 条记录包含父子控件、交叉验收与引用，不是独立功能分母。精修目录的 805 子控件、39 功能族和主面板 39 条显式路由也不能相除生成完成率；独立工作流未全部计入，多个路由还共用同一个编辑器。

## 不应被误报为缺失的现有能力

- `export_edited_16bit()` 与 `export_image16()` 是真实高位深编辑链，不是将 8-bit 左移补零。
- `project.py` 已有原子保存和原片指纹，`tasks.py` 已有持久化任务与恢复；“还没完成发行级验收”不等于“完全没有实现”。
- 批量撤销已比较当前模块与应用后的状态，能够跳过后续修改冲突；缺的是预检到提交之间固定源版本及目标单调 revision 的契约。
- 已有部分逐脸选择与人工修正；但不能由此推导完整多人/跨图人物工作流完成。

## 关键源码位置与原始要求

- `ui/src/App.tsx` 的 `nativeAt100` 附近明确承认当前可能是代理 1:1；手册第六章要求全分辨率检查与导出共用 full_quality。
- `ui/src/components/RetouchPanel.tsx` 的 `WIRED`、`DisabledRow` 与 `LEAF_NOTE` 区分实际接线、占位与不能用 heal 冒充的修补/仿制工具。
- `engine/src/lumaretouch_engine/server.py` 的 `BATCH_KEYS/cmd_batch/_batch_commit` 尚未承接预检 token 与目标 expected revision；手册批量传播要求固定源版本，目标预检后修改须跳过或重新预检。
- `engine/src/lumaretouch_engine/export.py`、`vram.py`、`ops/curves.py` 是当前高位深与曲线共享链；不能用老文档中的“尚无16-bit编辑”覆盖新实现。
- `project.py` 仍有单资产/工程体积上限及 dropped 报告，复杂项目要实测而不是只测 JSON 写成功。
- 手册 P0 门槛包括：授权 200 张代表样本和 50 张困难样本；千张混合集无原片修改/无静默漏导；干净 Linux 离线导入→编辑→预设→同步→检查→导出→重开闭环。单元测试数不能代替这些门槛。

## 推进顺序（保留完整范围）

1. 舒服地修一张：中性导入、基础调色、皮肤范围安全、稳定对比、可发现工具、流畅调参和真实 100% 检查。
2. 放心交付一批：真实合法人像质量、RAW/高位深/ICC、预览导出一致、预检版本契约、异常恢复、干净离线发行及许可门槛。
3. 补齐专业扩展：多人/跨图、局部精修、身体头发妆容衣物手脚、复杂交付及创意，逐项实现和验收，不用隐藏控件或旧“范围外”决定结项。
