# 全分辨率检查：共享处理核心，宿主/UI 尚未接通

原手册要求 full_quality 100% 检查与导出共用处理/色彩定义，不能把代理放大当原图。
本批只建立基础契约，不改变当前界面的代理标识，也不宣布 100% 功能完成。

- `export.render_edited_rgb16` 抽出原有 RGB16/ICC/编辑/几何链，不写文件；原导出调用该函数。
- `full_quality.render_inspection_roi` 接收已解码的真正全尺寸 RGB8/RGB16，整图处理后才裁出最终编辑画布中的 ROI。RGB16 到最后显示转换才降为 RGB8。
- 不在源图上先裁 ROI，避免改变修补、变形覆盖、增强窗口统计。当前是正确性基线，不是高效局部计算。
- 缺失活跃图层、相机 JPEG/代理、高位深源仅剩 8-bit、越界 ROI、超预算、导出专属放大/锐化均拒绝，不静默缩图或跳层。
- 中断在处理前、切块进度、几何前后和发布前检查；并不声称底层解码/整幅几何可随时中断。
- Rust `refinement.rs` 定义源/配方/视口代次、画布 ROI、预算与单运行/最新待运行请求规则。迟到结果不能发布，错误代次不能释放另一个运行任务。该模块尚未接入运行时。

仍需完成：实际 RAM/VRAM/tmpfs 预算估算与解码前准入；不可变配方/资产快照；异步处理与导出协调；独立带身份的像素通道；缓存所有权/释放；原生窗口的 ROI 覆盖、平移、DPR 与 100% 对齐；端到端和视觉验收。

当前导出中的半径与代理尺寸仍未完成统一源坐标归一化；共享导出能证明同一条链，而不能直接证明代理/全尺寸效果尺度完全一致。旧配方不能通过盲目乘比例迁移。

测试应验证 ROI 等于共享导出几何后的对应像素、RGB8/RGB16精度、旋转、拒绝代理/漏层、取消与源数组不变；Rust 测试验证代次、容量、越界、迟到及截断结果。实际运行以 Qoder/CI 回执为准。

复审已补：RGB8 RAW 的 src_bits 元数据可能仍是默认8，不能据此当作高精度；本核心对RAW要求RGB16并显式拒绝half_size。返回值区分 decoded_bits 与真实可知的 source_bits，RAW传感器位深未知时不伪报16。Rust票据含独立source_generation，失败/取消worker通过匹配票据释放槽位，不伪造成功像素。

几何尺寸修正：out_size 与两条旋转臂现在共享 v1 既有的严格半度吸附判据（两侧均包含，恰好半度不吸附）。保留旧配方实际渲染像素与存储角度，不迁移配方；只纠正先前近90度时错误的输出尺寸。新增两侧、正负角和半度边界回归，实际通过情况以 Qoder/CI 为准。

## 后台输入所有权边界（尚未运行时接入）

`render_snapshot.own_render_inputs` 只接收明确的 CPU 值与 RepairOp/LightOp/FacePrecompute/CubeLut记录，先计入每次实际数组复制的字节，再复制为独立只读数组。已连续数组也必须复制，不能通过给live别名加只读标志假装冻结。字典、列表、记录字段均归后台消费者独有。调用方必须在整次检查/复制期间持有编辑命令互斥，不能在worker中复制仍被用户修改的live数据。

预算仅为数组payload；另有限制节点数、文本字节及嵌套深度，不冒充Python进程总内存上界。该函数不是配方/图层有效性验证器，也没有启用全分辨率UI；后续仍须语义白名单、活跃层完整性校验、解码与渲染总预算、worker调度及像素通道接入。

独立像素包协议草案已落为 `inspection_wire.py` / Rust `inspection_wire.rs`，含跨语言同一golden向量、完整会话epoch及请求身份核验。它只编码头/校验已有字节，不等于共享内存发布、生命周期、JS解析或Viewer接入已完成；详见 `inspection-wire-v1.md`。

运行时接入第一步：现有 `Engine._export_snapshot` 已委托同一个纯 `export_recipe.build_export_spec`，保留原函数体与所有现有图层解释，不让检查worker构造假Engine或另抄缩减配方。该函数仍会做全尺寸mask重采样，必须在准入后调用；它本身不提供调度、资源限制或独立输入所有权。检查仍未运行时接通。

运行时准备路径：`inspection_snapshot` 是内部快照准备协议，不是full_quality结果。start要求递增的u64十进制request_id及明确资产预算；当前上限512MiB仅约束快照目标payload，不是进程总RAM。stdin读线程仅向容量1队列入队，全部编辑状态修改和复制tick仍在主执行序列；已排队命令先执行，每空隙最多复制1MiB，任何其他已知命令（hello除外）先取消旧准备事务。元数据验证/目标预约仍在start中，字节tick不是毫秒延迟保证。

事务完成只保存私有owned输入、发preparation_only快照ready；尚未创建渲染worker、发LRIF帧或启用100%UI。取消、导出/换图/历史命令、EOF及shutdown会丢弃未交付准备数据。后续任何后台资产安装也必须走同一取消/状态执行序列，不能直接并发修改源数组。

stdin reader使用原生fd/select及私有唤醒pipe，不阻塞在TextIOWrapper.readline；shutdown即使宿主保持stdin打开，也会唤醒并join reader后关闭本服务自己的pipe。测试覆盖EOF尾行、读取错误、队列积压shutdown、复制失败后下一命令和构造失败清理。输入队列容量只限制行数，不宣称任意JSON行的字节上界。
