## Actual source path

1. The lens host explicitly opts into edited capture version 1 only with the
   negotiated cohort-FFT-v2 renderer. Legacy callers keep version 0. No saved
   aperture recipe, common colour math, geometry sampler or Rust transfer ABI
   changes in this slice.
2. Preselection distinguishes supported original JPEG/PNG global-colour recipes
   from unsupported recipes before admitting extra snapshot copies. A supported
   request has a real owner graph, retained-storage census and bounded snapshot
   admission; this does not retroactively bound upstream host state capture.
3. Strict encoded metadata is inspected without pixel decoding. Genuine PNG16
   integer precision and ICC processing use the existing working-source decoder.
   PNG16 metadata cases whose canonical and retouch orientations differ retain
   the old path, including square images where shape alone cannot expose a flip.
4. The existing full export builder and renderer receive the exact selected
   snapshot. No selected effect is silently omitted. The optimized family is
   deliberately limited to supported global colour, integer crop and the old
   snapped-quarter-turn geometry. Other complete recipes retain legacy dispatch.
5. An exactly neutral detected-person graph is not discarded. Its private
   original-source context must pass a separate source/file/document/analysis
   proof in people preparation. Failed proof refuses the selected strategy;
   it cannot fall through into unadmitted full-frame people preparation.
6. Render-local source/spec/snapshot owners end before final transfer. A separate
   sink uses bounded blocks and the existing Rust signed extended-sRGB transfer.
   It preserves the old float32 assignment contract, with no clipping. Persistent
   host state, encoded original, ICC, actual RGB backing, staging, mutable output
   and the later immutable copy are accounted in their actual phases.
7. Only after immutable asset construction, cancellation checks and unchanged
   file/document fences does the existing asset store intern the result. Existing
   lens candidate comparison, image ACK, new-copy return, history and uncertain
   write reconciliation remain the publishing boundary. Original bytes remain
   unchanged. No proxy image is promoted to a final source.

## Module boundaries and maintenance

- `creative_document_import_bounded.inspect_encoded_source`: bounded metadata
  and working-orientation contract, shared with the existing importer.
- `creative_edited_capture_admission`: versioned eligibility, known-record owner
  census and named phase plans. Unknown future records fail closed.
- `creative_capture_people`: preselection versus definitive original-only proof.
  The private marker is not a general renderer fast-path permission.
- `creative_edited_capture_sink`: output transfer only, with a separate freeze
  requirement. It never claims to release aliases held by its caller.
- `creative_edited_capture`: source ownership, unchanged render and lifetime
  orchestration. Disabling its explicit version leaves legacy recipes intact.

No runtime plugin loader is claimed. These are replaceable source modules with
explicit contracts and existing host registration, not a broad architecture
rewrite. No external code or model weights were copied for this slice; existing
decoder/ICC/native implementation licences and notices remain applicable.

Primary ownership references rechecked 2026-10-25:
[NumPy copies and views](https://numpy.org/doc/stable/user/basics.copies.html)
distinguishes data-buffer copies from views and explains why crop/reshape views
can retain a larger buffer. [Python copy](https://docs.python.org/3/library/copy.html)
documents reference binding, recursive copies and per-pass memoization. These
support counting physical backing owners and planned copies separately; they
are not evidence that this application has met an RSS bound. No documentation
code was copied. Python documentation is PSF-2.0, with examples additionally
0BSD; NumPy dependency licensing remains covered by existing project notices.

## Limits and verification

All fixtures are authored and UNRUN. Syntax/JSON/hash/source inspection is not
decoder, render, numerical parity, photograph quality, cancellation latency,
24 MP throughput or process-memory acceptance. Named native reserves are a
conservative application plan, not an enforceable RSS bound. Decoder/native
calls remain cooperatively cancellable at their existing boundaries.

The 2 GB working and 1 GB session retention limits are not raised. Large encoded
files, retained semantic planes, actual available memory and immutable output
storage still limit admission. Active portrait/body/repair/local/background
effects, custom LUTs, arbitrary-angle rotation, RAW/TIFF and unsupported records
retain the complete older path and its older limits. Transparent/HDR retouch,
automated depth, unrestricted mixed-edit 24 MP capture, dense feather rendering,
batch/preset lens use and editable saved lens recipes remain unfinished.

The separate bounded-geometry proposal is deliberately not included or claimed
reachable in this capture slice. General dormant/alias support is not expanded.
