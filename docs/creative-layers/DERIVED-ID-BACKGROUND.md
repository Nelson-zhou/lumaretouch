## Source identity and review

`creative_derived_id_background` validates every retained support category, including disabled/unselected reviews, against the canonical returned asset identity and dimensions. Metadata-only snapshots retain recipe, original-file provenance and frozen asset identity. They do not embed decoded fields, model input buffers or a second editable bitmap history. Original pathname hashes are provenance only, never substitute analysis ownership.

`id_background_support` resolves manually selected objects against actual current source pixels. Source-owned manual vectors, colour/luminance predicates and existing prompted operands remain supported. Generic semantic/full masks and borrowed original-image masks are refused. A prompted review uses the canonical full-float source through the existing bounded SAM model-input transform, not the display proxy. Live resolution has `path=None` and the owned immutable packet; full export has `path=None` and the exact canonical full-resolution float32 source. The existing model and preprocessing are unchanged. The shared arm/prompted cache now also pins packet content separately from its mutable descriptor.

The three scopes still require separate explicit user review. No automatic hair matte, contact-relation inference or non-contact object detection has been invented. Manual coverage remains the existing 8-bit raster contract; model support remains its declared reduced model field, not a claim of native-resolution hair alpha.

## Pickers and native editing

`id_background_picker` binds source/current-target, selected immutable reference render, and independently reviewed subject/contact scope separately. All modes prove the current actual source pipeline, dimensions and projection; reference sampling also verifies the selected library row and immutable asset bytes. Captures retain float pixels, coverage and a content seal. Native private-copy/presented leases remain mandatory. Presentation and sampling recheck source, reference/support, projection, descriptor and retained pixel/coverage content. Unsupported nonfinite/HDR input is refused before sampling/resizing, not silently clipped.

`creative_id_background_host` admits only the existing exact ID commands and owned picker routes. Native controller receipts, revision fences, history transactions and rollback remain the sole edit owner. Read-only status and terminal receipt replay remain available. Import/review recheck source and revision before mutation. Disabling does not require executing a broken active model. Other background commands and shared planners are not exempted.

## Render, assets and persistence

`id_background_runtime` proves actual live input, ordered repair/output ownership, deformation, recipe/support, background conflicts, model dependency and immutable asset identity before reuse. Strict preparation reruns owned prompted support when required. Prepared stage identity/version is checked on cache hits. Preview keeps existing Rust edge/shadow algorithms and linear-light current-edited-pixel composition. It does not paste the unedited original over previous effects.

`export_snapshot`, `export_recipe`, `export`, `id_background_export` and runtime share the actual derived source for 100% inspection and export. Canonical float input is stamped before repair/quantization; full support preparation verifies it, never reconstructing full pixels from the preview. Full prepared alpha/background fields are sealed and rechecked through export completion. The existing 32 MP and memory/halo budgets remain, with explicit refusal rather than proxy enlargement. This does not certify ordinary 24 MP latency or memory behavior without local acceptance.

`creative_document_project`, server restore and rebound validation check retained source ownership before applying state. Existing project version, nested history, package/recovery storage and original source remain unchanged. The target scope validator accepts only each target's own derived reviews; cross-image planner admission is still fenced. Imported assets remain immutable encoded bundles, not linked mutable files or raw float buffers repeated per history snapshot.

The existing asset decoder is preserved: real PNG16 via imagecodecs, supported RGB/RGBA uint8/uint16 TIFF, ICC conversion, orientation, explicit unassociated-alpha contract, immutable encoded/decoded/alpha hashes, bounded memory and single-page checks. Transparent background assets flatten over the explicitly chosen solid base in linear light. These supported high-bit assets are not downgraded to RGB8. They do not imply HDR or transparent returned portrait-source support. No new model, dependency or copied third-party engine was introduced; existing licence obligations remain unchanged.

## Remaining limitations and acceptance

- Dedicated ID-background recovery is still missing. The common `background_replace` recovery brush belongs to the separate legacy stage; enabling it would not restore this compositor. It remains guarded. Implement a source-owned ID-stage recovery field, native review, history, full replay and stage blend together before claiming that requirement.
- Spill correction, original-shadow extraction/AI retention and its strength/blend/mask workflow remain unimplemented. Designed new shadows are not a substitute.
- Reviewed global-only and explicit face-map transfer are continued in `DERIVED-CROSS-IMAGE-TRANSFER.md`. General background/support-bearing transfer, legacy background algorithms, unsupported local effects and transparent/signed/HDR returned sources remain fenced. No implicit flattening, clipping or guessed model compatibility.
- Runtime/model/device behavior, private capture transport, undo/redo/package reopening, full-resolution quality, actual ICC/PNG16/TIFF decoding, native GUI reachability, memory/cancellation and visual parity are unverified here.

Required local acceptance: different original/returned dimensions; independent category switching; manual/colour/luminance/prompted support; all three pickers and stale presentations; source/repair/reference/asset mutation; missing model and disabled recovery; 8/16-bit export versus 100% inspection; alpha/ICC assets; undo/redo and nested project/package restoration; cancellation, rollback and terminal receipt replay. Authored fixtures are executable specifications for that later work, not evidence that it passed.
