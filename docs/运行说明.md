# 运行说明 · LumaRetouch

> 本文件把"怎么装、怎么起、各变体差别、以及本轮整改新增/定档的行为在界面上怎么体现"集中到一处，
> 落实总目标第七阶段"交付运行说明"。所有命令均取自仓库实际脚本（`packaging/*.sh`、`ui/package.json`、
> `ui/src-tauri/tauri.conf.json`），不写没实现或没跑过的开关。**"能装能起"不等于"效果已验收"**：
> 端到端像素/上屏视觉仍需受控 GPU 窗口，无 GPU 装机路径需在真无 GPU 裸机首跑，见文末"验证状态"。

## 0. 前置条件

- Linux（本项目自测于 x86_64；包为 amd64 deb）。
- Python 3.12 引擎运行时（由 `setup-runtime.sh` 建 venv 安装）。
- 一个加速设备：AMD GPU（ROCm）或 NVIDIA GPU（CUDA）；**无 GPU 也可跑**，但属显式降级路径（见 §3 与 ADR-0022）。
- 桌面运行需 Tauri v2 运行时依赖（WebKitGTK 等，随 deb 的 Depends 声明）。

## 1. 安装引擎运行时（GPU 自动探测）

```bash
bash packaging/setup-runtime.sh              # 默认 --variant auto：按 PCI 厂商探测装 GPU
```

- 探测读 `/sys/bus/pci` 的显示控制器厂商：`0x1002`→装 ROCm 变体，`0x10de`→装 CUDA 变体。
- 默认装到用户级 `XDG_DATA_HOME/LumaRetouch/engine/venv`；`--system` 装到 `/usr/lib/LumaRetouch/engine/venv`（需 root）。
- 幂等重跑：已有 venv 时只校验 + 补装 + 自检；`--force-new` 重建。
- 国内/离线取轮子：`--index-url <镜像>`（或 `LRT_WHEEL_INDEX`），会剔掉清单里的上游 index，避免静默回落到上游慢源。

常用参数：`--variant auto|rocm|cuda|cpu`、`--prefix DIR`、`--recheck`（只跑自检不装）、`--dry-run`（打印将执行命令不动磁盘）。

## 2. 装完先跑前置检查（判定"加速真的可用"）

```bash
bash packaging/preflight.sh                       # 用默认解释器
LRT_ENGINE_PY=<venv>/bin/python bash packaging/preflight.sh
```

`preflight.sh` 不看版本号，交给 `probe/probe.py` 用真算子、真数据打靶。退出码：`0` 可用 / `1` 依赖缺失 / `2` 设备不可用 / `3` 判定未通过。**安装成功不等于加速可用**——这一步就是用来戳穿"装了个跑不动的包"。

## 3. 无 GPU 的安装路径（显式降级，手册 P0 首版②）

```bash
bash packaging/setup-runtime.sh --variant cpu
```

- 这是决策 10"不做静默 CPU 回落"之外的一条**显式 opt-in** 路径：只有点名 `--variant cpu` 才走它；`auto` 探测不到 AMD/NVIDIA 时**仍会报错退出**，不会自动降级到 CPU。清单见 `engine/requirements-cpu.txt`。
- **能力/性能边界（务必知情，已实测）**：常驻精修管线建立在 torch 之上。`test_perf_report.py` 在
  `CUDA_VISIBLE_DEVICES=""` 下跑出产品形状（1024×1280）CPU 分位：导入首帧 ~608 ms、拖动重渲 p50 14 / p95 18.5 ms
  （缓存复用率 1.0）、预计算推断 ~491 ms、形变建场 ~1626 ms、导出 ~726 ms/张。属"可用、能出正确结果、
  拖动基本跟手、首帧与重效果偏慢"的降级，不是与 GPU 等体验。详见 `docs/adr/0022-no-gpu-run-path-capability-and-perf-boundary.md`。
- CPU 变体自检：`setup-runtime.sh` 的 selfcheck 带 `LRT_VARIANT` 守卫，按无 GPU 路径判定时 `gpu_available=False` 属预期（不误报为失败）。
- **未运行**：产品形状 CPU 耗时曲线已实测（见上），但 clean CPU 轮子在真无 GPU 裸机上的实际装机与端到端上屏，仍需首跑回填——不拿"代码能跑 + dry-run 通 + 本机隐卡耗时"冒充"裸机装机验收通过"。

## 4. 开发模式启动

```bash
cd ui
npm run stage:engine      # 把引擎源码 + 各 requirements 清单暂存进 gen/（去掉 __pycache__）
npm run dev               # Vite 前端（http://127.0.0.1:1420）
npm run tauri dev         # 起 Tauri 桌面窗口（beforeDevCommand 会先拉 vite）
```

## 5. 构建与打包

```bash
cd ui
npm run build             # tsc --noEmit 类型检查 + vite 构建
npm run tauri build       # 出 deb/其他产物（beforeBuildCommand = stage:engine && build）

bash packaging/build-deb.sh      # 仓库层出 deb 封装
bash packaging/install-deb.sh    # 按 sha256 内容校验后安装
```

发布前静态门禁（不需 GPU/root，CI 可直接跑）：

```bash
bash packaging/check-release.sh          # 版本一致/包描述/运行时候选表/暂存卫生/随包文件/许可台账/P0注册表覆盖
bash packaging/m5-release-check.sh       # 真窗口多臂验收（需 GPU 窗口，见文末）
```

## 6. 测试

```bash
# 前端（无 vitest，用 Node 24 原生 strip-types）
cd ui && npm test         # view / gradeLimits / exportModel / repairToolHonesty

# 引擎
PYTHONPATH=engine/src <venv>/bin/python -m pytest engine/tests -q
```

跑测纪律：满载 GPU 端到端会打满 ROCm，历史曾因此整机冻结；批量回归须在受控 GPU 窗口分批跑。纯逻辑/CPU 单测可加 `CUDA_VISIBLE_DEVICES=""` 走 CPU 确定性路径。

## 7. 本轮定档行为在界面上的体现

- **16-bit TIFF 导入（不静默降 8 位）**：16bpc RGB TIFF 走真 uint16 直通解码，母档导出保持 16-bit；非 16-bit 变体不会被左移补零冒充高位深。首版为双路模型（8-bit 编辑 + 16-bit 位忠直通，像素编辑按 16 位直通拦截），见 `docs/adr/0023-export-color-defaults-and-16bit-workspace.md`。
- **导出色彩与渲染意图**：工作空间恒 sRGB；导出到非 sRGB 命名档才真正做颜色转换（含 webp 等所有嵌档格式），`source`（保持源档）将工作 sRGB 像素转回源档；非 RAW 输入按嵌入 ICC 显式转换到工作 sRGB；渲染意图缺省 relative_colorimetric + BPC。同见 ADR-0023。
- **100% 检视如实标注**：当代理档被降采样、1:1 并非原始分辨率时，界面如实标"代理档"徽标，不冒充原始分辨率全像素；真全分辨率按需渲染尚待引擎出精帧 + GPU（未接通）。

### 当前开发分支补充：TIFF与工程恢复

16-bit RGB TIFF 导入使用 tifffile / imagecodecs，支持无压缩、Deflate、LZW、条带/分块、分离平面、大小端与 BigTIFF；方向无损重排。多页、浮点和额外 alpha 通道尚不提供选择/转换，不静默丢弃内容。需要按更新后的依赖/运行时安装脚本安装，不能只复制 Python 源码而沿用缺少编解码器的旧运行时。

这不等于已完成高位深编辑导出：当前16-bit母档直通仍会拒绝带编辑的照片，批量中每张均检查，不会只看当前照片后忽略其余图的编辑。

工程打开时原片内容改变/缺失会在所有工作区保留提醒；提醒在保存后仍保留，重新打开工程重新校验。模型掩膜不存工程，但已选择的皮肤通道/局部肤色作用域会触发重新分析并恢复。重新分析失败仍报告失败，不能当作正常恢复。
