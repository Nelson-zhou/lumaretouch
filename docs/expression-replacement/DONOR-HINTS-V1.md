## Actual authored route

Existing expression current-source acquisition additionally reads existing
confirmed person associations. Optional versioned `donor_hints` travels through
the same native current receipt, exact Python owner, Rust wire validator and
TypeScript validator into the existing review panel. Older receipts without this
optional field remain valid. No new write/history/receipt controller is created.

- Ordinary shared-project confirmed links are supported. The current original
  must have one enabled exact face for that person; each associated original must
  resolve to one retained nontrashed project-scope document. Existing retained `_people_source_sha256` or saved full-file
  fingerprints are only a routing index: canonical source/graph/document proofs
  are independently re-read. Missing retained/saved digest/ambiguous aliases, repeated
  faces on one original, disabled/manual/unverified faces refuse that cohort.
- Independent cross-owner associations use canonical capsules, exact member
  source/document/scope/FaceRefs and generation consensus. All members must be
  available and verified; an extra replica or stale member refuses the cohort.
- At most eight cohorts, each with two to sixteen explicitly associated faces.
  A source-returned derived baseline is not treated as the file named by its row.
  Hints currently support original-source evidence only.
- Each eye reading comes from that exact retained FaceRef and analysis revision,
  verified landmark digest, actual source dimensions and MediaPipe evidence.
  Reuses existing `picks.eye_openness`: smaller of the two pixel-domain eyelid
  gap/width ratios. No model inference is added; missing/incompatible/corrupt
  retained records yield **unknown**, not a guessed smile or quality score.
- The only ordering is descending measured eyelid aperture, with unknown last
  and stable document-ID tie breaks. It is not a closed-eye decision, gaze/pose
  measurement, expression preference, quality ordering or best-donor decision.
- UI displays filenames and exact original face/document identities. These do
  **not** auto-map onto newly analysed edited-source FaceRefs. User still uses
  the existing file picker, fresh donor/target face selections, explicit identity/
  session/pose/visibility confirmation, fusion brush, full before/after review
  and canonical new-copy transaction. No automatic selection, apply or deletion.

## Freshness, responsiveness and failures

No additional full-image decoding, model call or original-focus capture occurs.
Original-file content proofs can require hashing and are cancellable between
members/phases, not midway through an existing digest call. Other-member hints
are snapshots at acquisition time, not live monitoring or apply authorization;
manual donor capture revalidates its own actual source. Original current-source
fence is rechecked before publishing. Optional hint failure leaves manual flow
available; cancellation propagates instead of becoming an unavailable hint.

Original eye-region quality is explicitly **unknown**. The source-only
`pick_original_focus.review` could later accept a separately user-requested,
exact hash-verified original eye coordinate with fresh source/budget proofs.
This slice does not silently run eight full decodes during current acquisition,
reuse the default centre crop as eye evidence, or use proxy sharpness as quality.
