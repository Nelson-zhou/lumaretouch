# Measured reference proposal integration

Source-authored partial scope for `control:PC-32465:19`. Numerical, native ABI,
GUI, real-photo, history, project reopen, resource and export acceptance are
**UNRUN**. This is not a new correction algorithm, learned-AI classifier,
instance-segmentation system or proprietary brightest-face metric reproduction.

## Actual user path and authority

The face and body panels retain their separate source catalogs. After loading
and viewing that exact catalog image, the user may request a measured reference
suggestion. The engine captures the immutable original/native-precision or
canonical derived opaque SDR source, before repair and portrait edits. It measures
all enabled retained same-source faces using their own verified landmarks,
face-skin observation and conservative protected source support. It does not fit
proxy display RGB or rank detector confidence, demographics or beauty.

The existing Rust reference solver measures each region against itself with zero
correction limits. Its robust log-luminance diagnostic supplies the ranking; no
transform, source RGB, fitted coefficients or sampled mask is retained in a
recipe. The same existing correction solver and old face/body recipe versions
are unchanged. The selected family still performs its own full-source fit later.

A sufficiently distinct brightest measurement is a suggestion among retained
measurable faces, not a claim that all people in the photograph were found.
Missing measurements, a reached detector limit and a near tie remain explicit
reasons not to nominate automatically. The user can inspect measured alternatives
and explicitly choose an eligible reference. No result arrival automatically
selects a reference, grants ownership, paints support, acknowledges images or
applies edits. The existing common-reference restriction across active face/body
matching remains intact.

Choosing a suggested or manually overridden reference invalidates any incompatible
local draft consent and review. Face or body targets still require their own
existing evidence and complete mixed before/after image review before the usual
canonical commit. A body suggestion does not create BodyRef ownership or manual
body permission. Other portrait effects may independently affect the reference;
only the matching operations exclude it from their own correction.

## Stable module ports and exact current source

`skin_reference_choice` is one read-only action inside the existing people
command owner, with independent `skin_reference_choice_protocol: 1` capability.
It is not a new queue, mutation owner, history ledger or Tauri root command.
Unavailable capability leaves manual face/body selection unchanged.

The request carries one family, its exact source-review digest and an optional
explicit same-source FaceRef. Native/UI admission preserves the original eight
context fields in `skin_reference_choice_request`. The host verifies the actual
family source catalog, full document/repair snapshot, graph, body bank, analysis
bank and source pixel digest before and after measurement. Result metadata is
bound to those facts; its digest is not mutation authority. Original-file source
hashes and derived canonical source identities remain distinct.

The UI uses the existing pending/original-request query state, rejects stale
view/catalog responses and requires the source image to remain presented before
selection. The subsequent existing candidate transaction independently rechecks
current ownership and source proof. This proposal never changes the people cursor,
graph, support bank, document image or saved history, including on failure.

## Explicit remaining limits

- `census_complete: false` deliberately disclaims complete photograph-wide face
  detection. It does not mean a complete retained-candidate measurement is absent.
- Measurements describe observed source illumination and colour, not intrinsic
  complexion, ethnicity, reflectance, calibrated light or statistical confidence.
- Known occluders and neighboring faces are conservatively excluded. Unknown
  occlusion, detector omissions and semantic errors still require human review.
- Source and candidate displays remain reduced RGB8, not native-resolution quality
  proof. Native-precision fitting does not by itself prove preview/export parity.
- Existing bounded source capture, face-count, fit and full-render memory limits
  remain. No runtime 24 MP, timing or cancellation guarantee is claimed; no final
  output downsampling or silent alpha/HDR clipping is introduced.
- Automatic correction/approval, cross-photo reference transfer, batch/cohort and
  shared-source alias variants remain outside this slice. Whole-feature AI
  acceptance is still incomplete.

## Static review corrections

Independent source review verified the actual Rust diagnostic indexes and found
three integration defects before this freeze: verifier snapshot copies preceded
admission, native metadata used a storage label instead of the measurement ABI
encoding, and UI diagnostic bounds were stricter than the native roundoff
contract. These are corrected in source. The UI now also accepts the actual
canonical read-result envelope rather than an idealized payload-only fixture.

Memory admission now precedes any family snapshot verifier and reserves its
per-face copies while captured source remains resident. Capture and measurement
allowances are the values actually passed at their respective phases; neither is
retrospectively rewritten to fit a validator. Final resident/reserved bytes plus
actual admitted work must still fit the total bound. This is a reviewed source
contract, not measured memory behavior or a numerical/runtime acceptance result.
