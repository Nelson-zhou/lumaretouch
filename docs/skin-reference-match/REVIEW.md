## Ownership and integration

`skin_reference_match_host.py` owns only its source/review tokens, exact proof and immutable display pages. It creates no root command, graph owner, project support bank, transaction ledger or history owner. The existing `people` envelope/receipts, `people_host_commands.publish`, canonical people graph owner and outer document history retain those responsibilities.

Expose the six existing-people actions in `ACTIONS`, mark `READS` read-only before recovery dispatch, use `check_action`, and route their handlers. The target is exactly `{scope: "all_people", target_id: effective_source_sha256, face_ref: null}`. It is a photo binding, not a request to infer the target set or use group inheritance. `checked()` must require the already active owner but must not apply the currently selected-face cursor gate to this family. It must retain the original editable/source/document/graph/association guards.

Every reply must echo the full exact captured request under `skin_reference_match_request`. Confirm and clear call the module's `publish(engine, state, target, payload, candidate, proof, request_id, mark_started)`, which wraps the original publisher. Use its returned batch/frame tuple. Do not publish a second time. `verify_after_publish` is available for the outer route. Include `report(engine, state)` under `doc_state.people.skin_reference_match`. Call `bound_receipt_images(records)` when bounding the original receipt store. Unknown publication outcomes belong to that original receipt route and must not be converted to ordinary refusals or retried under a new request ID.

## Wire contract

All action names below have the `skin_reference_match_` prefix.

- `catalog`: payload `{}`. Returns the actual authenticated immutable effective-source PNG reduced only for display, full source dimensions/provenance, stable document identity/revision, explicit face boxes and FaceRefs, current matching report, capability, and `source_review_sha256`.
- `preview`: payload `{version: 1, reference_face_ref, target_face_refs, amount, source_review_sha256, ownership_confirmed: true}`. Amount must be positive and at most one. Targets are explicit unique enabled verified same-source FaceRefs, 1–63 entries, and cannot include the selected reference. The complete source catalog is capped at 64 faces; it never silently omits a face. The source proof must be the exact retained current catalog proof.
- `image`: payload `{token, side, sha256, review_sha256}`. Each immutable page belongs to the frozen document/revision/side/review. Returns the original payload fields, `kind`, and `image`.
- `confirm`: payload `{token, ack: {review_sha256, before_sha256, after_sha256}}`. Both exact image pages must have been retrieved. Client-side PNG hash, actual decoded dimensions and successful image-load acknowledgment remain necessary before offering confirmation.
- `clear`: payload `{}`. Removes this operation's entire current-photo scalar/pointer set, including dormant rows. Does not remove immutable support bytes needed by history or touch other recipes. No matching intent is a refusal rather than a fake edit. Does not require the native fitting extension, a source display, or image review; original source/analysis/editability guards still apply.

`source_image` and image page data have `{mime: "image/png", width, height, sha256, base64}`. Compact before/after metadata omits `base64`. Display dimensions are proportional `portrait_review_render.preview_size`, maximum edge 1024; PNG bytes are at most 4 MiB. Source boxes are `[left, top, right, bottom]`, normalized on the uncropped immutable source, not on warped/cropped output. The overlay must visibly identify reference and targets and require explicit ownership confirmation. No source display pixel is ever used for fitting.

The catalog fields are `kind`, `version`, `operation_id`, `scope: "current-photo-face-only"`, `source`, `source_proof`, `document_id`, decimal-string `revision`, `source_image`, `source_review_sha256`, `faces`, `current`, `body_matching: false`, `automatic_reference: false`, `skin_reference_match_available`, `skin_reference_match_reason`. Each face is `{face_ref, box, enabled, available, reason, amount}`. A reason is null on availability, otherwise a nonempty refusal. `source` is `{sha256, width, height}`; `source_proof` uses the canonical original/effective-source proof.

The current/report value is `{version: 1, operation_id, bank_sha256, reference_face_ref, target_face_refs, amounts}`. Each amount entry is `{face_ref, amount, support_sha256}`. Neutral has null reference and empty lists. Report rows are sorted by stable face ID; review and confirmation preserve the user's target order. Compare exact unique FaceRef sets and per-face amounts/support hashes, not incidental order.

Preview returns `{kind, review}`. Review includes `version`, random 32-hex `token`, `operation_id`, the standard six-field inventory `owner`, `source`, `reference_face_ref`, `target_face_refs`, `amount`, `source_review_sha256`, `before_target_face_refs`, `candidate_state_revision`, `before_bank_sha256`, `candidate_bank_sha256`, target-ID-keyed `support_sha256`, `visual`, and `review_sha256`. Owner scope may be `project` for an ordinary original document, but the exact affected source must have only one current document in that owner; it is not a blanket project permission.

Visual fields are `version`, `document_id`, decimal-string `revision`, `source_proof`, `source_size`, `before_output_size`, `after_output_size`, `before_state_sha256`, `candidate_state_sha256`, `before_people_sha256`, `candidate_people_sha256`, `before`, `after`. Both sides are complete current recipes, including repair and all unrelated portrait/global edits, rendered through `portrait_review_render`/`full_candidate_render`. New support is private `staged_people_context.people_support_assets` during preparation, never temporarily installed to render the preview.

Confirmation proof includes `kind`, `token`, `review_sha256`, exact `ack`, `reference_face_ref`, `target_face_refs`, `amount`, `candidate_state_revision`, `support_sha256`, `candidate_bank_sha256`. Clear proof includes `kind`, `candidate_state_revision`, `cleared_face_refs`. Each real publication increases graph revision and current document revision by exactly one; association revision is unchanged.

## Atomic replacement, protection and persistence

The candidate first removes this operation's complete prior current-photo target set and pointers, then retains one operation-specific relation per chosen target with `skin_reference_match_support.retain`. All new targets share the chosen non-target reference. Pure staging compacts its intermediate counters into one final graph revision. Unrelated recipes, faces, labels and associations are untouched. Reference metadata is not a portable scalar; no pixels, masks, sampled colours or fitted numerical transform are persisted. Existing immutable supports remain append-only so undo/redo and older relations can resolve.

Source-identical aliases, unavailable/dormant affected documents, other photographs, generic patches, presets, batch/cohort transfer and activation through shared inheritance are refused by this current-photo-only slice. No alias is silently edited. Generic reenable/amount/support/analysis changes to an active effect require a new review. The reference and every neighboring face box are protective anatomy, not unrelated edits. A neutral clear remains reachable.

`skin_reference_match_project.py` exposes `validate_leaf`, `recipe`, `active_refs`, `validate_graph`, `validate_records`, `validate`, `validate_owned_graph`, `require_unreviewed_transition`, `require_scope`, `require_transition`, and narrowly scoped `reviewed_transition`. Admission binds the exact original owner/fence, before graph, complete candidate and canonical bank digest. It cannot nest or admit a different graph or bank and is removed in `finally`. Parent integration must call guards in generic patch/preset/transfer/cohort paths and canonical preparation, and register the operation support kind in the canonical bank/raster exclusion. It must wire the actual full-source runtime provider separately.

`validate(project)` checks active and historical graph/face pointers using their nearest canonical owned bank, validates every operation relation record, and verifies enabled active targets share one existing reference. Dormant historical relations remain checked metadata, not current rendering permission. It never injects a neutral field or edits old documents, so adding this feature does not change neutral v1 project digests.

Only after final revalidation does confirmation install append-only support metadata and invoke the existing canonical publication inside exact admission. A preparation refusal may leave unused immutable metadata, never a successful graph edit. A changed owner fence, started commit or failed post-publication check must follow existing unknown-outcome recovery, not manufacture a fresh successful receipt. The host never creates its own rollback/history transaction.
