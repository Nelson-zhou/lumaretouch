## Requirement and actual operation

The exact retained controls are `control:PC-32472:2` (crown height) and
`control:PC-32472:3` (side volume). The official desktop guide, refreshed in this
source review on 2026-10-25, gives crown down/up and sides less/more with a left /
right lock: https://www.pixcakeai.com/guide/32472 (updated 2026-09-18).
It does not specify vendor numerical ranges or distinguish the two crown names.
The local versioned signed range is original implementation, not vendor parity.
This does not implement hairline movement, sparse-hair synthesis or stray-hair
removal, and does not increase the number/density of hair strands.

## Real current-photo path

The app-lifetime hair family mounts a dedicated contour workflow. The source
canvas displays actual source pixels as a bounded RGB8 image, not a native-pixel
inspection or final-quality proof. Source coordinates use `(width-1,height-1)`.
Users mark independent crown / left / right contours, paired hair/background
probes, complete transition strips and visible ear/neck/other-person protection.
The source owner and whole-frame review are explicit. Low hair confidence is not
proof that an area is background; clothing, objects and ambiguous contacts must
be protected or the operation declined.

The controller retains immutable canonical support bytes, stages the exact graph
and shared bank without publishing, and uses the existing full candidate
renderer for complete before/after photographs. A third image is a source
geometry diagnostic, letterboxed where needed, never a segmentation prediction
or a substitute for the complete effect image. All three hashes must be loaded
and acknowledged before the original single-use commit.

The common portrait renderer appends the field to the existing owner chain and
samples through the existing shared face/body geometry path. Original RGB8/16
and supported opaque SDR derived identity remain distinct. No original-source
mask is borrowed for derived pixels. Original source bytes remain unchanged.
Prepared strips bind source, FaceRef, semantic model/evidence, complete retained
face census, support hash and scalar intent. Hair supports use the existing
append-only `people_support_assets`, project contexts and canonical history,
not a parallel undo store. Snapshot/export replay freezes actual source evidence.

Foreign face geometry is checked at every queried common/body sample using
unwrapped complete inverse chains. If a nonzero new hair contribution overlaps
a foreign actual field, the render refuses rather than silently dropping it via
stable-owner priority. Existing priority and RGB sampler are unchanged. This is
not a proof of continuous global injectivity between samples. Exact 1/2/4 source
pixel admission boundaries use only a tiny float-comparison tolerance; no query
coordinates, amounts or rendered pixels are rounded or clipped to hide errors.
