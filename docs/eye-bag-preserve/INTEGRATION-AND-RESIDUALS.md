# Integration map and remaining work

Source-authored only. The exact payload is recorded in `FREEZE.json`; no runtime
or photographic acceptance follows from the wiring described here.

## Actual connected path

1. The dedicated retouch panel reads the current effective source and exact
   selected FaceRef. Original and returned opaque SDR sources use their own
   retained analysis, never original analysis rebound to a returned composite.
2. Independent per-eye source-edge vector strokes mark a visible ridge. The
   editor supports brush/erase, per-eye clear/undo, source-pixel width, feather,
   pan and zoom. It distinguishes advisory drawing from authoritative raster.
3. `eye_bag_preserve_support` retains content-addressed reviewed records in the
   existing support bank, without introducing another history or asset owner.
   Complete map replacement permits clearing a previously reviewed eye; old
   immutable bytes remain recoverable. Face skin, known exclusions, lower-lid
   geometry and competing-face regions limit applicability, not prove anatomy.
4. `eye_bag_preserve_layer` solves the unchanged pinned eye-bag correction on a
   complete full-resolution face ROI with its existing reference padding. The
   independent Rust compositor protects the admitted source region. The new
   stage is distinct from legacy `eye_detail`, so it does not erase unrelated
   eye corrections through duplicate-stage overlap arbitration.
5. `eye_bag_preserve_host` freezes the entire mixed portrait graph, source,
   repair stack, owner and immutable support. Before/after are actual complete
   canonical renders. The support overlay is rasterized at the authenticated
   source-analysis grid before display reduction, with separate source/grid
   metadata. It is not a full-resolution semantic segmentation assertion.
6. Three immutable image pages must load, match hashes/dimensions and be
   acknowledged. Confirmation binds the exact candidate graph revision and
   support digest. The existing people owner publishes one document history
   step, with exact revision/owner checks and correlated uncertainty handling.
7. Canonical preview, original/derived export, project/history validation and
   packaging use the new dedicated operation. Generic patch, person/group
   inheritance, confirmed transfer and persistent cross-owner cohort paths
   cannot introduce/change an active reviewed operation without its dedicated
   proof. Normal history restoration remains under the existing history owner.

## Legacy and neutral behavior

The old enhancement amount and numeric core are not migrated automatically.
Explicit replacement clears only legacy eye-bag intent in the same reviewed
transaction. It does not clear dark circles or unrelated enhancements.
New amount zero is a dormant reset and does not require a native solver or live
support raster. This does not waive structural integrity checks: a missing or
tampered persisted immutable asset is a project-recovery problem, not permission
to publish an unverified graph. No corrupt-project recovery acceptance is claimed.

## Precise residuals

- Automatic anatomical ridge detection remains absent. Manual reviewed support
  does not close the full official preservation requirement.
- Native-spatial source eye crops now provide the painting view, with exact
  whole-source edge coordinates and separately hash-bound image pages. The
  full-frame thumbnail is only a locator. Display remains RGB8, and oversized
  crops/source decodes refuse rather than reduce detail. See
  `SOURCE-CROP-CONTRACT.md`; actual decode/UI acceptance is still UNRUN.
- Active generic preset/batch and persistent-cohort application remain refused.
  Scalar capture/archive and neutral reset do not constitute active transfer.
  A future transfer path must stage the target's own reviewed side masks and
  actual full before/after/support images, never transfer donor masks or geometry.
- Current single-photo positive review refuses shared-source aliases and dormant
  affected siblings. Complete affected-set review is not implemented for v2.
- New effect-specific recovery painting is not connected. The preservation
  brush protects only this operation's approved ridge region, not arbitrary
  recovery or the old enhancement family.
- Complete UI cancellation is not wired through canonical preparation; native
  cancellation and private publication exist, but legacy OpenCV and mask-worker
  execution retain their existing interruption limits.
- Alpha/HDR, automatic person segmentation, native-pixel appearance parity,
  broad photo suitability and measured memory/performance remain unaccepted.

No requirement/work-package/algorithm count is incremented merely for new
adapters, the version number, review messages, or the Rust preservation blend.
