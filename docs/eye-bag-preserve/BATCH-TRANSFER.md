# Target-owned eye-bag scalar batch review

Status: source development only. All execution, numerical, photographic, native,
UI, history, project-reopen and export acceptance remains UNRUN.

This closes an ordinary batch workflow for the existing manual-assisted
`lnx.eye_bags.v2` operation. It is not a new correction algorithm, automatic
ridge segmentation, or acceptance of the full original preservation requirement
`LNX-REF-PC-32464-C-e5fac5fdcf`.

## Intended authority boundary

- The source contributes selected scalar parameter leaves only. A target's
  FaceRef, independently reviewed per-eye protection, support bank, recovery
  vectors and image pixels never come from the donor.
- Each explicit target document carries its own legacy replacement choice.
  Active replacement may clear that target's old eye-bag amount, not unrelated
  enhancement controls. A conflicting selected nonzero legacy amount is an
  error, not permission to silently discard part of the selection.
- All selected leaves are staged into the complete target owner graph. Image
  review shows the complete canonical mixed result, including other effects and
  current target repairs. It is not an isolated eye-bag overlay.
- The existing frozen batch token, protected ledger, graph rollback and native
  receipt owner remain the only publication/history authority. Display evidence
  is session-only and must never enter project assets or effect masks.
- Generic metadata cannot grant active transfer authority. Dedicated review
  verifies actual target-local evidence before preparation and again before
  publication. Persistent-cohort routes are not opened by this ordinary batch
  extension.

The UI separately exposes the pre-existing neutral compatibility path only
when the selected, conflict-free source amount is exactly zero. That route
omits the dedicated eye-bag policy and ACK fields; the engine still resolves
and checks each final target recipe. A preserve-only selection cannot use the
donor's zero amount to pretend an already-active target is neutral. Other
selected modules retain their own validation/review requirements.

## Integration and history

The dedicated planner stages scalar leaves and any explicitly approved legacy
replacement into the final owner aggregate. It binds target-local coverage and
full source/repair/support snapshots to existing frozen target records. The
separate image cache reuses the bounded immutable display store; its token
does not create another transaction or durable mask asset.

Protected batch history retains exact affected document membership and target
observation/support dependencies. History dependency hashing uses the existing
project codec rather than transient precompute arrays, UI cursors or unrelated
append-only support-bank contents. Save and load validate the marker. Undo/redo
captures the current document before checking dependencies, verifies dormant
source participation, and refuses newly affected unreviewed aliases. Older
unmarked history retains its previous semantics.

The source-only review also covers exact no-op outcomes: an unchanged target
still requires its image ACK on the dedicated route, but an entirely unchanged
candidate creates no batch history entry. Policy/context changes invalidate
read authority monotonically, including changing away and back. Submitted or
uncertain writes remain attached to their original receipt for query only.

After reopen, a compact validated ledger summary identifies this protected
history family and its changed member count; no full support record is exposed
as status. Correlated batch undo/redo now retains its exact existing batch ID in
the native receipt binding. A server guard refusal reports known no-write only
when the serialized boundary proves that the handler was never entered. Once
the handler starts, this helper cannot turn uncertainty into a canceled or
failed-without-write result.

## Review precision and honest limitations

The existing full-source renderer must successfully render the actual original
or independently bound derived source without omitting edits. Source precision
is retained by that renderer. The complete image is subsequently reduced to a
maximum 1024-pixel edge and encoded as RGB8 PNG solely for review. This display
is not native-resolution eye inspection, a lossless export, or HDR/alpha support.

Images use the established immutable paged evidence store, with exact target,
revision, side and content hash. No target is silently omitted or rendered at
lower detail to satisfy transport budgets. Missing target protection requires
opening and independently painting/reviewing that target first. An unreviewed
eye remains untreated; it is not inferred from its opposite eye or another
person.

Ordinary image/source limits, finite memory budgets and source verification
remain in force. Shared-source and dormant-history participation must either be
fully accounted for by the actual affected-set review or explicitly refused.
An uncertain write remains query-only; closing a review cannot declare it
canceled, successful or safe to repeat.

## Numerical and licensing continuity

No numerical core, solver constant, color transform or sampler is changed by
this workflow. The original implementation and pinned RapidRetouch licensing
remain documented in `REQUIREMENT-AND-RESEARCH.md`. No third-party code, model,
weights or assets are imported in this slice. The primary darktable history
stack manual was requested during this slice but the web tool returned an
access error; no new content or verification is claimed from that request.

The requirement remains partial. Manual support and a better transfer review do
not establish learned AI, automatic anatomy, broad photographic suitability,
vendor equivalence or tested runtime reliability.
