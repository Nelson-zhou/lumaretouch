# Shared-source visible-support painting

Source-connected implementation, all runtime and photographic acceptance UNRUN.
This completes a guarded workflow for the existing decoration operation; it adds
no renderer, material, automatic visibility model or requirement count.

## User path and proof

The existing authenticated source canvas remains the painting surface. The user
reads the current person's source, paints explicit visible skin and confirms the
existing ownership/occlusion consents. In a shared project owner, this creates a
support-only proposal rather than calling the old immediate review publication.
The original request binds the exact region and reference proof. The new
`face_decoration_support_alias_*` actions cannot borrow scalar alias receipts.

A candidate graph and immutable visibility bank are staged privately. Each
available affected document is rendered twice through its full existing edit
chain, retaining that document's crop, colour and repair. Coverage includes the
selected face plus every enabled active before/candidate face. Only one face's
visibility pointer can differ; recipes, other support, recovery and associations
remain unchanged. The initiating face's reference cannot prove another person's
visibility. Every actual image page must be served, decoded and explicitly
acknowledged before confirmation.

Initial absent support is allowed only when the before decoration is neutral.
Active invalid/missing support cannot be rescued by inventing its before render.
Repeated identical canonical support creates no transaction or revision. Moving
a pointer to an already retained record is a real graph change even when the
append-only bank hash remains unchanged.

## Publication and history

A distinct typed authority and `face_decoration_support_alias_review` marker
bind exact graph pointers, selected immutable records, source identities,
complete member closure, own-state dependencies and ordered image ACK. No
ordinary scalar ledger exception is used. All member revisions, the shared
pointer and staged bank publish atomically under the existing history owner.

The bank is append-only: selected before/after records survive undo for durable
history. Undo/redo restores the pointer and verifies referenced dependencies; it
does not erase unrelated history bytes or pretend to restore a historical whole
bank. Publication cannot replace immutable records or append unrelated assets.
Mixed support/scalar/recovery markers are rejected rather than misclassified.

Definite no-write and verified compensation are distinct terminal failures.
Unknown or late publication errors retain the original request, known ledger
identity and global write fence. The UI queries rather than blindly resending.
Only a verified new workspace can retire an old request; ordinary navigation or
closing the editor cannot. Reopen is not a claim the old request never wrote.

## Preserved limits

- Complete live shared-owner sets only, 2–16 members and at most 64 covered
  selected/active faces; oversized coverage refuses before rendering, never truncates. Dormant/unavailable or
  hidden source-bearing state without complete proof remains a refusal.
- Independent virtual-copy/import owners are not merged by matching pixels.
- Mixed-preset aliases now use PRESET-ALIAS-CONTRACT.md; alias effect-recovery painting remains a deferred gap.
- Source review and output comparison are bounded RGB8 display evidence, not
  native-resolution or high-bit photographic acceptance. Original/derived
  opaque SDR and the existing PNG16 master contracts remain unchanged.
- Manual visibility, moderately frontal anatomy, numeric work/memory budgets
  and lack of automatic occlusion/instance segmentation remain explicit.

See SUPPORT-ALIAS-RESEARCH.md and SUPPORT-ALIAS-ACCEPTANCE-UNRUN.md. Fixtures are
source artifacts only; compilation, tests, UI, undo/reopen, quality and performance
have not been executed in this development environment.
