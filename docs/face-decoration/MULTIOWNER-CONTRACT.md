# Face decoration: persistent cohorts and scalar aliases

Source-connected only; runtime, compilation and image-quality acceptance UNRUN.
Requirement `LNX-REF-PC-32471-C-dd14134407` remains one manually reviewed

## Persistent person cohorts

Create, patch and unlink use the existing atomic people-association planner.
Selected decoration or retained active decoration requires the initiating source
and every affected member's complete mixed before/after render, not a standalone
decoration overlay. Each image retains its document's crop, colour and repair.
Each target resolves its own FaceRef, current source analysis, reviewed visibility
and recovery. Only scalar pattern/strength inheritance travels; support pixels,
paint geometry and recovery vectors never travel between people or images.

Source-first coverage includes all enabled active faces before and after the
proposal. Ordered exact image ACKs bind document revision, both PNG hashes and
coverage hash. Companion portrait, eye-bag or collarbone reviews retain their own
ACKs and must refer to the same complete candidate. Empty module scope is valid
for a complete reviewed unlink, not permission to skip affected members.

The existing scoped ledger owns publication, rollback, undo and redo. Cohort
markers survive project persistence and reopened history. Unknown writes are
queried, not retried as fresh edits. Unsupported dedicated module combinations
are refused as a whole, never silently omitted.

## Shared-source direct scalar editing

A project-owned face shared by 2–16 available documents requires all affected
documents, not just the visible one. The editor prepares a pattern/strength draft,
reads immutable image pages and requires each pair's explicit acknowledgment.
Each member has its own original provenance, crop, colour and repair proof even
when the effective derived asset is identical. Existing reviewed visibility
support is immutable throughout this transaction.

Private authority permits only one or two pattern/strength leaf changes on one
face and an exact graph/member closure. It cannot alter support, associations,
other portrait effects or document-local state. Confirmation consumes the exact
frozen proposal and records a protected all-member history batch. Reopened undo
and redo require the same complete membership and dependencies. Exact recipe
no-op is an explicit read refusal without a transaction or invented history.

The review SHA is an opaque engine identity because recipes include normalized
floating values. UI independently verifies image and coverage hashes; the
history SHA covers the integer/string-only ACK. No cross-language float JSON
identity is assumed. Native and UI correlate the original request separately.

## Boundaries

- Scalar alias authority still refuses support painting. Initial/revised visibility
  now has a separate [exact support-bank transaction](SUPPORT-ALIAS-CONTRACT.md).
  Alias effect-recovery painting remains guarded; mixed-preset aliases use PRESET-ALIAS-CONTRACT.md.
- Dormant, unavailable or hidden source-bearing members without complete proof
  remain refusals. Independent virtual-copy owners are not silently joined.
- Existing 16-member cap, bounded paged image cache and full-source work budgets
  remain. Display evidence is reduced RGB8, not native-resolution acceptance or
  a claim that PNG16 source precision was discarded.
- Manual visible-skin support, moderately frontal landmarks and opaque SDR
  limitations remain. No automatic occlusion/instance segmentation, AI anatomy,
  original-freckle removal or proprietary vendor material parity is claimed.
