## One-photo preset

The decoration preset admission adapter permits selected versioned scalars only,
including a narrow supported opaque-SDR derived source. Source identity,
precompute and repair stacks remain bound to the actual immutable composite.
It does not alter the general derived-source operation allowlist.

The existing detached portrait planner stages the complete selected preset and
retained state. `portrait_review_render` makes the real before and candidate
images through the full-source render/export graph, including non-portrait
colour, geometry, crop and repair. No separate decoration overlay is substituted.
The same frozen plan is executed under the original preset transaction owner.
Post-render snapshot verification and exact-state rollback preserve that owner.

Review is required for selected decoration, including neutral, and for retained
active decoration when the preset selects other operations. The required flag
comes from current authenticated graph capture, not an imported preset's claim.
Coverage binds the selected face and every active before/candidate face, exact
FaceRefs, target visibility asset hashes and resolved candidate recipe hashes.
An active before image requires real valid before support even for a reset.

The existing single-photo planner still requires one explicit unambiguous
enabled face. Multiple-face detection does not claim arbitrary multi-face preset
mapping. Conflicting dedicated portrait review owners, unsupported mixed modules
and shared-source alias changes refuse as a whole rather than dropping effects.

## Ordinary face-map batch

The existing frozen people-transfer planner retains each target's non-portrait
state. It changes only explicitly selected portrait scalar leaves with confirmed
target FaceRefs. Each target uses its own source, landmarks, reviewed visibility
and recovery. Donor masks, repair, coordinates, source bytes and analysis are not
portable. Shared-owner target changes are aggregated before image generation,
so each photograph shows the actual final owner graph, not an isolated update.

The union of mapped faces and all active before/candidate decoration faces is
covered. Thus an unmapped retained face is not silently omitted from complete
render dependencies. Selected decoration or active retained decoration triggers
the engine-owned review flag. All eligible ordinary targets require real images
and exact acknowledgments; missing targets cannot be called reviewed.

This is an explicit face-map scalar batch, not arbitrary whole-state copying.
Target crop, colour and repair are retained and included in the comparison.
Whole-state/non-people batch with active decoration, persistent associations and
source-identical aliases without complete affected-set review remain guarded.
No hidden sibling is authorized by a single target's confirmation.

## Images, acknowledgment and uncertainty

Preset and batch image reads have separate exact request envelopes and scoped
tokens. Before/after compact proofs bind immutable source, document/revision,
whole render state/graph, coverage, full output dimensions and PNG SHA-256.
Full-source render occurs before display reduction to at most 1024 pixels on
the longest edge. PNG evidence is RGB8, not quantized master output or a mask.

Images are fetched lazily from bounded session storage, rather than embedding
all batch PNGs into one receipt. Existing per-image 4 MiB and raw-store 128 MiB
bounds remain; no silent reduction substitutes for unavailable evidence. The
ordinary batch limit remains sixteen targets. Memory/performance is unmeasured.
The UI verifies hash, decoded size and coverage, displays both images, and asks
for an explicit acknowledgment. Read success alone is not agreement to edit.

Before mutation, the exact current owner, source, repair, support, graph and
candidate snapshots must still match. The original transaction/ledger owns
commit, history, rollback and project restoration. Display PNGs are session
evidence, not persisted history frames. Unknown writes remain query-only and
cannot be relabelled canceled or safely retried. Expired evidence requires a
fresh preflight and fresh image acknowledgment.
