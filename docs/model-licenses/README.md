# 模型与数据许可台账

项目定位：**纯开源、非商业自由软件**（Free & Open Source, Non-Commercial），
无商业变现与闭源销售计划。本目录是这套定位唯一的事实落点 —— 定位不写进文件
就只是聊天里的一句话。

## 为什么代码许可管不到模型

`LICENSE`（GPL-3.0-or-later）只授予**本仓库自研代码**的权利。模型权重是第三方
独立许可的资产：Apache-2.0 的权重带它自己的 NOTICE 义务，非商业权重带它的用途
限制。把它们打进同一个 deb，等于同时分发五种许可的物。所以：

- 每个要进包的权重必须在 `models.json` 里有一条**填完**的台账；
- 台账没填完的模型，功能可以开发，**不得进任何对外发行物**；
- 硬门禁写在 `models.json → policy.gate`：`sha256=null` 或 `evidence=未核`
  的条目不得进 `bundled` 档。

## 三档分发（打包策略）

| 档 | 含义 | 判据 |
|---|---|---|
| `bundled` | 进 deb，装机零操作 | 体积可控（核心精修所需的 478 点模型束在这一档）+ 许可一手可证 |
| `fetched` | 一次性清单确认后自动拉取，之后静默更新（带哈希校验） | 几百 MB 的重型生成模型；不让主包胀破 1 GB |
| `blocked` | 功能显式禁用并说明缺什么 | 许可或训练数据权利核不清，且无法用上面两档安全承载 |

**`fetched` 不是"静默拉取"**：首次点击该能力时弹一张卡片，列「模型名 · 体积 ·
上游地址与 revision · 许可名称 · sha256」+ 一个「全部启用」。用户仍然不需要手动
挂载任何东西（这条诉求完整满足），差别只有一次点击。

不做纯静默下载的理由**不是**商业侵权风险，是另外两件：
1. 我们对外承诺不外传照片与特征，那入站的网络动作也得同等透明；
2. Apache-2.0 / CC-BY 类许可要求**许可文本与署名随副本分发**。静默下载会让用户
   机器上出现他从未见过的许可文本，署名义务直接落空。

## 证据等级（每条台账必须标，不许含糊）

- `一手` —— 在本环境直接读到权利人发布的许可原文或模型卡页面。
- `二手` —— 官方链接存在但本环境读不到（例如 HuggingFace 返回 401），结论取自
  多方一致引用。**必须在 `evidence_note` 写清缺口与补核动作。**
- `未核` —— 只有仓库自述或推测。等同 `blocked`。

## 测试靶（datasets 段）

非商业定位确实消掉了"商业采购授权"这道障碍：FFHQ / CelebA-HQ / CelebAMask-HQ
可以直接用作**本地评测靶**。但三条硬规则不因非商业而消失：

1. **靶集不进 git、不进 deb、不外发图像。** 这些数据集的条款只覆盖图片使用，
   不覆盖画面中真人的人格权（肖像权与数据许可是两回事，与商业无关）。
2. **FFHQ 是 BY-NC-`SA`** —— SA 会传染：以它为基的衍生模型再分发须带相同许可。
3. **官方禁止用于人脸识别/身份识别** —— 所以本项目不得实现"跨照片认人/以图搜人"，
   即使技术上做得到。这条同样适用于 MediaPipe 的模型卡限制。

由此带来一个对我们自己交付习惯的约束：**对外效果证据不再使用真实靶图**。
CI 与文档里的对比图一律用程序化生成人像（`packaging/make-test-portrait.py`，
SEED=20261016，哈希已随仓库），真实靶上只出**数值读数**。

## 加一个模型要走完的步骤

1. 在 `models.json` 新增条目，逐项填：上游、revision、artifact URL、体积、
   sha256、代码许可、权重许可、训练数据许可、证据等级、署名文本、义务清单。
2. 把许可原文/模型卡存档进 `archive/<id>/`（**这一步没做完就不算填完**）。
3. 在仓库根 `NOTICE` 补一段署名。
4. 定档（bundled / fetched / blocked），`bundled` 必须过 `policy.gate`。
5. 下载脚本校验 sha256；哈希不符要报错，不许"下下来能用就行"。
