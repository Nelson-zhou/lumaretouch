## Narrow route, unchanged generic guards

`collarbone_derived_preset` is used only by the current-photo preset controller
and its review owner. It admits the explicitly selected version/amount and the
already permitted derived scalar modules. It does not add collarbone to
`scope.DERIVED_PARAMETER_OPS` or remove `collarbone_scope.install`'s generic
refusal. Generic batch, generic history restoration and legacy replay do not
gain permission. Derived save requires an explicit module selection and writes
only portable parameters, never target marks, source assets, masks or FaceRefs.

Both prepare and claim reconstruct exactly the same candidate. Actual canonical
RGBA float source content is validated, and the existing opaque SDR admission
checks pixels without flattening alpha or clipping HDR. Effective content ID and
extent must match the target owner's proof and FaceRef. Original file hash stays
separate provenance. Existing inference-cache binding and both active/redo
repair stacks are validated; missing inference cache is not itself proof of a
bad target because independently retained analysis may exist. The actual full
renderer still validates all needed analysis and support.

The exact read-only planner receives an internal reviewed-collarbone option
only from `collarbone_preset_review.prepare`. It re-captures the live target and
checks independently reviewed body ownership, visible clavicle consent, current
analysis and native readiness. Generic replay keeps the old refusal. Candidate
construction modifies only collarbone scalar intent/request marker plus selected
already-supported scalar modules; all unrelated runtime buffers and state stay
target-owned. It cannot change the canonical base, repair stack or support.

The preceding complete-preset contract remains mandatory: actual before/after
full float source rendering, source/repair/graph/context fingerprints, logical
owner versus load identity, actual paged PNGs and single exact acknowledgment,
frozen graph publication, full snapshot post-check and guarded original-state
restoration under the existing history/unknown receipt owner. Derived sessions
now admit the exact bounded preset image-read action, not arbitrary requests or
an apply exemption. Native/UI proofs distinguish derived pixels from original
provenance. No original image analysis is rebound under a new hash.

## Limits retained

- Only mixtures that the established derived scalar validator and full portrait
  planner genuinely admit are available. Other portrait modules, legacy active
  recipes requiring their own unported install paths, source-bound mixed modules
  or support migrations still refuse; no selected effect is silently discarded.
- Active correction requires the actual target's separate body/clavicle review,
  source-owned semantic support, repair evidence and Rust kernel. Zero resets
  retain owner/source/ref checks; an unrenderable active before state cannot be
  misrepresented as a valid image pair.
- This does not implement AI 3D anatomy detection, automatic classification,
  multi-person instance segmentation or generated clavicles.
- Transparency/HDR retouch, stale-support recovery, pixel-scale display review,
  runtime save/load/history/export equivalence, numerical quality, performance
  and usability remain explicitly unverified or unsupported as previously stated.
- All new fixture declarations are UNRUN. Only static syntax/data/hash/source
  checks were performed; no application/model/test/build execution occurred.
