## Exact planning, not a collarbone-only overlay

`people_scope.plan_preset` extracts the existing complete portrait staging
logic. Preview does not replay state, publish a graph or create a history owner.
It requires an already active document owner and stages the same target,
changed leaves, coexistence validation and strict-local requirements as replay.
Legacy replay also uses that planner; old recipes and the numeric core remain
unchanged. The session-only plan keeps detached recipe containers and graph
values while retaining opaque large buffers under fingerprints, not duplicating
raw source arrays into project/history JSON.

`collarbone_preset_review` renders the real before state/before graph and final
candidate state/candidate graph through `full_candidate_render`, including
selected portrait effects, retained unselected intent, non-portrait edits,
repair and crop. A source-side collarbone scalar overlay cannot stand in for
this pair. Existing module-specific reviews and acknowledgments still apply.
Selected collarbone zero resets also require review. Unsupported mixed modules
refuse as a whole, never disappear from the preset.

The proof binds preset and prepared module content, logical document, current
load session, document revision/epoch, selected FaceRef, independently retained
support and immutable source. Python canonical hashes are frozen server proofs;
clients do not recompute numeric JSON using incompatible float spellings.
Coverage hashes use the existing integer/string-only canonical contract.

## Paged display and acknowledgment

`preset/collarbone_visual` has its own preset ID, token, load identity, revision,
side and PNG hash. It cannot use a batch or cohort token. The storage primitive
is reused, but the preset cache is separate. Before and after reads check the
exact row object, path, logical owner, load and current revision; immutable
bytes are checked against the frozen compact proof. The controller owns the
response envelope. Native and UI validate correlation, PNG/hash/size and proof.
Only both loaded images and an explicit single `collarbone_preset_ack` authorize
application. Metadata confirmation is not photographic review.

There are at most eight session plans, each expiring after 30 minutes. Existing
storage bounds are 128 MiB raw PNG bytes, 256 entries, 4 MiB per image, with no
silent quality reduction on budget refusal. Each displayed pair is reduced to
at most 1024 pixels on its longer edge, RGB8 display only. Source, export and
history are not quantized by this transport. This is not a 100% precision review.
Actual memory, latency and ordinary-photo usability have not been measured.

## Publication, restoration and uncertainty

Before token claim, current source, complete state/graph/context, coverage and
both stored images must still match. The existing controller advances its
document revision and owns the single preset transaction/history boundary.
Application checks the caller's exact prepared candidate fingerprint, then
executes the frozen normalized planner state and exact graph, not a newly
calculated partial overlay. Post-apply compares the actual export snapshot,
resolved graph and support context against the reviewed candidate. Only the
top-level graph commit revision is normalized; association intent, per-face
revision, source evidence and all recipe content stay exact.

If replay fails after installing candidate non-people state and restoring its
own graph, rollback admits that exact frozen candidate-state/before-graph hybrid,
as well as complete before or candidate state, under the captured owner fence.
It restores the actual frozen original state and graph, not reverse scalar
diffs. A foreign edit, stale source/support, another owner or an unrecognized
partial state refuses overwrite and remains explicit recovery/unknown outcome.
Retained analysis migration is not treated as harmless cache metadata. Unknown
apply receipts are query-only; image requests do not bypass mutation fences.
