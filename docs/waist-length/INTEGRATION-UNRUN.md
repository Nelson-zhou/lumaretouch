# Integration map and pending acceptance

All entries below describe authored source routes or future acceptance work.
They are **not executed tests**. The precise frozen file list and hashes are
recorded separately in `FREEZE.json` once all owners stop editing.

## Authored direct route

1. `toolRouting/coverage.ts`, `legShape/BodyShapeTools.tsx` and the waist workspace
   expose the exact waist-length leaf separately from torso length and waist width.
2. The real source preview binds the current immutable source and dimensions.
   Four waist points are explicitly marked, not supplied from Pose33. Complete
   head/hair, arm boxes, transition boundaries and operation-specific confirmations
   are reviewed. Current own-face evidence is attached by the canonical host.
3. `waist_length_api.rs` and existing native dispatch/receipt fences validate the
   versioned command. `BodyTransport` routes to `WaistLengthHostAdapter` under the
   existing canonical body lock. No second history or mutation owner is added.
4. `waist_length_state/runtime/field/native` validate the source-owned support and
   actual pose/face dependencies, then call the separate installed Rust ABI.
5. `body_pose_operations`, `body_pose_geometry` order8 and `body_pose_render`
   register the genuine field in the existing single body/face inverse sampler.
   Neutral state retains older order identities; old algorithms are not replaced.
6. The shared body bank, project snapshots, sparse history, autosave/recovery,
   original/derived source fences and export reconstruction retain the same
   immutable support and exact source binding. Native uncertain outcomes remain
   query-only. A lost notification does not authorize replay or guessed rollback.
7. Source availability is separate from kernel readiness. Active edits refuse a
   missing/incompatible native extension, while neutral reset, disable and status
   reconciliation remain possible.

## Acceptance still required outside this source-only environment

- Compile Rust and native UI bindings; run Python/TS/Rust fixtures without mocks
  for the actual numeric ABI. Source parsing is not compiler acceptance.
- Confirm four pointer-marked waist points, source resizing, stale preview/image
  decode, missing marker, clear/reset, all confirmations and native readiness UX.
- Exercise actual original RGB8/RGB16 and derived float images through preview,
  100% inspection, full export, project reopen, history, source relocation and
  uncertain-publication readback. Do not substitute a routing double for this.
- Validate positive/negative marked endpoint displacement, fixed lower waist and
  hips, whole upper-trunk/head transport, crossed-arm refusal/disclosure, finite
  inverse residuals and composite Jacobian bounds on actual compiled kernels.
- Photographically review diverse supported subjects, contours, garments,
  backgrounds and source resolutions. Marked anatomy may be inaccurate; no
  naturalness, speed or memory-peak claim follows from a formula or fixture.
- Preserve alpha/HDR refusals until the whole pipeline genuinely supports them.

## Next bounded user workflow

Dedicated waist scalar preset/batch transfer remains **not registered**. A future
route must transfer only version and amount, resolve each target's own explicit
four-marker support, BodyRef, current face association and immutable source,
render real before/after, and collect a target-bound acknowledgment through the
existing frozen ledger. It must not copy donor markers, pose, masks, identity or
support assets. Mixed scopes and whole-bank copies must not bypass this review.
Existing torso review infrastructure may inform this implementation, but cannot
be treated as having already connected waist controls.
