# Editable canvas guides · missing core M16

Status: implementation candidate; ALL runtime, browser, native, project round-trip and visual cases below are UNRUN. No test/build/compiler/typecheck/inference/download/install was performed in this implementation pass. Static review does not establish acceptance.

## Evidence and deliberate design

Handbook “参考线” and AI development package 功能需求验收映射.json, exact five LNX-REF-PC-165385-C IDs in mapping.json. Official public guide https://www.pixcakeai.com/guide/165385 read 2026-10-23: create multiple horizontal/vertical guides; drag; manual hide/show; automatic hiding and no creation in comparison/reference, brushes/custom masks, category correction and crop; immovable in manual liquify/repair; context-delete one/all. No persistence/undo/coordinate-default behavior is publicly specified. This implementation independently chooses source-normalized geometry, document-owned project view metadata, a maximum of 128 lines, 64 view-history steps, independent view undo/redo, and insertion at the current crop center. These are not claims about the reference product.

Guides are separate SVG/DOM decoration. They are not the crop grid, do not call rendering, do not enter the recipe, do not produce image edits, and must never appear in exported pixels. Source crop integer rounding and clockwise rotation are handled explicitly before display zoom/pan. A new guide starts at the source-coordinate center of the current crop; a cropped-out guide is retained (not silently moved/deleted), and the coordinate list supports exact movement/deletion even when offscreen. Manual show/hide survives automatic hide. Real Viewer admitted frame identity gates the overlay. Virtual copies use canonical document-row identity, not filename/source path. Source file relocation must retain the same document view state.

## Required Qoder verification (all UNRUN)

1. Create at least three horizontal and three vertical lines using menu and R/Ctrl+R. Existing guides are retained. IDs remain unique; 128-line limit reports a clear message and never discards old lines.
2. Drag independently with mouse, touch and pen; pointer capture remains during out-of-bounds movement. Resize, zoom, pan, switch image/project, lose focus, cancel pointer capture, or press Esc mid-drag: uncommitted draft is cancelled, no accidental pixel brush/pan begins. Shift+arrow projects 10 CSS pixels onto the guide movement normal; arrow projects 1 CSS pixel (zoom-aware). Keyboard Delete removes only focused guide.
3. Right click a line and delete one/all. Keyboard context menu is reachable. Manual Shift+R/menu hides all and restores without changing coordinates. Menu action and shortcut do not fire while typing, editing selects, or in blocked views.
4. Enter split, swipe, original-hold, reference library, brush/recovery, custom mask, correction panel, crop, full-resolution inspection and color pickers. Guides automatically hide and creation/edit shortcuts are blocked. Exit each: prior manual visibility survives, no new pixel edits/history entries.

Position controls and guide undo/redo stay locked; brushes continue working. Its before-comparison hides guides. Source-patch and clone-stamp viewers retain guides in read-only form. Frozen capture overlays and guides use the same crop/display domain, no tool receives a guide drag.
