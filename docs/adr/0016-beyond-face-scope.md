# ADR-0016：身体美型 / 妆容头发 / 手脚精修定档为"本版本显式不支持"，005/006 给出路线

日期：2026-10-19　状态：已采纳（1.8.0 之后生效）
关联：《开发验收用例》PORTRAIT-008（全身美型）、PORTRAIT-010（妆容头发）、
PORTRAIT-011（手脚精修）、PORTRAIT-005（跨图候选人工确认）、PORTRAIT-006（人工纠正优先）；
DoD §2（只用 Apache 2.0 的 MediaPipe FaceMesh + 几何网格变形，严禁伪装 AI 与假效果）、
DoD §3（未接通功能显式禁用并说明原因，绝不留无响应控件）、
ADR-0001（许可与权重分层）、ADR-0002（mediapipe 作为随包运行时）、
ADR-0009（P1 覆盖边界那张账，本档把它剩下的三条定档）、ADR-0007（批量任务台账与边界）

## 1. 起因：验收报告上那行 `uncovered` 不是一个决定

1.8.0 定版后 `docs/acceptance/case-map.json` 的账是 **P0 57/57、P1 12/17、P2 0/6**。
P1 剩下 5 条里，PORTRAIT-008/010/011 三条从 M8 起就一直挂在"未覆盖"那一列——
它既不是"做了一半"也不是"待测"，而是**没人替它做过决定**。

这在本仓是不够的。DoD §3 要求"未接通功能显式禁用并说明原因"，而当前这三组的形态是
**面板上没有这一栏**：控件列表由引擎 `ready` 报出的能力名单驱动（`deform_kinds` /
`enhance_subs` / `mask_channels` / `matting_backends` …），名单里没有就不画——这满足了
"绝不留无响应控件"，但"没有控件"本身不等于"这个产品对外说明了它不做什么"。
所以需要一个显式档位，写进 ADR 并落进验收叙述，而不是让 `uncovered` 那一行替它说话。

## 2. 决定

### 2.1 这三组在 1.x 里显式不支持，理由是关键点集与许可，不是排期

| 用例 | 冻结件的 then | 为什么不做（而不是"还没做"） |
|---|---|---|
| PORTRAIT-008 全身美型 | 未选人物无非预期位移、变形无断裂、中性值恢复 | 形变层的控制点全部取自 FaceMesh 478 点的解剖语义（眼睑环、轮廓链、唇链、下巴尖）。躯干/四肢在这个点集里**一个点都没有**；要做就得引入 MediaPipe Pose（33 点）或 Body 分割，那是新的权重、新的许可声明行、新的运行时失败面（ADR-0001/0002 的分层要重走一遍）。而 Pose 的 33 点对"腰细一点"这种连续美型的支撑密度远低于 FaceMesh 对脸的支撑密度——用它做出来的瘦脸式滑块在真机上就是"拖一块网格"，观感与"无断裂"那条判据都撑不住。 |
| PORTRAIT-010 妆容头发 | 效果限制在目标内、**保留发丝边界**、子模块独立中性测试 | "限制在目标内 + 保留发丝边界"要求的是**发丝级的区域分割**。FaceMesh 没有发际点，任何用椭圆/多边形近似出来的"头发区域"都会在真照片上切进额头或飘出轮廓——那正是 DoD 严禁的那类假效果（看上去有该功能，判据一量就漏）。与其交一份注定不过的判据，不如不交。 |
| PORTRAIT-011 手脚精修 | 无指头数目/形状非预期变化；识别失败给出明确未处理状态 | 手是 21×2 点集 + 自遮挡问题，且这一条的判据核心是"识别失败要**明确**报未处理"。在只随包 FaceMesh 的版本里，这一条永远走"失败分支"——把整栏做成一个只会上报"我不支持"的功能，就是留了一个无响应控件的华丽版本。 |

三条同一个根子：**本版本的解剖学基础是 478 点面部网格**（DoD §2 就是这么定的技术路线）。
超出面部的那部分不在这一版的能力面里。

### 2.2 产品面怎么表达这个"不支持"

1. 面板按引擎报的能力名单画控件（这条已经是硬约束，`enhance_subs`/`deform_kinds` 两轮的
   双出处教训都在里面）。名单里没有的组**不出现空分组、不出现灰滑块**。
2. `ready_caps` 里新增一格**显式的不支持名单**（下一版落地时做）：值形如
   `unsupported: ["body", "makeup_hair", "hands_feet"]`，宿主可以把它显示成一句
   "本版本不做身体/妆容头发/手脚（面部关键点之外没有依据）"，而不是让用户自己找。
3. 验收叙述里这三条的状态从 `uncovered` 改成 `not_supported(有理由)`：由 `case-map.json`
   的人工 `note` 格承担（它不是派生物，正是给人签字用的那一格）。

### 2.3 PORTRAIT-006 与 005：这两条是要做的，路线写死

- **PORTRAIT-006（人工纠正优先，排在 1.9.0）**：把它实现成"人脸名单的人工状态"——
  `disabled`（用户关掉的那一只误检）与 `manual`（用户手加的那一张区域）随工程持久化，
  重检测之后：人工状态保留、变化可预览（列出这次检测要新增/移除谁），
  **不静默恢复已禁用的误检**。判据直接来自冻结件那两句，而且可逐字节化：
  被禁用那一只对应的形变/眼牙层在重检测后的那一帧上不得重新出现。
  这一条与 ADR-0011 的 `face_index` 选定是同一个人（"在改谁"），共用那份 `_face_state()`
  组装点，不另起第二份状态出处。
- **PORTRAIT-005（跨图候选人工确认）**：批量同步的 preflight / commit / undo / 冲突报告
  已经在 BATCH-004 落地（ADR-0007），缺的是"跨图同一人的候选从哪来"。按脸盒归一化尺寸 +
  关键点几何距离出候选，落到 006 之后做；判据是那两句：未确认/冲突候选**不被自动修改**、
  同步对象清单**可审计**（清单就是任务台账那格，不另造一份账）。

## 3. 后果与退出条件

- 这三条不再以 `uncovered` 混在报告里；`装机自证` 的未闭合那一节写的是"有理由的不支持"。
- 退出条件（什么时候把它们重新变成"要做"）：出现一份许可与体积都能进 THIRD_PARTY_NOTICES
  的**身体/手关键点**或**发丝级分割**运行时，并且能在冻结件那两句判据下交出可复算的实测表
  （不是观感评审）。到那时是本档的 supersede，不是在这里加滑块。
- 明确不做的事：不给"身体瘦脸"这种由面部关键点外推的近似（DoD §2 严禁假效果），
  不给只有失败分支的栏目（DoD §3 严禁无响应控件）。
