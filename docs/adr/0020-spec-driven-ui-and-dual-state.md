# ADR-0020：规格数据驱动的工作台与「已接通 / P1 置灰」双态契约

- 状态：已采纳（1.12.0）
- 日期：2026-10-19
- 关联：ADR-0003（容差 0 / 中性逐字节恒等）、ADR-0016（能力边界显式化）、
  `交给AI的开发提示词.md` 第 3/4 条

## 背景

产品手册的全景是 39 个功能族、805 项子控件、32 个创意工具与五大工作区。引擎侧
真正落地的是 15+ 项能力（曝光/白平衡、影调、磨皮、形变、眼牙、局部调色、LUT、
裁剪旋转、换底、消除笔、修容、工程/预设/批量/历史）。两者之间有一个必须说清的
差额：**没有接通的算法不能从界面上消失**——用户看到的应当是一台完整的工作台，
而不是按引擎能力裁剪过的阉割版。

同时，1.11 及以前的前端是手写控件清单：每接一层就手抄一段 JSX。手抄清单有三个
已发生的后果：①新能力加进去了、对照组忘了改；②为了测试平账删掉没接通的控件
（直接违背开发提示词第 3 条）；③规格 ID 与界面位置只能靠人记。

## 决定

### 1. 规格 JSON 是界面清单的唯一出处

四份规格（精修 39 族/805 项、工作流 34 条、创意工具 32 件、P0 注册表 36 条）以
**逐字节副本**放进 `ui/src/spec/`，并在 `manifest.json` 里记 sha256、字节数与条数。
`engine/tests/test_ui_dnd.py` 在资料包在场时逐字节比对，不在场时用 manifest 自证。
前端用 `buildTree()` 按 `path` 的 `/` 分层递归渲染；本文件不判断“这一族要不要画”。

### 2. 双态契约：已接通画真控件，未接通完整陈列 + 置灰 + 规格 ID

`WIRED` 表只做一件事：把「功能族 ID|规格 path」指到一条真实命令。表里没有的一律
走 `P1Row`：保留名称与层级，`disabled`，Tooltip 原文
`P1 规划中 · [PC-xxxxx]：当前版本未接通后端算法`。面板头把 `data-spec-total=39`
与 `data-spec-controls=805` 画在 DOM 上，发布门禁用这两个数对账，**不靠人眼数**。

### 3. 八色 HSL 是一个真图层，不是前端滤镜

需求里的「8 色 HSL」在规格里只有 `HSL/色相 / 饱和度 / 明亮度 / 吸管` 四格，没有
色段名单。实现口径：

- 八个色相中心 0/30/60/120/180/240/280/320°，升余弦窗半宽 45°；权重**不归一化**
  （归一化会把“红 -100 饱和度”摊给橙色，用户拉到头也去不干净），交界处两段各出
  一半，最终值夹回量程；
- 24 个数（8 段 × 色相/饱和度/明亮度）作为一个 `_hsl` 文档字段，进撤销/工程/批量；
- 链上位置：曝光之后、LUT 之前（它读的是曝光后的颜色，而表是输出变换）；
- 无彩像素（HSV 饱和度 < 0.06）不参与任何色段：给灰色像素“红原色明亮度”加值，
  用户从画面上找不到对应关系；
- 中性（24 个 0）由 `apply_hsl` 一步短路，逐字节恒等（ADR-0003）。
- IPC 只有一个 `hsl` 命令（`set` 部分提交 / `clear`），UI 的色段 chips 是**界面
  选择**，三个滑杆仍是规格里的真叶子，不另造一套状态。

### 4. 100% 是随窗口重算的档位，不是一个算过一次的数

`zoom` 存的是相对 Fit 的倍率，1:1 的算法是 `zoom = 1/(dpr*fitScale)`。4K 验收时
量到过：在 1600×1000 的窗口里点 100%，把窗口拉到 3840 宽之后，徽标写成 **119%**
——图已经不是 1 像素对 1 屏幕像素了，而按钮还亮着。修法是把它提升成 `oneToOne`
档位：`fitScale` 一变就重算；滚轮/捏合改倍率即退出这一档。守卫：
`test_ui_dnd.py::test_one_to_one_zoom_is_recomputed_when_the_window_resizes`。

### 5. 刷新文档状态等 `doc_rev`，不等 `source`

宿主的 `doc_report` 会一直留着上一条 `history_state`。4K 全幅那一轮，第二次
刷新只等 `source == "history_state"`，于是当场读到**裁剪前**的那一份，报告写成
“历史已经 5 步、crop 还是恒等”。改成先记下 `doc_rev`、再要求它真的往前走；
同时把引擎的 `last_error` 原样带进报告（crop 被整条拒时命令不抛异常，只写
`last_error`）。守卫：`test_ui_dnd.py::test_doc_report_is_refreshed_by_revision_
not_by_source`。m5 第 12 臂也改成全幅 1024×1280 跑（原来用 400×504 的代理预算，
这条竞态在小图上撞不出来）。

### 6. 宿主桥的参数名是 camelCase（本轮的静默丢参事故）

Tauri 把 Rust 的 `temperature_shift` 映射成 JS 的 `temperatureShift`；**不认识的键
被当作“没给”**。1.12 之前的 native.ts 在 exposure/crop/preset/batch/export 里混用
snake_case，后果是色温、色调、参考白、四项影调、旋转、预设作用域、批量策略、
16-bit/ICC/GPS/冲突策略全部“界面选了而引擎没收到”，而所有回执都正常。

决定：JS 侧一律 camelCase；`test_ui_dnd.py` 加一条名字守卫；新增 M0_SPEC 真窗口臂，
用**引擎回报的 doc_state**而不是命令回执来判“参数真的到了”。

## 证据

- `M0_SPEC`（装机 deb、Xephyr 真窗口、`portrait-1024x1280` 夹具）：
  `bads=[]`；曝光/色温/色调/对比度/高光/阴影/饱和度 7 个数原样到达；HSL 第 2 段
  `[18,35,12]`；磨皮 0.62；瘦脸 0.3；裁剪 `[0.05,0.05,0.95,0.95]` + 90°；
  `crop_out=[454,360]`、`out_full=[1152,922]`；100% 读数、`pixelated=0`、
  `families=39`、`specControls=805`、真滑块 27 个。
- 截图：`docs/acceptance/UI-1.12.0-精修-100%与规格面板.png`、
  `docs/acceptance/UI-1.12.0-色彩调节与八色HSL.png`。

## 后果与代价

- 805 项全部进 DOM（折叠态），首帧多约 1.5 万节点；可接受，换来“0 规格遗漏”的
  可验证性。若将来需要更快的首屏，应做虚拟滚动，**不是删控件**。
- P1 置灰不是“没有成本”的：每个灰色控件都必须在 Tooltip 里说出规格 ID；将来接通
  一条能力时要同时删 WIRED 之外的那一行——两步都在同一个文件里，可审。
- 八色 HSL 是原创扩展，不写进 P0 注册表；它的量程由引擎随事件报，前端不抄。
