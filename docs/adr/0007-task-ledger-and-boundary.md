# ADR-0007：批量任务台账——转移表只有一份，安全点只在条目之间

日期：2026-10-18
状态：已采纳
关联：《Linux开源人像修图产品指导手册》LNX-P0-TASK；《开发验收用例》TASK-001/002/003/004/006/007/008/009、CORE-008

## 背景

导出是批量动作：一次几十张、每张几秒。手册要求它可暂停、可继续、可取消、可重试，
并且进程中断后重开不能偷偷重跑。此前引擎里只有一条 `self._export` 线程 + 一组参数
元组，没有任何"这一批到哪了"的账——UI 只能显示"导出中"，而"暂停"无处落脚。

## 决策

1. **状态与转移只在 `engine/src/lumaretouch_engine/tasks.py` 里。**
   十个状态、一张 `LEGAL` 转移表、`history` 逐步记账（截 64 步）。不在表里就是拒，
   不静默"差不多就当过了"。命令面（`cmd_task`）与 worker（`_export_loop`）读同一张表，
   不允许出现"worker 以为能暂停、命令面以为不能"。

2. **控制位与状态分开。** server 侧 `_TaskControl` 只有三个 `Event`（pause/resume/cancel），
   它们是"请求"，不是状态。请求位不是状态这件事一旦含糊，UI 上就会出现"写着已暂停、
   文件还在长"。

3. **安全点只在条目之间。** `_task_boundary()` 只在两张图之间被调用；这一层根本不提供
   "中断当前条目"的入口。TASK-009 的"已进入原子提交的任务完成后维持成功"于是靠**结构**
   保证而不是靠判据：写一个文件中途被叫停会留下一个解不开的半成品，而它在地账上看起来
   是"已经写了"。

4. **批次状态是算出来的。** `batch_state()` 由成员状态求值：只要还有一条是
   `running`/`pause_requested`（没到边界），批次就不是 `paused`（TASK-007 要的那句）。

5. **配方快照按 `task_id` 收，且只活在会话里。** `_task_args[task_id]` 存的是那一批
   开始那一刻的图层（含 numpy 表与掩膜）。因此：
   * 重试旧批次不能用"会话里最后那一批"的参数（TASK-002 禁止的正是这个）；
   * 从工程文件读回来的批次没有快照 → `retry` 必须**拒**并说明原因，而不是拿现在的
     滑块重跑（那既违反 TASK-002，也违反 TASK-008 的"不切换最新配方"）。

6. **`recipe_persisted` 说的是"快照还在不在会话里"**，不是"有没有写过工程文件"：当场
   建账的批次必然在（True），只有读回来的那份是 False。第一版在这里写死 False，于是
   重试的门在本会话内也是关着的——单测层看不见命令面守卫，是端到端用例响出来的。

7. **没 worker 的取消是记账**：落到 `cancelled`，不删任何已落盘文件与源图；而没 worker
   的 `pause/resume` 一律拒（会把台账写成一个永远醒不过来的 `resuming`）。

8. **暂停中允许 `project save`。** 工程层原本"导出进行中"一刀切拒绝，而 TASK-008 要的
   "中断后重开仍然 paused"只能发生在暂停中：用户暂停了一批没跑完的活儿，关应用前必然
   要存一次工程。一刀切会把验收用例逼成"先跑完再存"，那时已经没有未完成的批次可恢复。
   worker 睡着时不写任何文件，存盘是安全的。

9. **持久化只存台账与参数快照**（`inputs`、逐条目结局、history），不存配方（numpy）。
   `tasks` 进工程文件的那一份字段名与事件里的清单名分开：事件用 `task_restore`（逐条
   说明），`tasks` 留给台账格数——两个同名键在同一个字典字面量里会后写吃先写，这一形
   本轮又响了一次（`len(7)` 那种 TypeError）。

## 替代方案

* **把状态放进 worker 线程对象**：worker 一死状态就没了，而"进程曾中断后仍然 paused"
  要的恰好是线程没了之后的账。
* **用 SQLite 存任务表**：见 ADR-0006，单文件 JSON 与工程同生同死；任务台账是工程的
  一部分，不是独立数据库。
* **支持条目内中断（协作式取消逐块渲染）**：会把"原子提交"变成"提交到第几块"，收益是
  少等一张（几秒），代价是留下读不开的半成品与一张说不清的账。不做。

## 后果

* 逐图进度与台账结局在 16-bit 直通分支也必须记（此前 `continue` 得过早，RAW 批量导出
  在进度条上是"动都不动"，在批次账上是"跑完了而没人知道跑了哪几张"）。
* `export_done` 现在带 `task_id`/`task_state`/`cancelled`；收尾状态由条目账算：有失败
  报 `failed`，被叫停放 `pending` 数进原因，全绿才 `succeeded`——把部分失败折成"完成"
  就是 TASK-003 拒绝的那件事。
* 宿主（Rust）只搬运台账（`on_task` 按 id 覆盖），不判转移合法性；UI 的按钮可用态取自
  `state.tasks`，名单取自引擎 `ready.task_actions`。
