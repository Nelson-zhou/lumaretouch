# ADR-0019：PORTRAIT-005（跨图同一人）——本版本缓期，不做启发式冒充

- 状态：已定档（2026-10-19）；部分取代 ADR-0016 §2.3 里“脸盒 + 关键点几何出候选”
  这条路线
- 关联：冻结用例 PORTRAIT-005、ADR-0007（批量同步台账）、ADR-0016（面部之外的
  边界）、ADR-0017 §未闭合

## 用例要的是什么

> 同一人物多张照片及相似不同人物；分析关联后批量同步到已确认人物；
> 未确认/冲突候选不被自动修改；同步对象清单可审计。

两句判据里，后半句（不自动改、清单可审计）是安全性，前半句（候选从哪来）是
能力。安全性那一半本版本已经成立：批量同步只作用于用户显式选中的路径，任务台账
逐张记目标——不会因为“AI 觉得像”就动谁。缺的是前半句。

## 为什么本版本不做

1. **没有合规的人脸嵌入模型。** 跨图同一人靠的是身份嵌入 + 聚类，不是脸型几何。
   运行时里没有 insightface/facenet 一类依赖，也没有可用的 ONNX 权重；加一个
   意味着新权重、新许可声明行、新体积与新的运行时失败面（缺权重时整条链怎么退）。
   本轮可行性探测的结论就是“没有现成的、许可与体积都能进 THIRD_PARTY_NOTICES 的
   模型”。
2. **启发式冒充不了识别。** ADR-0016 曾提出“按脸盒归一化尺寸 + 关键点几何距离”
   出候选。脸盒与五官比例量的是姿态、焦距与脸型，不是身份：同一个人换镜头会散，
   两个脸型相近的人会聚。用它生成的“候选”在真实客片上必然混入陌生人——而这条
   用例的全部意义是**人工确认**，一份混着陌生人的候选清单比没有清单更坏。
   拿它硬凑成“已覆盖”，就是 DoD §2 禁止的伪装 AI。
3. **界面不为它开一个假入口。** 本版本的产品面只有四栏（磨皮/重塑/五官/颜色）。
   要加跨图候选，就得有确认/冲突的可视面；在没有可靠候选的前提下，那只会变成
   “点开一片噪声”的栏目——DoD §3 禁止的无响应控件。

## 决定

- PORTRAIT-005 记为 `deferred`（缓期），依据本 ADR；**不冒充通过**，也不再以
  `uncovered` 混在红色里。
- 本版本保证：**任何未被用户显式选中的照片都不会被修改**；批量同步的目标清单
  继续由任务台账逐张记录（BATCH-004，ADR-0007）。
- 不新增“同一人”入口、不新增启发式候选、不下载任何权重。

## 退出条件（什么时候重新变成“要做”）

同时满足三条才开工，缺一条都继续缓期：

1. 有一份**许可与体积都能进 THIRD_PARTY_NOTICES 与 deb** 的人脸嵌入权重；
2. 在**有许可的**同人/异人样本集上给出可复算的分离度（同人/异人分布不重叠，
   阈值有标定表），不是观感评审；
3. 有一个不破坏四栏产品面的确认面：候选分组、逐组确认、冲突显式拒绝，且任务
   台账能逐张审计。

到那时本 ADR 被 supersede，PORTRAIT-005 按冻结件原判据建集成用例；在此之前，
它是一条有理由的缓期项，不是一条被忘记的缺口。
