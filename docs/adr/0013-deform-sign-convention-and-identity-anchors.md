# ADR-0013：形变的位移场只有一种读法（前向），身份锚按格配，表情只做嘴角那一格

日期：2026-10-18　状态：已采纳（目标版本 1.7.0）
关联：《开发验收用例》PORTRAIT-012（P1·表情调整）、PORTRAIT-001/002/003/004/007（面部重塑那几条）、
DoD §2（严禁假滑块、MediaPipe FaceMesh + GPU 几何网格变形做瘦脸/大眼/下巴）、DoD §4（逐项跑通 P0/P1）、
ADR-0009（实测才能定档；局部性半径那一笔）、ADR-0011（同一份分析结果里的多人）

## 1. 起因：一个"看起来在生效"的反向

写 PORTRAIT-012（微笑嘴角）之前，先按老规矩把新 kind 的量法定成"在**出片**上重测 MediaPipe 关键点"。
第一次实测读数是：

| 档位 | 请求（`controls()` 里的 D） | 出片上嘴角的实际落点 |
|---|---|---|
| smile = +0.8 | 嘴角上抬 20.9 px（`SMILE_LIFT_OF_MOUTH_W × 0.8 × 嘴宽`） | **下掉 17.4 px** |
| smile = +0.8 | 嘴角横向**外展** 5% 嘴宽 | 横向**内收** 10 px |

画面确实动了（9.5 万格、最大 241 LSB），`deform_done` 的账单齐全，`det J > 0` 处处成立，
预览与导出逐字节一致——除了方向，每一句都自洽。这正是本仓反复防的那类缺陷：**能看见"生效"，
看不见"反了"**。

顺藤摸到根子：`grid_sample` 是反向映射（`output(x) = input(x + 网格偏移)`），而 `warp_t`/`warp_np`
一直把入参 `delta` 当**采样偏移**用（原有的两条采样判据就是这么钉的：`delta=+k` 时输出第 j 列取自
输入第 j+k 列，即内容搬 −k）。`ops/deform.py` 的 `controls()` 里：

- `slim_face` 的 D 按**采样偏移**落符号（左轮廓 `side=-1` → D_x 为负 → 内容往 +x 走 = 内收，恰好对）；
- `big_eye`、`small_chin`、`smile` 的 D 按**内容搬运**落符号（眼睑环外扩、巴尖上收、嘴角上抬）。

同一个字段两种读法，于是四种形变里三种在真图上是反的：**大眼变小眼、小下巴变长下巴、微笑变撇嘴**。
`slim_face` 对，是巧合——它靠"负负得正"碰上了。这个巧合掩盖了缺陷：单元测试只钉 `controls()` 里的
符号，而那是三种读法都能自洽的地方。

## 2. 决定

### 2.1 一种约定、一处负号

- `controls()` 的 D、`unit_field()` 的场、`export.composed_delta()` 的场，**一律是"画面内容要搬运的
  方向"**（前向位移，像素单位）。这是唯一读法，写进模块 docstring 第 5 条。
- 反向映射那个负号**只在 `warp_t` / `warp_np` 里取**（它们才是"采样"那一层）。预览与导出都汇到
  这两个函数，所以"屏幕上往左、导出往右"这种分叉在结构上进不来。
- `slim_face` 的 D 跟着改成前向写法（左轮廓 `D_x = -side·k`，即往画面内收），渲染结果与改前一致。
  其余三种一字不改——它们本来就是照"内容搬运"写的，错的是被当成采样偏移。

被否掉的两条路：

- *在 `vram.apply_deform` 里取负*：那会让 `adopt_deform_field`（导出器交进来的整幅场）与
  `unit_field`（预览建的场）从此是两种东西，下一次再加一条臂就会漏；
- *把 `controls()` 全部改成采样偏移口径*：那就是把名字与语义继续拧着——"上抬"写成负 y 靠读者自己
  换算，是这次事故的成因而不是解法。

### 2.2 身份锚：按格配，不一刀切

方向修对之后露出第二个问题：TPS 的远场**不衰减**（只有紧支撑窗在 `r ≥ 1.6R` 外归零），窗以内整片
都在动。实测 0.8 档 `slim_face` 把**瞳距改了 −13.2%**（两只眼睛互相走过去），`smile` 把瞳距改了 −3.9%。
"瘦脸"于是是"把整张脸缩一圈"，用户看见的是换人。

决定：每种形变带一组**零位移身份锚**（`ANCHORS_BY_KIND`），规则一句话——**这一格本来要动的部位
不许进自己的名单**：

| kind | 锚（零位移） | 为什么 |
|---|---|---|
| `slim_face` | 虹膜×2、鼻尖、四个眼角、嘴角×2、内唇×2、巴尖 | 只许动轮廓 |
| `big_eye` | 虹膜×2、鼻尖、嘴角×2、内唇×2、巴尖 | 眼角是**作用对象**：把内眼角钉住实测只把眼高开 0.34 px、却把两内眼角横向拖开 12.45 px |
| `small_chin` | 虹膜×2、鼻尖、四个眼角、嘴角×2、内唇×2 | 只动巴尖与下颌 |
| `smile` | 虹膜×2、鼻尖、四个眼角、巴尖 | 嘴角是要动的；唇中线由该 kind 自己那两点锚 |

锚点在 `dedupe_controls` **之前**加入：小眼/低头的几何时锚点会与五官点贴近，那种重合该进 `merged`
账，而不是被悄悄吃掉（吃掉的就是"用户请求的一半位移"）。鼻尖 `NOSE_TIP = 1` 与内眼角 133/362、
外眼角 33/263 的下标语义都在真夹具上量过（见 §3），不靠记忆。

### 2.3 表情这一格只做嘴角上扬

冻结件把手册的表情调整写成六样（自动/手动替换、露齿笑、抿嘴笑、闭合嘴巴、恢复画笔、微笑嘴角）。
本版本只做**嘴角上扬**：其余几样要**重建唇齿内容**（生成式），而冻结件 2310 行把"生成式表情/牙齿重建"
明确划进 P2 实验档；DoD §2 又不许拿假效果占一个控件位。于是：

- 引擎 `KINDS` 里只有 `smile`；请求 `teeth_show / pout / mouth_close / expression_transfer` 整条拒，
  拒绝文案报得出可用名单（`未知形变类型 'pout'（可用：slim_face, big_eye, small_chin, smile）`）；
- 面板**按引擎报的 `deform_kinds` 画滑块**（`ready` 那一格是唯一出处），前端不再自己抄元组；
  值域也取引擎的 `deform_range`；
- 文案守卫进 `test_deform`：zh/en 两份必须给 `KINDS` 每一格都有名字，且不许出现"露齿笑/抿嘴笑/
  闭合嘴巴/换表情"这类没实现的承诺。

## 3. 实测账（都是这一版跑出来的数，夹具 `portrait-1024x1280.jpg`，mediapipe 后端，代理档 504×400）

**请求 vs 落地**（亮点法：把 5×5 白点放在控制点上，走生产链 `build_deform → apply_deform → warp_t`，
量它搬到了哪；模板几何与真图关键点各跑一遍）：

| kind | 真几何上请求 D | 实测搬移 | 落地/请求 |
|---|---|---|---|
| `slim_face` | (+18.22, 0) | (+14.63, 0) | 0.80 |
| `big_eye` | (−2.61, −0.27) | (−2.74, −0.22) | 1.05 |
| `small_chin` | (0, −9.54) | (0, −8.52) | 0.89 |
| `smile` | (−2.92, −8.17) | (−2.85, −8.06) | 0.99 |
| 锚点（任一格） | (0, 0) | ≤ 0.36 px | — |

**出片上重测关键点**（导出 PNG → MediaPipe 再检测 → 量像素几何；档 0.8，对照同一管线的中性出片）：

| 读数 | plain | slim_face | big_eye | small_chin | smile |
|---|---|---|---|---|---|
| 瞳距 px | 228.22 | 226.41（−0.8%） | 231.45（+1.4%） | 226.33（−0.8%） | 226.16（−0.9%） |
| 脸半宽/内眼角距 | 1.5244 | **1.3386（−12.2%）** | 1.4723 | 1.5100 | 1.5514 |
| 下巴-内唇/内眼角距 | 1.0950 | 1.0911 | 1.0053 | **1.0205（−6.8%）** | 1.1558 |
| 嘴角相对唇中线 px | 64.11 | 62.00 | 61.66 | 56.22 | **82.13（上抬）** |

修之前同一张图的两笔账（留在这里，因为它们是这条 ADR 存在的理由）：`slim_face` 瞳距 −13.2%、
`smile` 嘴角 −17.4 px（往下）、`small_chin` 下巴-唇距 +9%（往下长）、`big_eye` 眼睑环几乎不动。

**smile 这一格的端到端判据**（`test_acceptance_p1.py::test_smile_raises_the_corners_keeps_the_person_and_restores_neutrally`）：
0.8 档嘴角上抬 23.06/24.64 px（请求 20.91 px，判 0.5–2.0 倍）、左右差 ≤ 25%、虹膜移动 ≤ 1.40 px、
瞳距变化 −0.90%（判 ≤ 2%）、内唇中点移动 8.4 px = 嘴角量的 36%（判 ≤ 60%）、嘴周边缘能量 99.9 分位
109.3 → 70.2（判不比中性出片高一档）、smile=0 与出厂帧**逐字节相同**、推到 0.8 再回 0 也逐字节相同、
底部 12% 那一横条一格没动（作用面 bbox 到 426 行 / 画幅 504 行）。

局部性那一笔要如实写清：**这一格不要求"画面外沿一圈逐字节不动"**。这张夹具的脸填满画幅，
`SUPPORT_RATIO=1.60` 的紧支撑窗把整幅都盖住了（ADR-0009 已在 `slim_face` 上量过同一件事），
所以那里给的是"最多 25 LSB"的余量（实测 18）而不是 0。写成 0 的用例会在每一张构图饱满的人像上
假失败，而假失败与假通过一样是噪声。

## 4. 后果与纪律

1. 采样口径的两条老判据（`test_fractional_translation_matches_analytic_bilinear`、
   `test_translation_moves_by_exact_pixels` → 改名 `..._moves_content_by_exact_pixels`）改成按
   "内容搬运"写：它们现在钉的是产品语义，不再是 `grid_sample` 的实现细节。
2. 新增三条守卫：`test_every_kind_moves_the_picture_the_way_its_name_says`（逐格判方向 + 落地 ≥ 六成）、
   `test_identity_anchors_stay_put_on_the_rendered_picture`（锚不许被拖走，≤ 1 px）、
   `test_preview_field_and_export_field_point_the_same_way`（预览场与导出场同点同号，差 < 1e-3）。
3. **加 kind 时必须同时加一条"出片上量语义"的判据**：字段/账单/事件都能自洽而方向是反的，
   这件事只有量出来才会响。同理，任何"移动/搬运/重塑"类算子都要有一条把请求方向与画面落点
   对起来的测试，写在算子层的符号检查不算。
4. 断言里的形变金额字典改为从引擎 `KINDS` 推（`_amounts()`）：加第四格时红的是产品名单而不是
   测试字面量——本轮三条老用例（`test_protocol` 两条 + PORTRAIT-004 一条）就是这么被抓出来的。
5. `big_eye` 在出片上的可见幅度仍偏小（0.8 档实测眼睑环 +1 px 级，而真几何的场落地是请求的 1.05 倍）。
   这一格的**方向**由亮点法与场级判据钉住，**观感强度**留作 1.7.0 之后的调档项（调 `EYE_PEAK_OF_IRIS`
   必须重跑这张表并把新数写回这里，不许只改常数）。
6. 未闭合：PORTRAIT-005/006（跨图身份、人工纠正优先）与 008/010/011（全身、妆容头发、手脚）
   本版本仍没有实现，验收执行器把它们写成 `uncovered`，不是 `passed`、也不是 skip。
