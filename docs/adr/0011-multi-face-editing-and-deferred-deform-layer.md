# ADR-0011：多人图的分人编辑（按脸盒认人）与"关键点不随工程走"留下的那一层

日期：2026-10-18　状态：已采纳（目标版本 1.4.0）
关联：《开发验收用例》PORTRAIT-003（P1·多人照片仅编辑指定人物）、SCOPE-001（P0·多人超范围保护）、
CORE-001（P0·项目创建与重开："配方完整恢复"）、ADR-0002（MediaPipe 内嵌后端）、
ADR-0006（工程存单文件 JSON、派生物不入库）、ADR-0009 §2（形变支撑窗实测）、ADR-0010 §7（派生物落后与守卫）

## 1. 要解决的问题

冻结件里那两条读起来像互相禁止：

- **SCOPE-001**：探到多张脸时，人像 AI 要么整条拒并说明作用范围，要么按人分服务——
  **唯独不许"静默选一张"**，因为用户从画面上看不出来（脸确实被推了，推的不是他以为的那一个）。
- **PORTRAIT-003**：两人照片 → 只选择第一人调整眼部 → 第二人有效配方不变，影响落在第一人的蒙版边缘内。

裁决：两条不冲突。**SCOPE-001 挡的是"引擎替你选"，而用户的一次显式点选正是放行的凭据**。
于是这一条能力的形状被钉死成三件事：名单只能来自真实分析、放行判据只能有一处、选型必须是文档状态
（能进撤销栈、能进工程文件、能进出片口径）。

第二个问题不是读冻结件读出来的，是端到端用例跑到第 ⑨ 段才撞出来的：关键点**不随工程文件走**
（ADR-0006：它是模型派生物，剔掉它的理由与 RepairOp "只存输入不存结果"同一条），而形变层的单位场
是从那批关键点解出来的。上一版 `_attach_pipeline` 遇到"有已建好的形变层而关键点不在"就**整层归零**，
注释里还写着"不能默默建不起来"——它确实没有默默，它把用户的作品删了。重开工程那一刻这条必然命中，
于是"保存 → 重开 → 瘦脸没了"，撞的正是 CORE-001 的 then：**配方完整恢复**。

## 2. 决定

### 2.1 名单与视图：一张分析结果里可以有更多人

`FacePrecompute` 增 `all_landmarks`（逐张 478×3，mediapipe 路径逐张校契约）与 `face_index`，
`faces()` 报"可编辑的人"（归一化脸盒 + 占画幅比例），`select_face(i)` 返回一个**新视图**而不是副本：
`landmarks/face_box/face_index` 换掉，`masks` 与 `all_landmarks` 与原对象同一身份——磨皮用的皮肤掩膜
本来就该是整张图的，换人不换掩膜，也不为换人重跑推理。

`scope_block` 不随选型翻牌：它说的是"这一轮探到了多人"这个事实，而不是"现在能不能点"。
放行之语由 `blocked` 说（见 2.3）。把两件事混成一个布尔，下一次问"当初为什么拒"就没人答得上。

### 2.2 认脸靠脸盒，不靠序号

检测器的返回顺序不是人能预期的。重算一次、重开一次工程之后，"第 0 张"完全可能换个人——
**拿旧序号对新名单就是一次静默选型**，与不选型一样错，而且更隐蔽：状态里写着"用户选了"。

所以文档里存三键：`_face_index`（那一次分析里的第几张）、`_face_box`（那一张的身份）、
`_face_explicit`（这一个是**人**选的，不是默认值）。`_preserve_face_choice()` 与 `_replay_face_view()`
一律**先认脸盒、后认 index**，容差 1e-3（归一化坐标；同一次推理重算两次应逐字节一致，真漂过这一档
就不是同一个人，宁可不认）；认不回就退回未选定 + 一条 `engine_warn`，绝不用序号冒充。

只存 index 不存"是不是人选的"，下次就能拿默认 0 冒充选定——这就是 `_face_explicit` 存在的全部理由。

### 2.3 放行判据只有一个出处：`_face_state()["blocked"]`

`blocked = 多人 and not explicit`。引擎的 `cmd_deform` 整条拒读它，UI 的禁用理由读它，端到端用例的
断言也读它。写第二处就会出现"面板说能点而引擎拒"——那是 DoD §3 明确禁止的无响应控件。

`face select` 是 EDIT_CMD：一次点选进撤销栈，`_history_apply` 之后 `_replay_face_view()` 把视图指回
那一张。不重放就是"状态说在改 0 号、画面在改 1 号"，而两张脸都确实被推过。

### 2.4 形变层新增一格：`_deform_defer`（层在，单位场等关键点回来）

三层语义分开，各自诚实：

| 状态 | `built` | `_deform_defer` | `amounts` | 事件 |
|---|---|---|---|---|
| 正常生效 | True | False | 会话真在渲染的值 | `deform_done set/rebuild` |
| 层在而关键点没回来 | False | True | **用户的值，原样留着** | `deform_done action=defer` |
| 用户清了 / 认不回人 / 后端不能取点 | False | False | 全零 | `deform_done action=invalidate` + `dropped_amounts` |

`doc_state.deform` 与 `deform_done` 都把 `defer` 报出去，`deform_done` 另带一份 `deferred_amounts`：
`amounts` 说的是"会话现在真的在渲染什么"（defer 期间那是零），用户的值走另一个字段。合成一个字段
就是说谎——要么把"没在渲染"说成"没这一层"，要么把"已存住"说成"已生效"。

`_rebuild_deform_for_landmarks()` 的入口条件跟着改成 `built or defer`：关键点一回来就把存住的那一份
解出来。defer 与 `_deform` 同属 PROXY_BOUND（代理档一变就作废）：作废时留着它，下一次分析就会把
"上一张图的瘦脸"复活成这一张图上的一层。

### 2.5 重开工程主动补一次分析，点名存下来的后端

`project open` 自动展开的那一张，若配方靠关键点（`_recipe_needs_landmarks()`：形变层/待重挂/选型），
就在 `load_image` 里带上 `precompute=true` 与**工程文件里存的那个 backend**。

不静默回落：点名 mediapipe 而后端/模型不在，`cmd_precompute` 直接报错，那一层留在 defer 状态
（值还在、面板写着"等重新分析"），而不是换 template 凑一层假形变——那正是 DoD §2 禁止的"伪装 AI"。

分析完成后 `precompute_ready` 现在带一份 `face`（同一处组装的 `_face_state()`）：重开那一刻
`image_ready` 先出、分析后到，宿主只有一个"最新一句陈述"的槽位可读，`source` 字段说清是谁说的。

### 2.6 出片同口径

导出路径本来就自己从关键点重解场（满幅/分块），所以它只需要 `pc.landmarks` + 那三个数，不需要会话里
那个单位场。判据相应从 `amounts and built` 改成 `amounts and (built or defer)`：只看 `built` 会把一个
重开工程后还没补分析的用户"他的瘦脸"静默从文件里删掉——那是屏幕与文件双向错配里最难复查的一族，
而 RENDER-002 要证的恰好是"屏上等于文件"。

## 3. 这一轮被新判据抓住的两起（不是修测试，是修代码）

1. **`_capture_state` 撞 AttributeError × 3**（test_history 三条臂）。face 那三键进了
   DOC_FIELDS、进了 `_capture_state`，唯独没进 `__init__`。本仓的名单铁律原本只有两条腿
   （`_fresh_doc_state` ↔ DOC_FIELDS、`_capture_state` ↔ DOC_FIELDS），而这两份名单是同一条口径
   写在两处，一起漏就照不出。补第三条腿：`__init__` 末尾 `assert` DOC_FIELDS 每一项都已有属性——
   把"少一行"从运行时提前到创建引擎。
2. **⑨"重开后画面与保存前差 240 LSB"**。这条判据是新写的，第一次跑就抓住了 2.4 那个真缺口。
   顺手也修了断言自己：`np.abs(got - lit_frame)` 在 uint8 上做减法会回绕（240 = −16 的补数），
   对拍一律先升 int16。

## 4. 验证

- 库层：`engine/tests/test_face_select.py` 6 条（名单不被重排、视图共享同一个 masks 对象、
  原件不被改、越界/坏类型/坏形状整条拒、`meta()` 两格与 `scope_block` 不翻牌、
  synthetic/template 也填名单）。
- 端到端：`engine/tests/test_acceptance_p1.py::test_editing_one_person_leaves_the_other_untouched`
  九段判据（真 mediapipe 两人图夹具，`num_faces=2`）：未选定整条拒且不留半截状态 → 非法 index 全拒 →
  选人不动画面 → 推 A 时 B 的内芯逐字节为 0 → 影响落在 1.6× 脸半对角圆盘外为 0（ADR-0009 §2 实测的
  支撑窗）→ 换 B 之后 A 归零 → 撤销/重做逐字节对回 → 两次导出反查（文件里 B 被推、A 的内芯 0 LSB）→
  **重开工程：选型回来 + 引擎自动补分析 + 画面逐字节 = 保存前那一帧 + 原片哈希不变**。
- 面板：`status.face` 一个槽位多源汇入；chip 名单只从引擎读；未选定时那三个滑块禁用并写明
  "先点选要编辑的人物"，选定后解禁。

## 5. 仍然没闭合的（诚实清单）

009（眼牙）、BACKGROUND-001、PICK-001 仍记 **uncovered**：它们分别要身份模型、人体/手部关键点、
可评测的分割质量与"近似组/模糊/闭眼"的本地确定性度量。DoD §2 禁止伪装 AI，所以宁可留未覆盖，
也不签一个假实现。PORTRAIT-002/007 的自动化那半已跑，人工盲评那半要人签字，`manual_pending`
不算通过（退码 3）。
