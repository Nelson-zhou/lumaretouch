# ADR-0014：定版门禁的假红按缺陷处理——脚本期望不许落后于单一出处，执行器按 seq 认帧

日期：2026-10-18　状态：已采纳（目标版本 1.7.0）
关联：DoD §4（逐项跑通 P0/P1 并留真实性能读数）、DoD §5（deb 装机 + 真机自证）、
ADR-0013（本轮新增 `smile` 那一格；形变字典的键集从此是四格）、ADR-0003（中性=逐字节恒等）、
`packaging/m5-release-check.sh`（真窗口七臂 VERDICT）、`tools/run-acceptance.py`（映射落后报假红的守卫）

## 1. 起因：一次定版里两处"红"，都不是产品的错，而都必须当成缺陷修

1.7.0 打包装机后跑七臂真窗口自证，读数是：

```
── 6. 层级那一臂：全人物默认 + 逐张覆盖 + 恢复继承（LNX-PORTRAIT-004）
  × 生效值 = 默认打底 + 覆盖盖上：{'big_eye': 0.9, 'slim_face': 0.2, 'small_chin': 0, 'smile': 0}
  × 改默认（slim 0.2→0.6）时：… → {'big_eye': 0.9, 'slim_face': 0.6, 'small_chin': 0, 'smile': 0}
  × 恢复继承后全部按层级合成 → amounts={'big_eye': 0.3, 'slim_face': 0.6, 'small_chin': 0, 'smile': 0}
── 读数：28 条通过，1 条不过
VERDICT=FAIL — 这个包还不算开箱即用
```

引擎合成出来的字典多了 `smile: 0`（这是 ADR-0013 那一格加进来之后的**正确**行为），而臂里拿
三键字典字面量做等式比较。红的是脚本，不是包。

同一轮全量回归另有一处：`863 passed / 1 failed`，红的是
`test_acceptance_p0.py::test_neutral_params_are_byte_identity_and_survive_save_reopen`
——"强度 1.0 画面还一模一样：那是假滑块"。**单独重跑同一条：1 passed**。差的那一格只在整机
负载高时出现。

## 2. 决定

### 2.1 门禁脚本不许写死"整份形变字典"，改逐格判

`_composed(d, want)` 两半都是真判据：①这一臂**显式设过**的那几格必须逐格等于设计值；
②这一臂**根本没碰过**的格必须全为 0（合成不许凭空给没设过的格带上值）。旧写法靠字典字面量
把第②半藏在"键集也要一样"里，于是新增一格就报假红。

配一条守卫用例 `test_release_scripts_do_not_hardcode_an_amounts_literal`（`test_acceptance_tool.py`）：
`packaging/*.sh`、`tools/*.py` 里一旦出现"`== {…slim_face…}`"这种整份字典等式就红。负向自证（一手）：

```
修前的脚本里命中 3 处：  574 / 576 / 580   ← 正是这次报红的那三行
修后的脚本里命中 0 处
```

### 2.2 执行器按「这一笔的回执」认帧——两次改法，第一次还是错的

第一版判红之后我把根因记成"`_drain` 的安静窗口太短"，改成了"发命令前取 `peer.freshest()`
的 seq，之后第一帧 seq 更大者算数"。全量重跑：**同一条用例仍以同一种形状红**（864 passed /
1 failed）。于是加了一支探针把帧事件自己的字段打出来，连跑三次都是同一句话：

```
@@strength0 ev.seq=4 ev.slot=1 ev.strength=0.0
@@strength1 ev.seq=5 ev.slot=0 ev.strength=0.0     ← 请求的是 value=1.0
@@强度0↔1 差 = 0 LSB
```

也就是说 seq 更大的那一帧**事件自己写着 strength=0.0**：它属于上一条命令。为什么 seq 规则
也会输——前面几条命令（`inpaint clear` / `light clear`）发出去之后没人等它们的回执，引擎
是在我取样**之后**才把那些帧提交进 shm 的，seq 自然比我取的那个样本大。拿"取样时刻的最大
seq"当分界线，赌的还是时序。

真正的身份是**事件流里的位置**：引擎单线程处理命令，每条命令固定发
`……(前面所有命令的回执与帧)…… → 本命令的回执 → 本命令的帧`。所以先等本命令的回执
（`set_strength` 是 `params_set`），回执一到，前面别人的帧就全被消费掉了，下一条 `frame`
必是本命令写的。没有回执的命令（`crop`/`exposure` 只出带 `mode` 的帧）按 `mode` 认；
名单里查不到的命令当场响，不许退回去拿"下一帧"。再补一道自证：帧事件自带 `strength`，
请求值与它对不上就不算这一帧（认错了就是伪证）。

同一条规则配了不连引擎的判据（假 shm + 假事件流），把两个形状都钉住：旧帧压在前面时
必须跳过、只认带 mode 的帧时不许拿到 `drag` 那一帧。

顺带把判据本身也变强了：`P0-*-NEUTRAL` 里"强度 1.0 必须与 0.0 不同"这一判原来用出厂
那组增益（broad 0 / mid 0 / detail 1），库层 cpu 与 cuda 两臂实测只有 1 LSB——那是
"保留全部肌理"的语义，红线贴着 1 LSB 等于没有红线。现在用一组真要磨皮的增益
（0.55 / 0.35 / 0.25，三个数都在协议校验的 [0, 2] 量程内），两臂实测 134 LSB，红线取
16 LSB；而"strength=0 逐字节恒等"那条冻结判据一个字没动（混合式 `0 × 磨皮结果` 恒为 0，
这一判反而比以前更强）。

### 2.3 文案与注释不许写死形变格数

面板会印出来的那一句是真缺陷：`deform` 的 `inherit/clear(person)` 空操作提示原文写着
"三格全部跟随全人物默认"，而 KINDS 已经是四格——屏幕上当场说假话。改为由 `len(KINDS)` 推。
同批清掉 12 处旧计数（`server.py` 文档串与注释、`vram.py`、`ops/deform.py`、两条测试的
文档串/断言消息）：判据一律由 `KINDS` 推，计数不在文案里重述。

## 3. 为什么不选另一种

- **放宽判据**（把等式改成"包含就行"、把 `>0` 改成 `>=0`）：那等于把真缺陷的门也拆了，
  本仓防的正是这一类。
- **给失败加重试**：把时序问题藏进第二遍，第三次跑还是红，而人会开始怀疑红。
- **把 `_drain` 的安静窗口从 0.4 s 调到 2 s**：仍然是拿时间当判据。负载再高一点就复发，
  而且每条命令白等 2 s，全量回归直接翻倍。
- **改按 `freshest()` 的 seq 认帧**（我改的第一版）：看着像把时序换成了确定量，实际赌的
  还是"取样之后不再有别人的帧"。它没解决任何东西，只是把假红变成难以解释的假红。
- **只改 m5 脚本不加守卫**：下一轮新增一格（PORTRAIT-009 那一格迟早要来）会在同一个地方
  再红一次。

## 4. 后果与纪律

- 假红的代价不是难看，是**教会人跳过 `VERDICT=FAIL`**。所以本轮两处红都追到根、都留下了
  能复算的负向读数，而不是重跑一次看它绿。
- 任何"读回一帧/读回一个文件"的判据，身份标识必须是**因果链上的位置**而不是时间窗或
  取样快照：文件用 sha256 与 IHDR，出片用再检测的关键点，帧用"这一笔的回执之后第一条
  frame"（外加帧事件自带的 strength 对账）。本轮连着两次拿"看起来更可靠的快照"当身份
  （安静窗口、freshest 的 seq），两次都被同一条用例打回——差别只在于第二次错得更像对的。
- 引擎里凡是键集由 `KINDS` 决定的字典，消费侧（脚本、测试、UI 文案）只能逐格判或按 `KINDS` 推，
  不许重述整份键集。
