# ADR-0017：人工纠正优先——人脸名单的人工状态、按 IoU 认人、区域真检测

日期：2026-10-19　状态：已采纳（1.9.0 落地）
关联：《开发验收用例》LNX-PORTRAIT-006（given 用户手动添加/禁用的人脸，when 后台重检测或
更换检测模型，then 人工纠正保留、变化可预览、不静默恢复已禁用误检）；
ADR-0016 §2.3（这一条的路线）；ADR-0011（`face_index` 显式选定）；ADR-0009（P1 覆盖边界）；
ADR-0015 §2.9（两条计账纪律，本档沿用同一口径）；DoD §2（严禁伪装 AI 与假效果）、
DoD §3（未接通功能显式禁用并说明原因）。

探针：`tools/probe-face-manual.py`（运行时 venv，真 mediapipe + 真夹具；下面每个数字都是它
的一手输出，不是回填的说明文）。

## 1. 决定一览

| 项 | 决定 | 一句话理由 |
|---|---|---|
| 人工账存什么 | 归一化**脸盒/框**，不存 index | 检测器返回顺序不可预期，index 只活在"那一次分析"里（ADR-0011 已经为这件事付过一次钱） |
| 人工账放哪儿 | 进 `DOC_FIELDS`（文档状态、撤销栈、工程文件），**不进** `PROXY_BOUND` | 归一化坐标与代理档无关：换一档代理它仍指同一个人；跟着作废就是"重算一次分辨率，关掉的误检自己活了回来" |
| 认人怎么认 | 禁用/补框按 **IoU ≥ 0.5**，选型仍按逐位（容差 1e-3） | 冻结件的 when 写的是"重检测**或更换检测模型**"，逐位相等等于宣布人工纠正只在同一次推理内有效 |
| 放行判据 | `blocked` 按**还剩几个可编辑的人**算；`scope_block` 保持原始分析事实 | 用户关掉一只误检后只剩一个人，还要求他"选一个名单里只剩一格的下拉框"就是另一种无响应控件；而 SCOPE-001 的 P0 判据钉的是"这一轮是不是多人图"这个事实 |
| 补脸怎么拿点位 | 在用户框的区域上**再跑一次同一个后端**（`face.detect_region`） | DoD §2：不许按框拟合一套占位点位冒充"这就是你框的那张脸"。拿不到就明拒 |
| 认不回时 | 条目**留在账上**并标 `stale` / `lost`，随 `precompute_ready` 报出去 | 丢掉账 = 静默恢复；留着并说出来 = 用户还能自己处理 |

## 2. 实测表（一手读数）

夹具：`portrait-dual-1570x950.jpg`（代理档 354×585，真 mediapipe 报 `num_faces=2`）、
`portrait-1024x1280.jpg`（代理档 509×407）、三格图（`make-test-dual-portrait.py --cells 3`，
代理档 287×720）。

### 2.1 换检测模型时"同一个人"的盒差多少（`MANUAL_IOU_MIN` 的根据）

| 对照 | 最佳 IoU |
|---|---|
| mediapipe 第 0 位 ↔ template（同一张多人图） | **0.1319** |
| mediapipe 第 1 位 ↔ template | **0.1268** |
| mediapipe ↔ mediapipe（同图同档重算） | 逐字节一致（容差 1e-3 的选型判据就是为这一档设计的） |
| 用户框 ↔ 区域检测回来的盒（三格图漏检那位） | **0.9813** |
| 同一轮名单里**两个人**的盒互相对 | **0.0** |

结论与它的代价，两句话都得说：
· 同模型重算与"用户框 → 区域检测"这两条路上 IoU 接近 1，0.5 的下限余量充足；
· **mediapipe ↔ template 这一对根本到不了 0.5**（template 给的是肤色包围盒，多人图上它
  就是横跨两个人的那一片）。所以本版本对"换成模板后端"这一臂的诚实答案是
  **认不回 → 账保留 → 标 `stale` 并随事件说出来**，而不是假装认得回。端到端那条臂
  （`test_manual_face_corrections_survive_redetection_model_switch_and_reopen` 的第⑤段）
  判的就是这个二选一：`attached` 与 `stale` 必须**互斥且必有一个**，谁都不许静默。
下限取 0.5 的判据是"两个不同的人不该被算成同一个"：名单内部 IoU 实测 0.0，而同一人
跨后端也才 0.13——0.5 卡在"绝不把邻座认成同一个人"这一侧，把跨真模型的漂移让给 `stale`
通道。取更低（0.2）会把"两个人挨得近"当成一个人，那比认不回更坏。

### 2.2 用户只框五官时要补多少上下文（`REGION_PAD_RATIO` 的根据）

在同一张单人图上把框内缩成"只有五官"（归一化 `[0.332, 0.3167, 0.6675, 0.6105]`），
按不同补比例跑区域检测：

| 补比例 | 结果 | 回来的盒与用户框 IoU | 窗尺寸 px |
|---|---|---|---|
| 0% | **失败**：`MediaPipe 未在这张图上检测到人脸` | — | — |
| 15% | 成功 | 0.4961 | 181×194 |
| **30%**（采用） | 成功 | 0.4631 | 227×240 |
| 45% | 成功 | 0.4609 | 273×286 |

补 0% 直接失败，这一条把"补上下文是装饰"这个想法证伪了；15% 已经在悬崖边（同一夹具
再小一档就掉下去），45% 换不到可读的收益却把邻座更多地带进窗里（2.1 那条"选与框对得上
的那一张"的压力更大）。取 30%。

### 2.3 框一路缩小时谁先失效（`REGION_MIN_SIDE_PX` 的根据）

| 内缩比例 | 框短边 px | 补完的窗短边 px | 结果 |
|---|---|---|---|
| 0% | 175 | 345 | 成功，IoU 0.975 |
| 15% | 149 | 293 | 成功，IoU 0.7212 |
| 30% | 123 | 241 | 成功，IoU 0.5242 |
| 45% | 96 | 189 | 成功，IoU 0.3781 |
| 60% | 70 | ~91 | **失败**：该图上没有可检的人脸 |

48 px 这一格**不是**检测器的可用下限（实测它在 ~90 px 这一带就先失效），它是"别再往下喂
退化窗"的地板：窗比 48 还小的时候后端必然报"没脸"，而那句话会被用户读成"我框错了"。
所以这一格的作用是**把"喂不动"与"框里没有"这两种失败分开**，让后者才是唯一对外文案。
真失效那一条（60% 那一档）说的就是实话：这一框里没有可服务的人脸，名单原样未动。

## 3. 四条构造性质（与实现同源，不是事后追述）

1. **禁用是一次排除，不是一次选型**：`face disable` 之后若只剩一个可编辑的人，引擎把那一
   个人指为当前对象，并把这一步在事件里明说（`note="…已指为当前编辑对象"`）。判据：真窗口
   第 9 臂 `M0_MANUAL` 与端到端①段——画面逐字节不动（记一条账不是调图），而留下那一位的
   活儿一点没被烧掉。
2. **被禁那一只不许再被服务**：`face select` 撞上一个 `disabled` 索引时整条拒，错误里给出路
   （`face enable`）。放行判据与拒绝都从 `_face_guard()` 这一处出（deform 与 enhance 两条臂
   共用）——两处各自拼一遍就会在加进人工账之后分了家。
3. **放下过一层就得补一帧**：本轮把 `_rebuild_deform_for_landmarks` / `_rehang_enhance` 的
   三条 invalidate 臂统一接上 `_refresh_frame_after_drop`。此前的行为是"建新层并点亮才补帧"，
   于是 `lit=false` 报出去而屏幕上还挂着刚才那张脸——这是 ADR-0015 §2.9 那条"账与画面对不上"
   的兄弟形状，由 PORTRAIT-006 的逐格判据（被禁那一只的内芯必须 0 改动）抓出来。

4. **人工账那一条事件必须自己带着 `face` 对象**：`face_manual` 与 `face_selected`/
   `face_list` 走宿主同一个槽位（`note_face` 只认事件里那格 `face`）。上一版桥的路由器
   只列了前两个名字，于是引擎记上了账而屏幕要到下一次 precompute 才认——面板上就是
   "点了 ✕ 不动"，DoD §3 禁的那一类。这一条由**双向守卫**钉住（`test_face_manual.py`
   里那条：引擎带 `face` 的事件名与 Rust 路由器列出的名字必须互相包含），因为"新增一条
   事件忘了接桥"这件事裸引擎用例一个字也看不见：auto_pick（上一轮）与 face_manual
   （这一轮）是同一个形状的两个实例，都只有装机真窗口量得出来。

## 4. 后果

· 工程文件多一格 `_face_manual`（随配方走），旧工程缺这一格按空账处理；名单里"人工"那一张
  不随工程走（它是派生物，与关键点同一条理由），重开时由区域检测再取一次。
· `ready_caps.face_actions` 成为面板按钮的单一出处；引擎没报的动作不画按钮。
· `face add` 的代价与一次整幅检测同量级（实测 `t_detect_ms` 10.03 ms / 287×720 代理档，
  三格图那一位），不是免费控件；UI 因此把它做成一次点击一条命令，不放进拖动里。
· 未闭合：跨**图**的同一人确认（PORTRAIT-005）仍没做——它要的是人脸嵌入与聚类，本版本没有
  那个模型（ADR-0016 §2.3）。这里做的是同图内的人工账，不是"认得人"。
