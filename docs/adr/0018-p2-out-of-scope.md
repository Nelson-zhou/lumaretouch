# ADR-0018：P2 里的生成式、云协作与创意历史——显式范围外

- 状态：已定档（2026-10-19）
- 关联：冻结验收用例 GEN-001/002、CLOUD-001/002、DIFF-001/002；
  ADR-0001（非商业定位）、产品定位“本地优先、离线可用、不做生成”

## 背景

冻结件 P2 里有六条用例，验收执行器过去把它们一律记成 `uncovered`（红）。但其中
没有一条是“还没做”：它们要么与产品定位直接冲突，要么依赖一个本产品不提供的
服务端。把“决定不做”与“漏了没做”混在同一个红色状态里，会让真正的缺口被噪声
埋掉——这本身就是账目失真。

## 决定

以下六条记为 `out_of_scope`，依据本 ADR，**永不**计入通过：

| 用例 | 为什么范围外 |
|---|---|
| GEN-001/002 | 本产品不做生成式编辑：没有生成模型，也没有“接受生成结果”的动作。判据里的资产/依赖版本/重开可用，对一个不存在的动作没有对象。 |
| CLOUD-001/002 | 本产品没有云通道：默认纯本地、离线可用（`test_no_egress` 守着不出网）。没有“首次发起云任务”这个入口，也没有协作服务端扮演 revision 冲突的另一方。 |
| DIFF-001/002 | 创意历史是“生成派生资产”的版本树；没有生成就没有这棵树。提交式版本与撤销/重做已由 CORE-007、CORE-001/006 覆盖。 |

## 后果

- 报告里这六条显示为“➖ 范围外（ADR-0018）”，不再显示为红色 `uncovered`；
  汇总表单独计列，且不计入通过。
- 产品面不为这些能力留任何入口（DoD §3：不留无响应控件）。界面上的四栏就是
  全部可编辑面。
- 退出条件：如果产品定位变更（加入云协作或生成式编辑），本 ADR 被 supersede，
  这六条重新进入“要做”，并按冻结件的原判据建用例；不允许拿“近似能力”冒名顶替。

## 明确不做的事

- 不把“导出到别处再上传”包装成云能力；
- 不把传统修复/克隆包装成生成式编辑；
- 不给 GEN/CLOUD/DIFF 造一条永远只报“不支持”的测试来把状态刷成通过。
