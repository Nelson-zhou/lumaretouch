# ADR-0001 · 代码许可与纯开源模型分发策略

状态：2026-10-20 修订，替代旧文档中“非商业定位可自动放行受限模型”的推断。现有 LICENSE 的 GPL-3.0-or-later 文本不变。

## 定位纠正

用户明确项目为纯开源，并未因此要求禁止下游商用。开源与项目是否收费不同；OSI定义不允许以行业或商业用途排除使用者。不能把“作者没有商业计划”用作第三方许可的豁免，也不能将“仅非商业”依赖直接作为纯开源发行方案。

旧文档称MIT/Apache允许丢弃署名，这是错误概括。MIT明确要求随副本保留版权与许可声明；GPL、Apache及各组件具体义务仍分别遵守。本次不替换项目代码许可，不删除第三方版权文本。

## 分发与验收

- bundled：具体文件、版本、哈希、体积及适用许可有一手证据，实际打包清单一致。哈希通过只证明字节，不证明全部法律问题已解决。
- fetched：按需下载同样是分发链，不是绕过许可的办法；只有具体版本许可与摘要核准后才能进入下载清单。
- fetched-pending / bundled-candidate：候选而非已可分发，未核清内容不得混入主发行物。
- blocked：该后端不符合当前分发条件，不能用它关闭产品需求；对应功能仍须寻找兼容后端并验证效果。

下载前透明说明文件、来源、版本、体积与许可，是隐私和可控性设计；提供许可文本与署名不等于法律强制用户逐次点击弹窗，也不能推导“静默下载必然违反署名义务”。版本或权限条件改变时需重新核验，不能把一次确认当成无限静默更新授权。

## 模型决定

- CodeFormer：S-Lab License 1.0限非商业，移出默认获取候选。保留面部恢复/超清需求，不删功能。
- GFPGAN：仅为待审候选。上游LICENSE本身列有第三方例外，不能只看首页Apache标记；须按实际推理代码路径和具体权重核查。
- LaMa：独立权重许可证据未齐，列fetched-pending。不能因为训练集有某条款就直接断言权重自动继承全部条款，也不能因没有独立声明便自行放行。
- MediaPipe：台账中的既有字节与声明保持可追溯；PyPI遥测、源码运行时构建和具体模型卡适用条款仍单独核验。当前断网测试不证明发行运行时已无遥测。
- YuNet：候选，当前没有已核验可分发的权重副本；MIT目录声明不能代替实际版本及文件指纹。
