# Numerical design and provenance

Status: AUTHORED / UNRUN. All thresholds below are original conservative defaults,
not measured quality claims or reverse-engineered proprietary behavior.

## Input color and coordinates

Active inputs are interleaved float32 RGB in genuine encoded working-sRGB, finite
and in [0,1]. The core does not guess an ICC profile or accept display-rendered
colors, 8-bit roundtrips, camera RGB, linear data mislabeled as encoded, HDR or
wide-gamut values. Reference measurement always uses the genuine immutable full
source and same-source-grid masks, never a display proxy. Composition may use an
explicit, provenance-bound downscaled CURRENT float processing grid; its target
mask and tile coordinates must use that same declared grid. Caller owns upstream
color management, projection and alpha handling.

Each channel is decoded using the sRGB transfer function: v/12.92 at or below
0.04045, otherwise ((v+0.055)/1.055)^2.4. Linear luminance is
Y = 0.2126 R + 0.7152 G + 0.0722 B. All statistics and composition use f64 internally.
Output is sRGB-encoded and converted once to f32. No per-channel RGB clipping occurs.

## Robust selected-reference estimation

Root and tip samples are separate manual masks, each finite in [0,1], no greater
than the provided reviewed hair coverage. A pixel with both sample masks > 0 is
ambiguous and causes refusal. No automatic top/bottom, face-box or hair-orientation
heuristic infers a root or tip. An empty nonselected mask is allowed.

For a selected pixel, let p = linear_RGB / sum(linear_RGB). It is normalized
linear-RGB chromaticity, not perceptually uniform Lab and not a learned feature.
Sample weight is the already-intersected selected mask times a reliability gate.
The hair mask is not multiplied a second time.

For t = clamp((v-lo)/(hi-lo),0,1), S(lo,hi,v) = t²(3-2t). The gate is
S(0.008,0.04,Y) × (1-S(0.55,0.90,Y)) × (1-S(0.85,0.99,max(R,G,B))).
These are LINEAR values. Black, near-white and clipped/saturated channel peaks are
intentionally poor reference evidence. The gate also attenuates target composition.

There are three bounded full-source passes:

1. Validate all RGB/masks, including uncovered pixels. Accumulate selected raw
   support and 512-bin weighted histograms for each p component. The component
   median uses the center of the first bin reaching half the eligible weight;
   component quantization is at most 1/1024 for that bin's samples. This component
   median need not sum to one and is used only for robust distance decisions.
2. Histogram the maximum absolute component distance to that median using another
   512 bins. Let MAD be the weighted median of these distances. Refuse MAD > 0.05.
3. Retain samples within radius min(0.12,max(0.02,3×MAD)), then calculate weighted
   mean chromaticity, effective sample count and RMS Euclidean dispersion.

Require >=32 selected and retained pixels, selected and retained weight >=16,
effective count (sum w)²/sum(w²) >=32 (1e-9 boundary tolerance), retained weight
>=70% of eligible weight and >=25% of raw selected weight, and RMS dispersion <=0.06.
A broad or conflicting mixture therefore cannot silently become a made-up average;
a dominant coherent patch can exclude a bounded minority. These checks do not
prove a sample is the person's natural color or reject every multimodal case.
Mixed dyes, intentional gradients, reflected colored light and scalp contamination
still require manual review. A refusal should ask for clearer samples, not invent
color or auto-select another reference.

The final field is q = mean_p / Y(mean_p) - (1,1,1), so sum(W_c q_c) is zero to
floating-point accuracy. Each q_c is physically bounded by [-1,1/W_c-1]. The ABI
stores direction, source size, raw/retained counts and weights, effective count,
retained fraction and dispersion alongside q. This is a numeric record, not an
identity token or confidence generated by a learned model.

## Current-stage application and gamut

For CURRENT linear RGB P and luminance Y, form chroma C = Y q. Let s be the minimum
of 1, (1-Y)/C_c for positive C_c, and -Y/C_c for negative C_c. Contract this ONE
common scalar inward by 1-4e-12 for safe floating-point boundary margin, then set
T = (Y,Y,Y) + s C. This is an analytical SDR cube intersection along the linear-RGB
neutral-to-target direction, not CSS perceptual gamut mapping. It preserves Y and
the common chroma direction without independent channel clipping.

The application weight is a = |amount| × effective_target_coverage × gate(P), and
P_out = (1-a)P + aT. Both endpoints are in-gamut and have the same Y, so the convex
blend remains in-gamut and retains current Y analytically. Final f32 encoding adds
small rounding error; numerical tolerance needs to be verified. Alpha zero copies
the original three floats bit-for-bit. No spatial filter or neighbor is read.

The target coverage is provided by the host and MUST be zero wherever the selected
reference sample mask is positive. Mere multiplication by (1-sample_weight) would
not exactly protect a fractional sample. The core cannot enforce that exclusion
because the composition ABI intentionally carries no sample-mask raster.

## Explicit processing-grid projection

The old `compose_v1` remains source-grid-only. New `compose_grid_v1` declares the
complete current processing grid separately from the tile rectangle and from the
immutable measured full source. It performs the identical per-pixel chromatic math
above; no color or statistics are interpolated, and the core does not resize RGB
or masks. Different preview/export pixels can produce different gated results;
identical q does not claim pixel equality across image resampling.

For source dimensions (W,H) and declared grid (Gx,Gy), require positive dimensions,
Gx<=W and Gy<=H. The exact full grid is accepted without an alignment condition.
Reduced grids require both Gx and Gy to be divisible by 8. The decoder uses
`max(8, floor(axis*k/8)*8)` separately on each axis, not ordinary pixel rounding.
The strict half-open intervals [Gx/W,(Gx+8)/W) and [Gy/H,(Gy+8)/H) must overlap.
Equivalently, require Gx H < (Gy+8) W AND Gy W < (Gx+8) H with checked u64 arithmetic.
An equality at an upper boundary is rejected. This is the canonical dimensional
policy already implemented by `body_pose_evidence.whole_source_shape`.

For example, 6000x4000 -> 3464x2304 satisfies both strict inequalities despite
exceeding a one-pixel aspect tolerance. A loose symmetric 8*(W+H) error allowance
is not the contract: it could accept grids without a common downward scale.
`decode.proxy_size` also has an 8-pixel floor and a tiny-budget decrement fallback.
An axis-upscaling or out-of-interval result from those exceptions is explicitly
unsupported rather than weakening the core guard. The host must verify the exact
pipeline projection and budget; passing the shape guard does not prove image
provenance. Tiles must fit (Gx,Gy), including neutral calls. Neutral has no reference
and therefore cannot check source-relative projection or reduced-grid alignment.

The host re-rasterizes the selected manual region on the declared display grid and
zeros target coverage wherever that display-selected mask is nonzero. If the
selected display mask becomes entirely zero, the host refuses that preview.
This is not a conservative footprint projection of every original source subpixel
or disconnected component: small components or boundary portions can disappear
under re-rasterization, and exact preview-edge parity is not claimed. Full-source
export excludes every positive original selected-mask pixel exactly. Keep measured
full-source dimensions/counts/quality unchanged: an application grid change is
not remeasurement or sample rescaling.

## Research and license boundaries

- [Reinhard, Ashikhmin, Gooch and Shirley, 2001, Color transfer between images,
  DOI 10.1109/38.946629](https://ieeexplore.ieee.org/abstract/document/946629/authors)
  establishes statistical color-reference transfer as a mature practice. Its
  decorrelated-space distribution transfer is background research, not the
  implemented algorithm. Publication is IEEE-copyrighted; no paper text, code,
  figures, source images, or implementation were copied into the product.
- [W3C CSS Color 4, inspected 2026-10-25](https://www.w3.org/TR/css-color-4/)
  documents encoded versus linear-light sRGB, luminance, color conversion and the
  limitations of channel clipping. Its published status is Candidate Recommendation
  Draft, not a frozen final standard. Mathematical color definitions informed this
  independently written implementation; W3C sample code was not copied. The
  [W3C Software and Document License](https://www.w3.org/copyright/software-license-2023/)
  is the published source license; vendoring its code later would require notices.
- [PixCake official guide](https://www.pixcakeai.com/guide/32472) is used only to
  verify signed user-facing semantics. Proprietary code, weights, pictures and
  undisclosed implementation are neither available nor reused.

All newly authored core source is GPL-3.0-or-later, consistent with the repository
LICENSE. No dependency, third-party code, model, binary or redistributed asset is
introduced. The existing palette/gloss core remains separate and unchanged.
