### 人工纠正那一臂（第 9 臂，多人夹具 `portrait-dual-1570x950.jpg`）

一手 JSON（`/tmp/m5-release-manual.83036.log`，原样）：

```
M0_MANUAL {"roster":2,"kept":0,"refused":1,"disabledLedger":0,"enabledAfterEnable":2,
 "scopeBlock":"multi_face",
 "preview":"保留 1 处禁用、0 处人工补的脸，本轮新增 1 张无人工记录的脸",
 "keptCore":0,"redetectCore":0,"refusedReachedHost":true,"rectReachedEngine":true,
 "rectErr":"这一框里已经有脸了（名单里有与它对得上的人）：要改他就用 `face select`，重复入列会让同一张脸在名单里出现两次",
 "deformLit":true,"canvas":"584x352"}
```

判据逐条（33 条通过 / 0 条不过，`VERDICT=PASS`）：

· `roster=2` —— 这一臂的对象只能来自真检测（单人图上没有"关掉一位、留下另一位"）；
· `keptCore=0` —— 记一条人工账不是调图：关掉那一只，画面上他那圈内芯逐字节不动；
· `scopeBlock="multi_face"` —— 人工账不许把"这一轮是多人图"这个原始事实抹掉
  （SCOPE-001 的 P0 判据读这一格；`blocked` 另按"还剩几个可编辑的人"算）；
· `refusedReachedHost=true` —— 事后 `face select` 那只被禁的，引擎整条拒，而那句
  「已被人工禁用」走到了宿主的 `last_error`：面板据此**禁用带原因**，而不是留一个点了不动的按钮；
· `redetectCore=0` —— 后台重检测之后，被禁那一位的内芯仍逐格没动（冻结件 then 那句
  「不静默恢复已禁用误检」在这一帧上成立）；
· `disabledLedger=0` + `enabledAfterEnable=2` —— 人工判断要能被人推翻：`face enable` 之后账清空；
· `rectReachedEngine=true` —— `face add` 的矩形走过了 Rust 桥：宿主读到的拒绝是「这一框里已经有脸了」
  而不是「要给归一化矩形」。这两句话的差别就是判据本身——桥丢了 `rect` 这一项时前一句永远出不来
  （上一轮 `auto_pick` 漏桥就是这一类静默）；
· `preview` —— "变化可预览"那句真到了宿主（谁被保留、谁认不回、本轮新增几张）；
· `deformLit=true` —— 关掉别人不烧掉留下那一位的活儿；
· `canvas=584x352` —— 以上全部量在用户看见的那一帧上，不是引擎内部的第二块画布。

## 3. 本轮这一臂抓到（与我自己造成）的缺陷

1. **首屏白屏**：`StudioPanel.tsx` 在非分人分支上写了 `faceSt!.manual`。非空断言在编译期被擦除，
   运行时 `faceSt` 为 `null` 就是渲染期 TypeError，整棵 React 树打崩 → 装机壳日志 0 字节、引擎
   从没被 spawn，而 m5 那时只会说"900 s 内没跑完"。诊断：起本地 http.server 用浏览器读 console
   拿到那一行栈。修：改可选链；同时给 m5 的每个等待环加**45 s 零字节判红**（"空日志"≠"还没跑到"，
   而是"根本没跑起来"），并把结局文案从 `&&/||` 平铺改成 `if/elif/fi` —— 平铺那一版在 `got=2`
   时会连印两条（三态自证 `.scratch/ff3.sh` 抓到）。
2. **我自己造成的那一记**：给 face 路由臂加 `"face_manual"` 时，编辑工具连带删掉了紧邻的
   `"enhance_done"` 与 `"pick_*"` 两个臂（diff 里 6 增 26 删）。tsc 不知道（那是 Rust），裸引擎
   933 条不知道（不经过桥），症状是第 7、8 两臂静默超时。已从 HEAD 恢复并用累积式 python 补丁重打，
   加两条会红的守卫：`test_every_face_bearing_engine_event_is_routed_by_the_host_bridge`（事件名
   双向包含）与 `test_every_host_slot_writer_has_a_router_arm`（`main.rs` 里每个 `pub fn on_*` 必须有
   调用者）。两条都做了**负向自证**：临时删一遍臂，判据确实变红。
3. **`face_manual` 确实没接桥**（第 1 记修好后暴露的真缺陷）：点了 ✕，账记上了而屏幕要等下一次
   precompute 才认——DoD §3 禁的正是这一类控件。桥接上之后面板即时刷新。
4. **判据自身的假红**：`int(mm.get("disabledLedger") or -1) == 0` 在值恰为 0（我们要的那一格）时被
   `-1` 顶掉。这类"假零"形状在本脚本里扫过一遍，只剩 `> 0` / `>= 4` 那些用法（那里 falsy→0 是对的）。
5. **`XAUTHORITY` 写死后缀**：`.mutter-Xwaylandauth.XXXXXX` 是每次登录重新生成的随机名，写死一处
   就等于给六条臂埋雷（失败模式恰是"窗口起不来 + 日志零字节"）。改成就地解析：环境里已有的（还在）
   → `/run/user/<uid>` 下最新那一个 → 都没有就不设，让 Xlib 走默认查找。
6. 引擎侧（本轮前半，判据同源）：`detect_region` 报出去的 `window` 两轴都除宽；`_grow_window` 顶到
   边界时补齐仍偏短；`face remove` 按"盒相等"清账导致撤掉的脸下一轮又被补回（静默恢复）；
   放下亮着的层却不补帧（`_refresh_frame_after_drop`）。

  这台机器上成立，靠的是 §1 那个运行时引导已经跑过；换一台没跑过引导的机器，第一条红会是
  `check-release`/m5 的"运行时不在"那一格，而不是静默失败。
