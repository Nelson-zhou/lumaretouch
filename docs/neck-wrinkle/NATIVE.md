The independently versioned `lnx.neck_wrinkle.v1` module adds validators, not a
second mailbox, renderer, geometry model, history owner or implicit consent.
The source solver and its AGPL derivative notices remain separate from these
original GPL-3.0-or-later transport checks.

## Exact integration ports

Register `#[path = "neck_wrinkle_people.rs"] pub(crate) mod neck_wrinkle;` inside
`people_api.rs`, beside the existing family modules. Add the five `ACTIONS` to
its action allowlist. Invoke `command(&request)` before engine submission.
Require `neck_wrinkle_protocol == 1` for these actions; a missing numerical
capability must not prevent the exact neutral reset patch or detach.

`action` recognizes the five dedicated actions and the exact neutral patch:
one `/amount` leaf, `unset: false`, numeric zero, exact operation ID. For a
result it also recognizes that patch through its retained request marker.
`mutation` distinguishes confirmation/detach/reset from reads.
`matches_request` binds a terminal receipt to the retained exact command for the
existing project recovery fence. Neck mutations are guarded until a valid
matching terminal or verified workspace reopen. An unrun recovery fixture
covers altered echoes, a bare reopen event, unknown writes and verified reopen.

In `receipt_host::ReviewBinding::from_command`, invoke `binding(value)` and
retain its exact returned fields under the existing 256 KiB request binding
budget, with `strict_failure_identity: true` and `read_only(value)`. This is
essential: checking a result-supplied marker without retaining the submitted
command would not prove correlation. The marker is `neck_wrinkle_request` and
contains action, payload and all six existing context fields. Engine receipts,
including failures and reset patches, must echo those exact fields.

Include `receipt(value)` in the people-kind validation conjunction. Then allow
this family to return early, like the skin-reference adapters: this validator
already checks read/no-document, released-image tombstone, and mutation
post-state contracts. Include `action` in the guarded receive and
`begin_command` family predicates. This ensures malformed successful writes
cannot publish a frame or document state and remain uncertain in the existing
receipt machinery. Query/reopen remains that machinery's responsibility.

`post_state(result, captured_request)` is also exported for focused static
fixtures or an owner-specific publication hook. It requires exact current face,
document/epoch, source, association revision, resolved amount and own support
report; revisions cannot go backwards. A detach needs amount zero and attached
false; neutral reset need not remove the retained support. No-op semantics are
not forced into an artificial revision increment.

## Evidence limits and required owner checks

Commands enforce independent BodyRef, brush-only visible support, separately
reviewed opaque/add-only/unfeathered hard protection, per-stroke and aggregate
point bounds, and a positive measured scale. The source-sized preview validates
that the scale represents 1.4 through 12 actual canonical pixels.

Source proof must agree with effective source, not original filename identity.
Every read carries actual input/repair hashes. Native PNG checking reuses the
existing `torso_transfer_protocol::png` signature/chunk/CRC checks, verifies
base64 roundtrip and SHA-256, and admits only RGB PNGs, 4 MiB each. Whole images
are bounded at 1152 pixels per edge; crops at 1024 and must equal the requested
native rectangle dimensions. Crop source/reference versus result/preview
identities cannot be interchanged. Three full review images plus one matched
native before/after inspection pair are required by confirmation schema.

A schema validator cannot prove that a human viewed an image. The app-lifetime
UI owner must additionally retain the exact preview and inspected pair and run
`validWriteResult` from the neck UI module before publication, even if the panel
unmounted. It binds the selected amount and all image hashes to the prior
preview, protects unrelated state, and verifies actual loaded image ACKs. The
engine must likewise verify its frozen preview, source/repair/support and
inspection hashes before the existing atomic graph/support transaction.

No support masks, body observations or previews are transferred to another
photo, alias, cohort or preset. Those paths remain outside this slice. This
transport is not evidence of automatic neck segmentation or photographic
quality, nor proof that any numerical or renderer test passed.

They cover source injection, required full/native image acknowledgement,
source/output crop identity, bounded rectangles, exact neutral reset,
