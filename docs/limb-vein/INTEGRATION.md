# Reference-assisted limb vein integration

Status: authored source integration only. Builds, type checks, numerical tests,
interaction, photographic quality, export parity and performance are **UNRUN**.
PC-46608:2 and PC-9XYcMCvHXW:1–2 remain partial, not accepted. Manual hand,
forearm or foot selection is not automatic anatomy or vein recognition.

## Canonical owner and delivery

The immutable `_limb_vein` recipe is part of Engine DOC_FIELDS, ordinary history,
project persistence and canonical document revision. `limb_vein_routes` supplies
capture/render ports to the isolated host and commits one normal history event
per confirmed correction or clear. It adds no parallel document/history model.
Native integration reuses ReceiptHost and existing recovery guards, binding exact
request, engine epoch and post-state recipe digest. Unknown writes query their
original request and are not resent. The App-lifetime hook exposes the hand and
foot tool routes; the panel explicitly chooses hand, forearm or foot. Other hand
neutral-grey and hand-shaping controls are not implemented by this panel.

## Source and rendering

Full precision unrotated working-sRGB input is decoded and the canonical ordered
repair stack is replayed before measurement. Source dimensions/digest, repaired
input digest and repair-stack digest must match the saved recipe. Display proxy
pixels never become numerical measurement input. Original files are untouched.
Reference capture is shared infrastructure, while the independent limb kernel
retains its own operation/version and colour-first, shading-second behavior.

The full-grid field is measured from the repaired source once per recipe. Normal
preview uses an explicitly approximate nearest-grid projection. Confirmation uses
complete before/after rendering; export installs exact slices of the full field
at each source tile origin. Both ordinary and tiled pipelines apply sweat, then
limb vein correction, before the remaining portrait/colour consumers. Current
linear RGB is corrected, not the saved source pixels, so other retained edits
are not overwritten. Input and field no-ops preserve the current raster.

Changing source repairs requires clearing and re-reviewing this effect. Imports
start neutral, undo/reopen retain canonical state, and batch/preset export cannot
blindly copy a current-photo skin reference. Reduced captures and RGB16 neutral
passthrough refuse to omit an active effect. Source-domain masks may differ in
size/aspect from the final cropped comparison, which is intentionally supported.

## Boundaries and validation

Same-limb skin, vein target, clean reference and protection are manual declarations;
protect nails, tattoos, jewelry, edges and other limbs. The bounded numerical
method does not prove correct anatomy, similar lighting or clinically meaningful
vessels. This is cosmetic photo editing, never diagnosis.

The original dependency-free GPL-3.0-or-later Rust module is staged with its
source, header and licence via the explicit packaging recipe. Missing native ABI
refuses positive processing; there is no automatic compile, download or fallback.
Clear needs no limb numerical computation, though any other retained effects must
still be renderable. The 32 MP ceiling is not a usable-size or latency promise;
full-resolution memory admission may refuse. CPU field transfers, GPU parity,
24 MP memory, colour/texture quality and real-device interaction remain untested.

Source review covered canonical stage hooks, source binding, neutral bypass,

AST-parsed without importing product modules; `git diff --check` was clean at
freeze. These are syntax/source checks, not execution or build evidence.
