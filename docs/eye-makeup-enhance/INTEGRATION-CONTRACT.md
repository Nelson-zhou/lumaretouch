# Current-photo canonical integration

Source authored only; all compilation, tests, numerical and photographic acceptance are UNRUN.
Baseline for this integrated slice: ec6178ce2be0ba1ff703736ed858af93bce1e809.

The dedicated operation lnx.eye_makeup_enhance.v1 has four independent signed,
left/right-linkable controls. The current source owns measured facial evidence,
manual makeup coverage, exclusion polygons and, for amount only, two disjoint
reviewed bare-skin references for each requested eye. No support crosses owners.
Integer source pixel centres and normalized coordinates scaled by dimension minus
one are used by both reference painting and working-resolution rasterization.
RGB8 PNG is inspection transport only, not the numerical working source.

Registry and project validation retain old defaults and explicit recipe intent.
Single-leaf validation accepts atomic bilateral edits; whole materialized recipes
still enforce linked equality after staging. The source context excludes only the
new implicit neutral default, not explicit neutral leaves or reviewed support.

Original and opaque SDR derived sources pass their own support bank to the common
people renderer. The estimator consumes the original effective float32 source,
not a repaired or another effect's result. Owned deltas compose with the shared
one-gain SDR feasibility rule on CPU and device. Full-source export uses the same
prepared source operation; neither proxy colours nor thumbnail masks are promoted.
Resident source effects share a deduplicated budget helper; no new global cap.

Dedicated reference and review commands use native action, binding, receipt and
read-only gates. Reference release is not a write: its exact request clears only
its matching draft even when refresh fails. Review commits require current source,
face, revision, payload echo and canonical graph publication. Existing graph and
support-bank snapshots own undo, project persistence and recovery. No second undo
or receipt journal is introduced. Packaging stages the original Rust core and
third-party mathematical notices; capability remains unavailable without its ABI.

## Explicit outstanding scope

This is manually reviewed existing makeup, not learned cosmetic segmentation,
new cosmetics generation, removal of hidden skin, or proprietary appearance parity.
Alias edits, cross-photo presets/batches/cohorts, automatic per-eye visibility and
dedicated effect-recovery painting are not admitted by this current-photo slice.
HDR/transparent retouch sources remain explicitly unsupported. Extreme pose,
insufficient visible makeup/skin, tiny eyes, over-budget images and occlusion
without defensible coverage refuse rather than silently simplify.

## Original RGB opacity boundary correction

The two original RGB8 retouch decoders now invoke the existing actual-alpha
validator before RGB conversion. This rejects truly transparent originals instead
of silently flattening them; fully opaque RGBA remains accepted. Genuine native
RGB16/PNG16 admission is unchanged. The colour conversion helper itself is not
restricted, so separately owned creative RGBA import and background assets keep
their existing alpha-preserving contracts. Old transparent retouch documents may
now require an explicit opaque source rather than reproduce hidden alpha loss.
This is an intentional safety refusal, not expanded alpha editing support.
