## Eighteen integration hooks

1. **Canonical recipe registry:** `people_algorithms.specifications()` registers `blush_makeup_state.OP` with neutral/check. Leaves `/pattern`, `/strength`, `/colour` remain separate from lip enhancement and eye-light.
2. **Normal edit receipts:** mounted controls send leaves through `peopleOwner.patch`; `people_edit` and `people_host_commands` own validation, full preparation, publication and correlated receipts. No second render graph/history owner.
3. **Project/dormant validation:** `people_project.validate_records` checks blush libraries and all blush overrides in graphs, including nested records. `blush_makeup_support.validate_project` resolves active/historical immutable review references against the one retained asset bank.
4. **Real local preparation:** `people_render_runtime.prepare` verifies measured analysis, resolves and rasterizes cheek review; `people_effects.prepare` calls `blush_makeup_layer.prepare_record` with actual skin, exclusions, semantic identity and reviewed support. Requested failures remain atomic across faces.
5. **Actual pixel stage:** `people_effects.STAGES` and `people_pipeline.source_effect` admit blush. `vram.retouch` calls the blush stage after lip makeup and before common geometry. Existing independent eye-light source stage remains separate and unchanged.
6. **Original-size export:** `people_engine_runtime.prepare_export` forwards the same frozen support bank and rebuilds blush at original dimensions. Existing LocalEffect crop/attenuation and tile pipeline consume the prepared field; export `people.facts` includes blush records. No per-tile solve or proxy-field upscale.
7. **Packaging:** `stage-engine.sh` calls `build-blush-makeup.sh`, stages the fixed catalogue and original Rust source/license/MediaPipe attribution. `server.hello` exposes `blush_makeup_protocol` only when the native library file exists. No runtime compiler or substitute renderer.
8. **Recovery registration:** `facial_wrinkle_recovery.FACE_TARGETS`, effect-recovery target/label/stage registries and UI RecoveryTarget include blush. Canonical selected-face availability checks the actual nonzero LocalEffect.
9. **Immutable recovery:** existing `people_support_assets.retain/resolve/raster` owns blush recovery vectors; the compositor attenuates only blush. `people_export.isolated_snapshot` excludes mirrored face recovery from the legacy path. Cheek visibility is a distinct special asset consumer, never mistaken for recovery.
10. **Palette state:** `_blush_makeup_library` is in Engine construction, DOC_FIELDS, fresh defaults, capture and checked restore. Normal project document encode/decode and undo/redo retain it. It contains schema/catalogue digest plus max six unique colours. Scope is per photograph, not untracked global UI storage.
11. **Palette command:** `blush_palette` is a Rust-validated/TS-typed people action. Its full document/graph envelope is checked. `blush_makeup_host.palette_action` installs a validated candidate, fences the current document and rolls back on mutation failure; normal history and final people receipt own completion. Dedicated history grouping prevents two separate favourite clicks merging.
12. **Frozen material identity:** native proposals load `blush_makeup_patterns.json` through its pinned catalogue digest; Python and TS catalogue mirrors retain that digest. Explicit corrupt/null/mismatched library records refuse. Missing older library fields default to empty; existing graph intent is not erased.
13. **Real preset route:** `scope.py` registers blush; `WorkflowPortsMixin._people_preset_capture` composes eye-light and blush transport DTOs. `people_scope.replay_preset` consumes changed blush leaves into the canonical graph and requires strict preparation. DTOs are ephemeral, not DOC_FIELDS or alternate render owners. Preset UI labels include blush.
14. **Batch route:** registered scalar leaves appear in canonical people parameter catalogs and confirmed-face transfer UI. Existing frozen people batch adapters, mappings, fences, receipts and protected undo own transfer. Generic scope metadata identifies the family; destination must have its own real analysis/review. No review/recovery/palette/source bytes transfer.
15. **Handbook UI mounting:** RetouchPanel maps the six exact `PC-32471` blush paths to the actual BlushMakeupPanel supplied by App. The controls expose all twelve distinct shapes, amount, recommended colours, RGB/HEX and six favourites. Per-context component key resets transient drafts. Disabled native/analysis/refusal/pending states are visible.
16. **Capture ownership:** App instantiates `useBlushPicker` with current PeopleView, transport `status.doc_rev`, availability and the existing `submitCaptured` receipt owner. Source asset, document/graph/association revisions, target and selected analysis are frozen. Edit intent, Escape, tool/context changes and unmount invalidate.
17. **Actual presentation acknowledgment:** App routes the active blush picker into Viewer’s existing ColorSampleOverlay. That overlay paints the verified producer frame and calls `presented` after animation-frame presentation before click sampling. Panel shows the real ColorSamplePanel plus “使用此颜色”. Apply compares capture/ticket/epoch/generation/sequence and current context, then submits only `/colour` using the captured full envelope. No canvas screenshot or invented source identity.
18. **No stale rebase:** `usePeopleWorkflow` exposes its existing full-envelope `workflow.submit` as `submitCaptured`. Blush samples do not reconstruct a new envelope from a later target. Other tool starts cancel the blush lease; original people receipt handles uncertain outcomes without resend.

## Additional explicit bilateral support review

`blush_reference` and `blush_review` are registered in Rust/TS and routed by the existing people command host. The first reads a source-hash/dimension/FaceRef-matched undeformed source reference through the established source-preview producer. The mounted BlushMakeupSupportEditor requires the reference image to load with matching dimensions, then captures normalized brush vectors and explicit visible/unoccluded/ownership confirmation for both cheeks. The host retains content-addressed `blush_makeup_visibility` in the same project support bank, and the normal graph transaction publishes its pointer. Old bytes are retained for history. Reanalysis/source changes cannot silently rebind it. Actual landmark geometry, skin, eye/lip and known-occluder exclusions still apply.

The source reference is a whole-frame downscaled PNG for user review, not original-resolution pixel evidence. Review vectors are normalized source-coordinate intent. Semantic/occlusion limits remain documented in README; user review is not a guarantee of segmentation accuracy.
