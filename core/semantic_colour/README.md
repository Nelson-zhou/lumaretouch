# Semantic colour core, ABI 1

Status: original source implementation and source-only fixtures. Compilation,
unit tests, FFI integration, photographs, cancellation races, throughput and
visual acceptance are **UNRUN**. Source review is not acceptance. Qoder owns
subsequent local execution. This directory has no downloaded models, copied
paper implementation, runtime compilation or external crate dependencies.

## Scope and colour contract

This is a late display-referred colour-transfer stage. RGB is extended,
gamma-encoded sRGB, not scene-linear RGB. An upstream colour-management contract
must put reference and target in the same encoding. Source geometry, texture and
semantic labels are not generated by this core. No image dimensions, coordinates
or landmark geometry are needed for colour-distribution correspondence.

`colour::Operator` is used by both fitting and production. `Operator::render`
provides the common float32 input/output boundary, f64 point math and residual
blend. Local fitting rounds the global output to float32 before local evaluation,
just as production does. There is no separate approximate fitting LUT.

The operator order is:

1. Signed extended sRGB decode, linear exposure/RGB gains, signed sRGB encode.
2. Encoded-domain contrast around 0.5.
3. Encoded-luma saturation using weights 0.2126, 0.7152, 0.0722.
4. Master then per-channel PCHIP, using `../curves/curve.rs` directly.
5. Optional legacy eight-band HSV adjustment.

PCHIP extrapolates with endpoint tangents outside [0,1]. Contrast, saturation,
exposure and identity curves do not clamp extended values. The legacy HSV branch
is intentionally SDR: any effective nonzero HSV edit clips its input to [0,1].
It uses the existing eight centres, unnormalized smoothstep hue windows and
low-saturation gate. It is **not HDR HSL** and has no orange/skin-only gate.
Automatic HSV fitting is disabled when any relevant supplied reference/target
sample is extended-range. The global check includes all supplied classes; local
checks include all original reference-class samples and all target-class samples
after the global recipe, not only prototypes. Unsampled image pixels still
require full-image inspection. Genuine manual HSV editing remains available.

## C ABI, unchanged

- `lrt_semantic_colour_abi() -> u32`: returns 1.
- `lrt_sc_fit(reference, reference_count, target, target_count, mode, cancel,
  parameters_out, diagnostics_out) -> i32`.
- `lrt_sc_apply(rgb, pixel_count, parameters, strengths, mask, output) -> i32`.

Fit arrays are contiguous f64 rows `[R, G, B, class_id, weight]`, with 32–6144
rows in **each** array. RGB must be finite and in [-16,16]. Class IDs must be
integral in 0–5. Weights must be finite in [0,1]; zero-weight rows are ignored.
Class order is background, hair, body skin, face skin, clothes, others. Mode 0 is
extreme; mode 1 is harmonious. These names select regularization strength only,
not a different learned model or different correspondences.

Successful fit output is 7 × 50 f64 parameters and 7 × 10 f64 diagnostics.
Group 0 is global; groups 1–6 follow the class order above. Unsupported local
groups are identity with `available=0`; supported-but-neutral groups remain
`available=1`. If no class has adequate support, the fit returns error 2 instead
of inventing a global recipe.

Apply input/output is contiguous N × 3 f32, with N ≤ 2,000,000. Parameters are
50 f64; strengths are `[overall, tone, colour]` f64, each in [0,2]. A null mask
means uniform weight 1; otherwise it has N finite f32 values in [0,1]. Overall
strength scales the output residual; tone/colour strengths scale their respective
parameters about identity. The scalar formula is `x + mask*overall*(O(x)-x)`.

Callers own all buffers and must provide valid alignment, sufficient capacity,
and non-overlap between output and any input/other output. The ABI cannot check
pointer validity. All required pointers must be non-null, even for N=0. Do not
call in place. The optional C cancellation callback must not unwind or release
buffers. It is checked between bounded work units and before fit returns.

An ordinary error/cancellation does not change output buffers. Apply stages a
bounded scratch output (at most 24 MB at the ABI limit) before committing; tiled
callers normally use much less. It rejects finite f64 results that would overflow
to f32 infinity. Rust unwind is caught; invalid pointers, process aborts and
allocation aborts are not recoverable through this API.

Status codes: 0 success; 1 invalid arguments/samples/masks/active input;
2 insufficient supported data; 3 invalid recipe or nonfinite/overflow result;
4 OT numerical failure; 9 cancellation; 99 caught Rust panic.

Effective identity, overall strength zero and mask weight zero copy original
float32 bits. This includes signed zero and negative/HDR values. Bypassed pixels
also copy nonfinite payloads without evaluating them; nonfinite **active** input
is rejected. Invalid recipe/strength/mask metadata is still rejected even when
an operation would otherwise bypass.

## Parameter layout and fitting scope

All controls are actual evaluator inputs, not renamed copies of a single effect.

| Indices | Meaning | Base bounds | Fitted automatically |
|---|---|---|---|
| 0 | EV | -2…2 | yes |
| 1–3 | R/G/B log2 linear gains | -2…2 each | R and B; G stays 0 |
| 4 | Saturation percentage delta | -100…100 | yes |
| 5 | Contrast percentage delta | -100…100 | no, stays 0 |
| 6–10 | Master PCHIP y ordinates | 0…1 | interior three only |
| 11–15, 16–20, 21–25 | R/G/B PCHIP y ordinates | 0…1 | no, identity |
| 26–49 | Eight HSV bands, each Δh/Δs/Δv | ±60° / ±100 / ±100 | yes, SDR samples only |

Every curve's fixed x positions are 0, .25, .5, .75, 1. Identity y equals x.
Hue centres are 0°, 30°, 60°, 120°, 180°, 240°, 280°, 320°. Automatic master-curve
knots remain strictly increasing with a minimum .01 ordinate gap. Manual curves
may intentionally be non-monotone; increased strengths can also change shape.
Do not claim all edited recipes or 200% strengths are monotone.

## Bounded correspondence and fit

1. Normalize positive weights per class to avoid scale-dependent underflow.
   Canonically sort by OKLab L/a/b, RGB and weight. Every fourth sorted row is
   validation; the remaining rows are training. Input row permutation therefore
   does not define the split. Identical pixels may exist in both subsets; this is
   a held-out-row selection set, **not** an independent photographic dataset.
2. Both reference and target need at least 32 positive rows in a class. Kish
   effective sample size must be at least 16 overall, 12 training and 4 validation.
   These are explicit support guards, not semantic confidence estimates.
3. In each subset, divide the L-sorted rows into four count-quantile strata.
   Within each stratum use at most six joint-3D OKLab prototypes: deterministic
   weighted farthest-point seeds, six weighted k-means passes, then actual source
   representatives nearest the centres. A prototype's RGB and OKLab refer to the
   same real sample; no inconsistent RGB-mean/OKLab-mean pair is fitted.
4. Match only the same semantic class and luminance stratum. Log-domain balanced
   Sinkhorn uses robust full 3D distance, checks **both** marginals, and has at most
   256 iterations per attempt. Epsilon attempts are .0025, .005, .01; mode does not
   change them. Stop at discrepancy ≤1e-6; reject after bounded retries if >5e-4.
   Exactly identical prototype distributions use their identity coupling rather
   than acquiring an artificial correction from entropic diffusion.
5. The conditional coupling creates reference OKLab barycentric targets. Source
   stratum masses are retained. Each supported class has unit mass in the global
   objective, so image-area differences do not erase smaller supported classes.
   Maximum correspondence count is 24 per class per subset, 144 globally.
6. Seven bounded coordinate sweeps optimize the declared subset, starting from
   identity. The robust data objective also penalizes parameter movement, curve
   roughness/non-monotonicity, neighboring HSV-band jumps, semantic skin/neutral
   chroma displacement, new gamut excursions and local luminance-contrast change.
   Pre-existing extended RGB is not penalized merely for being outside SDR.
   These penalties are not guarantees of identity, fairness or visual quality.
7. Validate the candidate, then try 50% and 25% parameter interpolation toward
   identity if needed. A candidate may not increase validation residual or the
   regularized validation objective beyond numerical tolerances. Otherwise use
   identity. Validation is thus used for selection: its residual is **not** an
   unbiased test error. At most 440 objective calls are made per fitted group.

## Global and parallel local composition

Fit the global G first. Each class recipe Lc is then optimized as `Lc(G(x))`,
with `G(x)` as its neutral baseline. Both the value and ±.005 encoded-RGB contrast
probes go through the same global float32 endpoint first. Other local classes are
never chained into that fit.

Production must evaluate every local recipe against the **same global base**:

`base = G(input)`

`output = base + sum(mask_c * (Lc(base) - base))`

Normalize overlapping masks so their sum is at most 1; do not renormalize tiny
coverage up to 1. Per-group strengths belong to each recipe's evaluator, not to
a sequential class chain. Zero coverage must preserve the base bits. If the global
recipe is effectively identity as well, zero local coverage preserves original
input bits. Mask generation/resizing/composition belongs to the calling stage.

The fit identifies the pure-class mask=1 case at default strengths. RGB/class/
weight rows cannot identify full-image soft-mask boundaries or correlations among
six masks. Full rendered boundary/overlap inspection is therefore an explicit
acceptance gate, not something the local residual certifies. User edits, changed
strengths and changed masks invalidate the meaning of the original fit diagnostics.

## Diagnostics: exact ABI-1 column semantics

Each row contains, in order:

0. `residual_before`: weighted RMS Euclidean OKLab error on **validation**
   correspondences before this recipe. For a local row, this is the global base.
1. `residual_after`: same validation metric after the selected recipe; local
   rows measure `Lc(G(x))`, with default strengths and pure-class mask 1.
2. `objective`: selected recipe's **training** regularized objective. Its units
   differ from RMS residual, so these columns must not be compared directly.
3. `evaluations`: number of full objective calls including validation/selection.
4. `gamut_fraction`: weighted validation-source fraction with any resulting RGB
   channel outside [0,1]. It includes pre-existing extended range and is neither
   a clipping count nor a visual-quality score.
5. `pair_count`: **training** correspondence count, not pixel count or validation
   sample count. Global is the sum across supported classes.
6. `ref_samples`: positive-weight reference row count, before splitting/support
   filtering. Global counts all supplied classes, including unsupported classes.
7. `target_samples`: corresponding target row count.
8. `OT_error`: maximum absolute row/column marginal discrepancy over both subsets
   and all strata; global takes the maximum over supported classes. This is a
   numerical solver check, **not** correspondence correctness or quality.
9. `available`: 1 for a fitted/supported group (even if selected recipe is neutral),
   0 for unsupported local groups. Other unsupported fields are zero except raw
   sample counts. Zero unavailable residuals must not be displayed as perfect fit.

The term residual means closeness to this construction's barycentric reference
colour targets. It does not measure style success, skin naturalness, texture,
spatial correspondence, semantic-mask accuracy or similarity to a specific paper.

## Fixtures and open acceptance gates

Inline `#[cfg(test)]` fixtures are source only and have **not been run**. They cover
identity/strength/mask bypass bits, cancellation, overflow/atomic output, actual
HSV controls, extended curves, train/validation separation, prototype consistency,
constant-colour support, identical-distribution handling, support guards, mode
semantics, and global-before-local contrast probes.

Qoder must compile the dependency-free crate with the repository's packaging
script and execute the Rust fixtures, then run Python/ABI/render integration and
full-resolution colour-managed photographic comparisons. Required visual cases
include same-image identity; differing composition; blue/green clothes and
backgrounds; multiple skin tones; hair/background/face mask edges and overlaps;
negative/HDR samples; zero strengths; 200% strengths; edits after fit; reset;
CPU/tiled output; float16 GPU input conversion; stale/cancelled jobs and export.
Neither source inspection nor a lower residual closes these acceptance gates.
